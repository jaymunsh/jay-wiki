# 위키 전면 재개편 설계

작성일: 2026-08-10

## 왜 하는가

이 사이트의 독자는 면접관이다. 그 사람은 **5분 훑고, 고른 한 곳만 판다.** 지금 구조는
그 읽기를 지원하지 않는다.

| 증상 | 실측 |
|---|---|
| 두 번 고르고서야 글이 보인다 | 대분류 4 → 탭 19 → 글 |
| 그 끝이 비어 있다 | 글이 1~2편뿐인 탭이 6개(관측 1, 프론트 2, 보안 2, AI 2, 회고 2, 로드맵 2) |
| 정본 없는 글이 화면에 있다 | 운영 74편 중 **17편이 시드에 없다** |
| 정의되지 않은 탭이 노출된다 | `ops`("5. 관측·운영") — 시드에도 `wikiCategories.ts` 에도 없는데 7편을 달고 있다 |
| 메뉴에서 못 가는 글이 있다 | LAB 4탭 8편. 탭은 안 펼쳐지는데(`WikiShell.tsx:238`) 검색과 직접 URL 로는 열린다 |
| 사건 기록이 설명을 압도한다 | 종류별로 postmortem 32 / wiki 16 / adr 10 / note 1 |

마지막 줄이 핵심이다. 구조는 "무엇을 만들었나"를 표방하는데 내용물은 "무엇을 겪었나"다.

## 무엇을 지향하는가

**1번 화면은 "무엇을 만들었나"다.** 판단(왜 그렇게 했나)과 사건(무슨 일이 있었나)은
그 안에 배지와 문단으로 녹인다. 탭은 시스템의 구성을 나타내고, 글의 종류는 위치가
아니라 표시로 나타낸다.

## 1. 탭 구조 — 19 → 11

```
DASHBOARD  대시보드
BUILD      인프라 · 백엔드 · 데이터 · 프론트엔드
OPERATE    운영·관측 · 검증 · 시연 · 보안
IMPROVE    프로세스·AI · 거버넌스 · 회고·로드맵
LAB        → blog.leneu.cloud (탭을 펼치지 않는다)
```

접는 규칙은 셋이다.

| 접는 것 | 받는 곳 | 이유 |
|---|---|---|
| 관측(1편) | 운영 | 한 편짜리 탭은 탭이 아니다. 운영과 읽는 맥락이 같다 |
| AI 활용(2편) | 개발 프로세스 | AI 사용은 프로세스의 한 갈래다 |
| 로드맵(2편) | 회고 | 지난 것과 앞으로 할 것은 같은 화면에서 읽힌다 |

건드리는 곳은 `web/src/lib/wikiCategories.ts` 의 `WIKI_CATEGORY_GROUPS` 와
시드의 `TABS` 배열, 각 글의 `parentId` 다.

**순서를 지킨다 — 글을 먼저 옮기고 탭을 지운다.** 시드는 upsert 이고 DB 에만 있는
항목을 자동 삭제하지 않는다. 탭을 먼저 지우면 그 탭의 글이 고아가 되어, 지금 `ops` 탭이
빠진 것과 똑같은 상태가 하나 더 생긴다.

MECE 는 글이 아니라 이 탭 구조를 검사하는 데만 쓴다 — 탭끼리 겹치지 않는가, 빠진
영역은 없는가.

## 2. 콘텐츠 정리 — 74편 → 약 57편

### 2.1 유령 17편

전부 2026-07-07~09 에 쓰였고 08-02 대개편 때 시드가 다시 써지면서 버려진 1세대다.
일부는 존댓말이고 전부 `# 제목` 으로 시작한다.

**삭제 11편** — 시드에 더 나은 후속 글이 있다.

| 유령 글 | 대체하는 시드 글 |
|---|---|
| jay-wiki 프로젝트 개요 | `jaywiki-main-map`, `orchestration-map-walkthrough` |
| jay-wiki 현재 상태: 배포부터 운영 자동화까지 | 위와 같음. 2026-07-08 기준이라 낡았다 |

| Google OAuth와 관리자 권한을 분리한 이유 | 위 글과 내용이 겹친다. 유령끼리도 중복이다 |

**이 11편은 운영 DB 에만 있는 유일본이다.** `posts/jay-wiki/` 49파일은 전부 시드
글이라 유령의 사본이 없다. 그러므로 **지우기 전에 md 로 내려 `posts/archive/` 에
둔다.** 이 순서를 어기면 본문이 사라진다.

**편입 6편** — 시드에 대응 글이 아예 없다.

| 유령 글 | 왜 살리나 | 손볼 것 |
|---|---|---|
| OAuth 로그아웃 세션을 실제로 끝내기 | `jw_token` 을 지워도 `JSESSIONID` 에 인증이 남던 사건. 진짜 postmortem 이다 | 문체, 형식 |
| schema 분리 과설계를 걷어낸 기록 | 넣은 결정이 아니라 **뺀** 결정이다 | 706자로 짧다. 살을 붙인다 |
| PostgreSQL 백업 Phase B: R2 외부 복제 플랜 | README 의 "R2 는 계획 단계"를 뒷받침하는 유일한 글 | 아직 계획인지 확인 |

아래 3절의 형식을 새로 입혀야 한다.

### 2.2 유령 탭 `ops`

글 7편을 위 규칙대로 처리한 뒤 탭을 지운다. 화면에 「5. 관측·운영」이라는 옛 이름이
번호까지 붙은 채 노출되고 있다.

### 2.3 LAB 8편

전부 jay-wiki 바깥의 다른 프로젝트 이야기이고, **같은 slug 로 블로그에 이미 있다.**
위키 탭은 이 시스템의 구성을 나타내므로 남의 프로젝트 회고가 들어갈 자리가 없다.

시드에서 8편과 4탭을 제거하고 운영 DB 에서도 삭제한다. **리다이렉트는 걸지 않는다.**

## 3. 글 형식

### 3.1 공통 머리 — 모든 글

면접관이 훑을 때 읽는 것은 이 3줄뿐이다. 여기만 같으면 훑기가 된다.

```
한 줄 요약 — 이 글이 답하는 것
무엇을 판단했나 — 결정 한 문장
무엇으로 확인했나 — 근거 한 문장 (커밋 해시, 수치, 실행한 명령)
```

### 3.2 본문 뼈대 — 종류별 셋

셋은 애초에 다른 물건이다. 사고 기록에 결론부터 쓰면 시간 흐름이 깨지고, ADR 은 이미
통용되는 형식이 있다.

| 종류 | 뼈대 |
|---|---|
| `wiki` (설명) | PREP — 결론 → 왜 그렇게 했나 → 실제 구성 → 한계 |
| `postmortem` (사건) | 증상 → 잘못 짚은 원인 → 실제 원인 → 남긴 방어 |
| `adr` (결정) | 맥락 → 후보와 기각 이유 → 결정 → 결과와 되돌리는 법 |

`note` 는 뼈대를 강제하지 않는다. 현재 1편뿐이다.

### 3.3 기존 규칙과의 관계

지금 흩어져 있는 규칙(수치엔 근거, 소제목은 명사구가 아닌 문장, 굵게 안에 따옴표 금지,
`String.raw` 백틱 금지, mermaid `flowchart TB`)은 가이드 문서에 모은다. 새로 만드는
규칙이 아니라 있던 것을 한곳에 두는 것이다.

## 4. 하네스

| 무엇 | 역할 |
|---|---|
| `docs/wiki-writing-guide.md` | 위키 글 형식의 정본. 3절 전체 + 시드 편집 규칙 |
| `docs/blog-writing-guide.md` | 블로그판. 지금 `CLAUDE.md` 의 「블로그 글 작업」 절을 여기로 옮긴다 |
| 스킬 `wiki-writing` | 위키 글을 쓰거나 고칠 때 열린다 |
| 스킬 `blog-writing` | 블로그 글을 쓰거나 고칠 때 열린다 |
| `CLAUDE.md` | 두 줄로 줄인다 — 어떤 글에 어떤 스킬을 쓰는지만 |

스킬로 두는 이유는 하나다. 글쓰기 규칙은 **매 세션이 아니라 글 쓸 때만** 필요하다.
`CLAUDE.md` 에 넣으면 항상 컨텍스트를 차지한다. 지금 `CLAUDE.md` 의 블로그 절이
문서의 절반을 차지하는 것이 그 증거다.

## 5. 재개편 회고 1편

`wiki-information-architecture-rebuild` (IMPROVE > 회고). 소재는 이 문서의 「왜
하는가」 절 그대로다.

- 시드 upsert 가 DB 를 자동 삭제하지 않는다는 설계의 실제 대가가 유령 17편이다

- 탭을 19개로 늘린 것은 분류를 늘리면 정리된다는 착각이었다

## 검증

| 무엇 | 어떻게 |
|---|---|
| 고아 글이 없다 | 모든 글의 `parentId` 가 `TABS` 에 있는지 시드에서 검사 |
| 유령이 없다 | 운영 탭 API 의 slug 집합 ⊆ 시드 slug 집합 |
| 탭이 화면과 일치한다 | 운영 `tabId` 집합 = `wikiCategories.ts` 의 `tabIds` ∪ `start` |

| 회귀 없음 | Spring 172 / web 82 / `tsc` / lint 경고 8 |

화면 정렬과 줄바꿈은 자동 테스트가 못 잡는다(vitest 가 node 환경이다). 배포 전에
브라우저로 본다.
