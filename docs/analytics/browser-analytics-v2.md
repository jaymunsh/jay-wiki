# 브라우저 집계 v2 — 설계와 검증 기록

작업 기준: develop. 운영에 아직 배포하지 않은 로컬 구현이다.

## 확인한 문제

- `BlogController.post`가 GET 성공 때마다 `BlogStatsService.recordView`를 호출했다. 글 내보내기·비교 스크립트도 공개 상세 API를 읽으므로 사람의 열람과 같은 카운터를 올렸다.
- `ArticleService.view`는 문서별 IP 중복 제거와 별개로 사이트 조회는 매번 올렸다. Next의 메타데이터/SSR/프리패치에 집계를 붙이면 실제 표시를 구분할 수 없다.
- `SiteStatsService`의 방문자는 날짜+IP 해시. 프록시 신호 누락, 공유 IP, API 자동 호출은 조회/방문 비율의 해석을 어렵게 한다. 사용자 스크린샷의 1,195/4만으로 각각의 비중을 복원하지는 못했다.
- 기존 `Referrer`는 알려지지 않은 외부 호스트를 모두 `other`로 축약했다. 유입 API의 호출별 referrer는 세션의 첫 진입 출처와 다르다.
- 날짜별 행이 없는 날은 그래프에서도 빠졌고, 기간 선택·이전 기간 비교·페이지 성과가 없었다.

## 집계 계약

| 항목 | 정의 |
|---|---|
| 조회 | 대상 페이지가 visible 상태에서 약 1초 이상 표시된 뒤 보낸 view 이벤트 |
| 새로고침 | 다시 표시하면 새 조회. 재전송은 같은 eventId이므로 한 번만 반영 |
| 방문 | 탭별 세션. 30분 표시 활동 없음 또는 KST 날짜 전환 시 새 세션 |
| 일별 고유 브라우저 | jw_av 임의 UUID 쿠키. KST 자정 만료, 사이트별 분리 |
| 기간 브라우저 합계 | 일별 고유 수의 합. 기간 고유 사람 수가 아님 |
| 유입 출처 | 세션 첫 조회의 referrer 호스트. 내부 이동은 별도 분류. referrer가 없으면 직접/출처 미상 |
| 캠페인 | UTM source/medium/campaign. 각 1~40자 영문·숫자·하이픈·밑줄, 빠진 필드는 unset |
| 참여 | 표시 타이머 30초 이상과 페이지 75% 도달. 읽기 완료나 이해의 증거 아님 |
| 기존 수치 | 기존 테이블에서 보관만 하고 대시보드 접힌 영역에 표시. 새 통계와 합산하지 않음 |

탭 단위는 GA와 같은 도구의 세션 정의와 같지 않다. 한 사람이 여러 탭·기기·브라우저를 쓰면 방문/브라우저가 늘 수 있다. sessionStorage 복제로 열린 탭은 ID를 일시 공유할 수도 있다. IP 지문이나 계정 연결로 보정하지 않는다.

## 수집 범위와 보호

- 블로그 홈, 정상 발행 글, 검색/태그/카테고리 목록의 정규화된 경로. 목록의 검색어와 필터 값은 저장하지 않음.
- 위키 홈, 발행 문서, 지정한 공개 목록. 관리자·로그인·임의 경로 제외.
- Spring이 발행 글 존재 여부를 검사. 브라우저 경로만 믿고 임의 차원을 생성하지 않음.
- 관리자 권한의 **현재 사이트 인증 쿠키**가 있는 요청, 알려진 봇 UA, webdriver, DNT/GPC 제외. 다른 사이트에서만 로그인했거나 로그아웃한 운영자는 개인정보 화면의 제외 버튼 사용.
- Origin 필터 + 이벤트 엔드포인트의 Origin 필수 + 사이트/호스트 일치. 무인 클라이언트의 Origin/UA 위조까지 막는 증명 수단은 아니다.
- BFF 이벤트 본문 2 KiB 제한. 서버 입력 길이·허용값 검증.
- 날짜별 salted IP 해시를 쓰는 Redis 120건/분 제한. Lua로 증가와 첫 만료를 원자적으로 처리. 공유 IP의 정상 방문도 제한될 수 있음.
- 브라우저 전송은 실패 시 최대 3회. 실패해도 페이지 열람은 계속됨.

## 저장과 동시성

V34는 새 테이블만 추가한다. 기존 V14/V15/V32 데이터나 누적 글 조회를 지우지 않는다.

- `tb_analytics_meta`: v2 수집 가능 시점. 첫 실제 방문 시각은 아님.
- `tb_analytics_day`: 일별 조회·브라우저·방문·참여 수.
- `tb_analytics_dimension`: 출처·캠페인·기기·페이지·첫 페이지 집계.
- `tb_analytics_visitor/session/event`: 날짜+비밀값으로 변환한 임시 대조값. 원본 IP/UA/UUID는 저장하지 않음.

한 트랜잭션에서 세션 행 잠금 → 이벤트 PK 중복 제거 → 신규 브라우저/세션 판정 → 일별/차원별 누적을 처리한다. 동시 중복 요청에도 한 번만 증가한다. 참여는 기존 이벤트와 같은 세션/페이지이며 최소 경과 시간을 충족할 때 한 번만 반영한다.

임시 표는 매시간 오늘·어제만 남긴다. 최대 약 49시간이며 서버가 중단되면 재기동 후 정리된다. 일별 집계는 유지한다. 원본 DB 백업의 보관 기간까지 이 작업으로 바뀌지는 않는다.

## 검증 증거

`.local-backups/analytics-v2/`에 로컬 QA 결과와 캡처를 둔다. 토큰·원본 식별자는 결과 JSON에서 제외한다.

- Spring 통합 테스트: 중복/동시 재전송, 최초 세션 유입, 참여 선후관계·중복, 임의 경로 거절, 출처 축약, 인증/Origin/봇/DNT/GPC, 요청 제한, 보관 기간.
- 기존 GET 회귀 테스트를 읽기 전용 계약으로 변경. Wiki 저장/시드가 기존 조회수를 보존하는지도 확인.
- Playwright 로컬 실동작: 공개 글 표시 → view(204), 30초+스크롤 → engaged(204), 새로고침의 동일 세션·다른 eventId, 제외 버튼 후 전송 0.
- 데스크톱 1440px/모바일 390px 가로 넘침 0, pageerror 0. 밝은/어두운 캡처.
- 실제 브라우저 시나리오에서만 webdriver/UA를 명시적으로 일반 브라우저처럼 구성. 운영 코드의 봇 제외 조건은 끄지 않음.

## 운영 전환과 확인

현재 단계는 로컬 검증이다. 운영 반영 시 저장소 배포 절차에 따라 develop → main으로 배포한다.

1. DB 백업/복구 절차 확인 후 V34 적용 및 웹/백엔드 동시 rollout.
2. GET 상세 API 여러 번 읽기 전후 v2와 기존 카운터가 바뀌지 않는지 확인.
3. 일반 브라우저 공개 글 1회 열기, events 204, 관리자 report 증가 확인.
4. 관리자 방문·출처 위조·DNT/GPC·외부 Origin 거절 확인.
5. 다음 날 수집과 시간별 임시 행 삭제 확인. 이전 집계는 남아 있어야 함.
6. 새 수집 누락/오류가 있으면 수집기를 중지하고 분석. 과거 수치를 새 정의로 임의 환산하지 않음.

후속으로 고려할 것: 합의된 캠페인 사전, 세션 정의의 탭 간 통합, 더 정교한 봇 탐지, 수집 실패 지표. 댓글·가입 전환은 기존 별도 유입 쿠키/집계에 남으며 v2 방문과 연결하지 않았다. 현재 페이지에서 v2 전환 성과로 오인할 수 있는 표는 제거했다.
