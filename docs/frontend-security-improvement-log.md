# 프론트엔드·콘텐츠 보안 개선 기록

최근 갱신: 2026-07-11

## 이 문서의 목적

이 기록은 jay-wiki의 화면 개선을 단순한 디자인 변경으로 설명하지 않기 위한 근거다. 각 항목에서 어떤 사용자 문제가 있었고,
어떤 경계를 바꿨으며, 무엇까지 검증했고 무엇은 아직 측정하지 않았는지를 남긴다.

## 사용자 탐색과 반응형 안정성

| 문제 | 변경 | 얻은 결과 | 검증 |
|---|---|---|---|
| 탭 선택이 메모리 상태에만 있음 | 문서 선택을 `?article=<slug>` URL과 동기화 | 링크 공유, 새로고침, 브라우저 history가 같은 문서를 가리킴 | 딥링크와 활성 탭 확인 |
| 빠른 연속 선택에서 이전 응답이 늦게 도착 | 최신 선택만 상태를 바꾸도록 fetch 정리 경계 추가 | 마지막으로 누른 문서가 화면의 기준으로 남음 | 연속 문서 선택 수동 QA |
| 주변 상태 변화가 본문 다이어그램을 흔듦 | 본문 렌더링을 메모화하고 Mermaid 수명을 분리 | 이미 렌더링된 다이어그램의 불필요한 초기화를 줄임 | 문서 전환과 Mermaid 렌더 확인 |
| 모바일에서 넓은 요소가 페이지를 밀어냄 | 탭, 표, Mermaid가 각자 내부 overflow를 소유 | 페이지 본문은 가로 스크롤하지 않고, 읽어야 할 콘텐츠만 스크롤 | 390px, 768px, 1280px QA |
| 기술 라벨이 잘리거나 타임스탬프가 넘침 | 제목과 날짜의 고정 grid, 긴 라벨의 줄바꿈 규칙 적용 | 날짜와 한글 제목을 함께 스캔 가능 | 카테고리 목록 시각 QA |

390px에서 document와 body는 모두 390px 폭을 유지했다. Mermaid는 314px 프레임 안에 716px 콘텐츠를 두고 내부 스크롤하며,
페이지 자체의 가로 overflow는 만들지 않는다.

이 작업은 Web Vitals 또는 전송량의 개선 수치를 아직 주장하지 않는다. 현재 확인한 것은 탐색 결과의 일관성, 렌더링 수명 분리,
반응형 레이아웃의 안정성이다. 다음 성능 단계에서는 effect 기반 fetch와 상태 파생을 정리한 뒤 실제 배포 환경에서 Web Vitals와
문서 전환 지표를 측정한다.

## Markdown 콘텐츠 보안

DB에 저장된 Markdown은 관리자가 편집할 수 있는 콘텐츠이지만, HTML로 렌더링되기 전까지 브라우저에 신뢰할 수 없는 입력이다.
그래서 한 곳의 옵션에만 기대지 않고 두 단계의 방어를 둔다.

1. Markdown 렌더러의 raw HTML은 텍스트로 escape한다.
2. 최종 HTML은 allowlist sanitizer를 통과시킨다.

허용한 것은 문서에 필요한 기본 태그, 코드 강조 class, Mermaid 컨테이너, 이미지의 제한된 속성이다. 링크와 이미지 URL은
`http`, `https`, `mailto`만 허용하고 protocol-relative URL도 허용하지 않는다. 따라서 `javascript`와 `data` 계열 URL은
최종 HTML에 남지 않는다.

Mermaid는 일반 HTML로 섞지 않고 전용 컨테이너에서 strict 보안 수준으로 렌더링한다. Mermaid가 실패해도 원문 오류나 버전 정보가
본문에 노출되지 않으며, 다른 문서 내용은 계속 읽을 수 있다.

## 관리자 변경 경계

화면에서 편집 버튼을 감추는 것은 권한 검증이 아니다. 저장, 삭제, revision 되돌리기, 탭 저장과 삭제를 담당하는 Next Server Action은
모두 Spring의 auth me 응답이 authenticated ADMIN인지 먼저 확인한다.

관리자 Server Action은 확인된 요청에 `jw_token` 하나만 Spring 변경 API로 전달한다. USER 계정 또는 토큰 없는 요청은 변경 API에 도달하지 못한다.
이로써 UI 역할 분리와 서버 권한 검증을 다른 책임으로 유지했다.

## 회귀 검증

| 경계 | 테스트 또는 확인 |
|---|---|
| raw HTML | 이미지 이벤트 속성이 실행 가능한 HTML로 남지 않음 |
| 위험한 링크 | `javascript`, `data` 링크가 sanitizer 뒤 제거됨 |
| Mermaid | 전용 컨테이너와 strict renderer 유지 |
| ADMIN 변경 | 인증 확인 뒤 jw_token만 Spring 변경 API로 전달 |
| USER 변경 | 내부 변경 요청을 보내지 않고 권한 오류 반환 |
| 화면 | Vitest 6개, type-check, lint 0 errors, production build, 390/768/1280 브라우저 QA |

## 면접에서 말할 수 있는 문장

“문서가 많은 운영형 포트폴리오라서 화면을 예쁘게 꾸미는 것보다 탐색 계약을 먼저 고정했습니다. URL을 문서 선택의 기준으로 만들고,
비동기 요청이 역전되지 않게 했으며, 모바일에서는 Mermaid와 표가 페이지가 아니라 각 컴포넌트 안에서만 스크롤하게 했습니다.
동시에 DB Markdown이 HTML이 되는 경계와 관리자 변경 요청 경계를 별도로 검증해, 콘텐츠와 권한을 같은 신뢰 수준으로 보지 않았습니다.”

## 남은 보안·품질 과제

- 운영 공개 도메인에서 실제 ADMIN 권한 흐름과 세션 만료를 재검증한다.
- CSP 정책과 의존성 취약점 점검을 운영 배포 기준에 추가한다.
- React Doctor가 지적한 effect 기반 fetch와 상태 파생을 별도 리팩터링한다.
- 배포 환경에서 Web Vitals와 문서 전환 지표를 수집해 성능 수치를 추가한다.
