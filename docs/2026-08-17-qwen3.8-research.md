# Qwen3.8 리서치 — 27B 로컬 실행과 35B-A3B 소문 (2026-08-17)

- Qwen3.8 세대에서 지금 **받을 수 있는 것은 둘**이다. Max(2.4T-A95B)와 **27B dense**.
- 이 프로젝트에서 실제로 의미 있는 것은 **27B 하나**다. Max 는 개인 장비로 못 돌린다.
- **35B-A3B(3.8 세대)는 아직 확인되지 않았다.** 근거가 X 게시물과 커뮤니티 추측뿐이고, 공식 발표는 없다.

이 문서는 2026-08-17 기준 공개 정보를 정리한 것이다. 직접 돌려 본 측정치가 아니다 —
그 구분은 마지막 절에 다시 적는다.

## 지금 나와 있는 것

| 모델 | 구조 | 공개 | 라이선스 | 개인 장비 |
|---|---|---|---|---|
| Qwen3.8-Max (`Qwen3.8-2.4T-A95B`) | MoE 2.4T, 활성 95B | 2026-08-12 가중치 공개 | 커스텀(제약 있음) | **불가** |
| **Qwen3.8-27B** | **dense 27B, 비전 포함** | 2026-08, HF·ModelScope | **Apache 2.0** | **가능** |
| Qwen3.8-35B-A3B | MoE 35B / 활성 3B (추정) | **미확인** | — | — |

Max 는 "Max 급을 처음으로 받을 수 있게 됐다"는 상징성이 크지만, 2.4조 파라미터라
개인이 돌릴 대상이 아니다. 라이선스도 Apache 2.0 이 아니라 커스텀이다 — MAU 1억 또는
월 매출 2천만 달러를 넘는 제품은 모델명을 표시해야 하고, MaaS 사업으로 연 5천만 달러를
넘기면 별도 라이선스를 받아야 한다. 개인 포트폴리오에는 걸릴 조항이 아니지만,
**"오픈소스"라는 한 단어로 27B 와 같이 묶으면 안 된다.**

## 27B — 이 세대에서 실제로 쓸 물건

### 사양

| | |
|---|---|
| 파라미터 | 27B dense (MoE 아님) |
| 컨텍스트 | **262,144 토큰 네이티브**, YaRN 으로 100만까지 |
| 라이선스 | **Apache 2.0** |
| 입력 | 텍스트 + 이미지 + 비디오 (비전-언어 모델이다) |
| 특징 | thinking 모드 기본 켜짐, 깊이 조절 가능 |
| 구조 | 64층, `16 × (3 × (Gated DeltaNet → FFN) → 1 × (Gated Attention → FFN))` |

마지막 줄이 이 모델에서 가장 눈여겨볼 지점이다. **전 층이 어텐션이 아니라, 선형 어텐션
(Gated DeltaNet) 세 층마다 일반 어텐션 한 층을 끼운 하이브리드**다. 262K 컨텍스트를
27B 급에서 감당하는 근거가 여기 있다 — KV 캐시가 층 수에 비례해 늘어나는 구조를 4분의 1로
줄인 셈이다. 긴 문서를 다루는 용도라면 이 구조가 파라미터 수보다 중요하다.

### 각 벤치마크가 무엇을 재나

점수를 보기 전에 무엇을 재는 것인지부터 정리한다. 이름이 비슷해도 재는 것이 다르다.

| 벤치마크 | 무엇을 재나 | 특징 |
|---|---|---|
| **DeepSWE 1.1** | 긴 호흡의 실제 소프트웨어 작업 | 91개 저장소·5개 언어, **새로 쓴 문제**라 사전학습 노출이 없다. 검증기가 구현이 아니라 **동작**을 본다(심볼 이름이 달라도 동작이 맞으면 통과) |
| **SWE-bench Pro** | GitHub 이슈 해결 | 1,865문제·41저장소. 한 문제당 평균 120줄 규모. **판정 신뢰도가 약하다** — 감사에서 판정자가 약 3분의 1의 롤아웃에서 사람과 불일치(DeepSWE 는 1.4%) |
| **Terminal-Bench 2.1** | 터미널로 환경을 다루는 능력 전반 | 소프트웨어 개발이 가장 크지만 과반은 아니다. 과학 계산·ML 작업도 포함 |
| **OSWorld-Verified** | 실제 데스크톱 환경에서 GUI 작업 수행 | 컴퓨터 사용 에이전트 축 |
| **LiveCodeBench v6** | 최신 경진 프로그래밍 문제 | 오염을 피하려 최근 문제만 쓴다 |
| **SWE-MM** | 멀티모달 소프트웨어 작업 | 화면·이미지가 낀 개발 과제 |
| **GPQA Diamond** | 대학원 수준 과학 문제 | 코딩이 아니라 일반 추론 축 |

**DeepSWE 와 SWE-bench Pro 의 차이가 이번 비교의 핵심**이다. 앞엣것은 새로 만든 문제라
외워서 푸는 것이 어렵고, 뒤엣것은 공개 저장소 이슈라 학습 데이터에 섞였을 수 있다.

### 벤치마크 — 벤더 발표 기준

공개된 수치는 대부분 모델 카드와 그것을 옮긴 기사다. **직접 잰 것이 아니므로 그대로 믿지 않는다.**

| 항목 | 이전 세대(3.6-27B) | 3.8-27B | 참고: Claude Opus 4.6 |
|---|---|---|---|
| Terminal-Bench | 63.4 (2.1) | 73.0 (2.1) | 65.4 **(2.0)** |
| DeepSWE 1.1 | 13.3 | **42.2** | 공개 리더보드 상위에 없다 |
| OSWorld | 63.9 (Verified) | 84.3 (Verified) | 72.7 **(Verified 아님)** |
| SWE-bench Pro | — | 61.7 | 53.4 |
| SWE-MM | 25.7 | 38.6 | — |
| GPQA Diamond | — | 89.2 | — |

**Opus 열은 그대로 비교하면 안 된다.** Terminal-Bench 는 2.1 대 2.0 이고 OSWorld 는
Verified 여부가 갈린다. 버전이 다른 점수를 같은 줄에 놓는 것 자체가 흔한 왜곡이라,
여기서는 버전을 괄호로 남겨 두고 "같은 조건이 아니다"를 표에 박아 둔다.

DeepSWE 가 13.3 → 42.2 로 세 배 뛴 것이 눈에 띄는데, 이런 폭의 상승은 **평가셋 오염이나
평가 방식 변경을 먼저 의심하는 것이 맞다.**

### "Opus 4.6 을 앞섰다"는 주장의 상태

벤더 발표는 **SWE-bench Pro·QwenSWEBench·CoWorkBench·LiveCodeBench v6 에서 Claude Opus 4.6 Max 를
앞섰다**고 적고 있다. 27B 짜리 로컬 모델이 상용 최상위를 앞선다는 문장이라 그대로 옮기면 안 된다.
지금까지 확인되는 것은 이 정도다.

| 무엇 | 상태 |
|---|---|
| 모델 카드의 점수 | 벤더 발표 |
| datacurve DeepSWE 리더보드 42.2 | 기사들이 "모델 카드와 같은 값이 올라왔다"고 쓴다. 다만 **리더보드 상위 목록에서 27B 항목은 직접 확인되지 않는다** — 상위는 claude-opus-5 74%, gpt-5.6-sol 73%, claude-fable-5 70%, claude-opus-4.8 59%, qwen3.8-max 57% 순이다 |
| ScaleAI SWE-bench Pro 61.7 | 같은 값으로 올라와 있다고 보도된다 |
| 실사용 후기 | 아직 적다. 릴리스 직후 분석 글조차 "아직 아무도 제대로 못 돌려 봤다"고 적는다 |

**리더보드가 같은 값을 보인다는 것은 점수 재현의 근거이지, 실무 능력의 근거가 아니다.**
벤치마크가 재는 것과 실제로 쓰는 것은 다르고, 그 간극을 지적한 분석도 이미 나와 있다 —
한 리뷰는 27B 급의 현실을 **"작업량의 중간 대부분은 잘하고 가장 어려운 10% 에서 틀린다,
정말 복잡한 버그를 완전히 고치는 비율은 대략 절반"** 으로 적었다. 같은 글이 권하는 운용은
**로컬 27B 로 양을 처리하고 어려운 것만 호스팅 모델로 넘기는 분리**다. 검증 안 된 모델을
단일 장애점으로 만들지 않는다는 뜻이다.

### 비교의 바닥이 흔들린다 — SWE-bench Pro 의 판정 문제

이 비교를 더 약하게 만드는 보도가 하나 있다. DeepSWE 팀이 SWE-bench Pro 롤아웃을 감사했더니
**Claude Opus 4.6·4.7 의 통과 중 12% 넘는 사례가 git 이력에서 정답을 찾아오는 방식**이었다는
것이다(문제를 푼 것이 아니라). 사실이라면 SWE-bench Pro 점수는 모델 간 비교의 기준이 되기 어렵고,
"27B 가 Opus 4.6 을 앞섰다"는 문장도 그 위에 서 있는 셈이다.

여기서 내릴 결론은 "어느 쪽이 더 낫다"가 아니라 **"이 축으로는 아직 못 가른다"** 이다.

우리가 이미 겪은 것과 같은 함정이다 — [로컬 LLM 런타임 벤치마크](./local-llm-runtime-benchmark-result.md)를
할 때도 "커뮤니티에서 빠르다더라"를 결과로 받아들이지 않고 같은 장비에서 다시 쟀다.

## M1 Max 64GB 에서 돌린다면

이 저장소의 벤치마크 장비 기준(14인치 MacBook Pro, M1 Max 10코어 CPU·32코어 GPU, 통합 메모리 64GB)
으로 보면 여유가 있다.

| 정밀도 | 가중치 크기 | 64GB 에서 |
|---|---|---|
| BF16 | 약 56GB | 사실상 불가(KV 캐시가 위에 더 붙는다) |
| FP8 / 8-bit | 약 28GB | 가능 |
| **4-bit** | **약 16~18GB** | **여유롭다** |

이전 벤치마크에서 쓴 모델이 on-disk 약 22GB 였으니, 4-bit 27B 는 그보다 작다.

받는 경로는 셋이다.

- `ollama pull qwen3.8:27b-mlx` — Apple Silicon 용 MLX 네이티브 빌드, 4-bit 약 18GB
- LM Studio — `lmstudio-community/Qwen3.8-27B-MLX-4bit`
- `mlx-lm` 직접 — `mlx-community/Qwen3.8-27B-4bit`, 3/5/6-bit 와 MXFP4·NVFP4 도 있다

속도는 직접 재야 한다. 참고로 한 세대 전(3.6-27B) 4-bit 를 M1 Max 32GB 에서 잰 커뮤니티
수치가 **생성 15.5 tok/s, 프롬프트 처리 67.4 tok/s, 피크 메모리 15.8GB** 였다.
같은 계열이라 3.8 도 비슷한 자리에서 시작할 것으로 본다. **다만 이건 남의 숫자다.**

### 4-bit 로 내렸을 때 얼마나 깎이나

커뮤니티가 여러 양자화를 같은 조건에서 비교한 자료가 있다(RTX 5090 4장, 2026-08 중순).
**BF16 28.9GB 를 기준**으로 놓고 top-1 정확도를 잰 것이다.

| 양자화 | 크기 | top-1 |
|---|---|---|
| BF16 (기준) | 28.9GB | — |
| Q8_0 / Q6_K | 25GB 이상 | 기준과 사실상 수렴 |
| AD-IQ3_S | 13.8GB | 92.4% |
| IQ1_M | 8.5GB | 76.3% — 쓰지 말라고 적혀 있다 |

읽을 점이 둘이다.

**하나, 25GB 위에서는 양자화를 더 올려도 얻는 게 없다.** M1 Max 64GB 라면 8-bit(약 28GB)가
그 구간이므로, 품질을 최대로 원하면 8-bit 가 상한이고 그 위는 메모리만 쓴다.

**둘, 12~21GB 구간에서 만든 사람에 따라 품질이 갈린다.** 같은 13.8GB 급인데 KLD 기준으로
33% 차이가 났다(0.0325 대 0.0484). **"4-bit" 라는 이름표만 보고 아무 파일이나 받으면
그 차이를 그대로 먹는다.** 4-bit 대역에서는 어느 저장소가 만든 것인지가 비트 수만큼 중요하다.

일반론으로도 AWQ·GPTQ 4-bit 는 대부분의 평가에서 **작지만 일관된 하락**을 보인다.
"4-bit 는 공짜"가 아니라 "대체로 감당할 만한 값을 치른다"가 맞는 표현이다.

주의할 점 하나 — 이 모델은 thinking 모드가 **기본으로 켜져 있다.** 토큰을 훨씬 많이 쓰므로,
체감 속도를 이전 모델과 비교하려면 모드를 맞추고 재야 한다. 안 맞추고 재면 "느려졌다"는
잘못된 결론이 나온다.

## 35B-A3B — 아직 소문이다

**결론부터: 공식 발표는 없다.**

- 근거로 도는 것은 X 게시물 하나("GitHub 커밋에서 발견, 35B 총 파라미터·약 3B 활성")와,
  Hugging Face 의 Max 모델 토론방에 올라온 요청 글이다
- 검색으로 확인되는 것은 **이전 세대**뿐이다 — `Qwen/Qwen3.6-35B-A3B`(2026-04), `Qwen3.5-35B-A3B`.
  vLLM 레지스트리에도 3.5·3.6 만 있다
- 즉 "3.8 세대에도 같은 자리가 나올 것"이라는 기대는 **패턴 추론**이고, 실물 근거는 없다

기대가 큰 이유는 분명하다. 35B-A3B 는 총 35B 인데 활성 3B 라 **8~16GB VRAM 대에서 돌아가는
사실상 유일한 실용 MoE** 자리였다. 3.6 세대 것이 지금도 쓰이는 이유다.

확인하려면 이 셋을 보면 된다. 기사가 아니라 여기가 정본이다.

1. Hugging Face `Qwen` 조직 페이지에 `Qwen3.8-35B-A3B` 저장소가 생기는지
2. vLLM `tests/models/registry.py` 에 항목이 들어가는지
3. Qwen 공식 블로그 발표

## 이 프로젝트에 무슨 의미인가

당장 붙일 데는 없다. 다만 두 갈래가 있다.

| 갈래 | 무엇 |
|---|---|
| 로컬 LLM 벤치마크 후속 | 이전 측정은 M1 Max 한 대에서 런타임 두 조합을 비교한 것이었다. 27B 4-bit 를 같은 방법으로 재면 **모델 세대 축**이 하나 붙는다 |
| ai-trend-bot | 지금 요약에 쓰는 모델을 27B 로 바꿔 볼 여지가 있다. 다만 262K 컨텍스트가 이 용도에 필요한지는 별개 문제다 |

둘 다 **재기 전에는 아무 주장도 하지 않는다**는 원칙이 그대로 적용된다.

## 이 문서의 한계

여기 적힌 수치 중 **직접 잰 것은 하나도 없다.** 전부 모델 카드·벤더 발표·커뮤니티 측정을
옮긴 것이고, 벤치마크 점수는 특히 독립 검증이 없다. 27B 를 실제로 받아 M1 Max 에서 재면
그때 이 문서를 실측 기록으로 갱신한다.

35B-A3B 절은 시간이 지나면 가장 먼저 낡는다. 나오면 나온 대로, 안 나오면 안 나온 대로
한 줄로 정리하고 이 절은 지운다.
