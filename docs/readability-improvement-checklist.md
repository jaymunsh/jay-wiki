# 가독성·디자인·카피 개선 체크리스트

> 2026-07-18 사이트 평가에서 도출. 목표: "이해하기 쉽고 명확하게, 가독성 좋게".
> 우선순위 P1(효과 큼, 먼저) → P3. **1~7번은 2026-07-18 적용 완료.** 규모: S(1시간 내) / M(반나절) / L(하루 이상).
> URL·SEO 쪽 이월 과제는 [url-seo-conventions.md](url-seo-conventions.md) 참고.

## P1 — 타이포그래피 (가독성의 8할)

- [x] **1. 폰트 크기 토큰 스케일 도입** (M)
      현재 8~34px 사이 18종이 산재. `tokens.css`에 `--fs-*` 5~6단(예: 12/13/15/17/21/26)을 정의하고 전 CSS를 토큰으로 치환. radius(`--r-*`)처럼 관리.
- [x] **2. 본문 크기 상향: `.prose` 14.5px → 16px** (S)
      읽는 글 중심 사이트의 본문 기준. code/table 크기도 비율 맞춰 재조정.
- [x] **3. 초소형 글자 퇴출** (S)
      8~9px 전면 제거(현재 11곳), 장식 라벨 하한 11px. 9~10px 사용처 33곳 점검.
- [x] **4. 본문 줄 길이 제한: `.prose`에 `max-width: 46rem`** (S)
      현재 본문 컬럼 약 900px → 한 줄 한글 60자 이상. 적정선은 40자 내외.
- [x] **5. 저대비 텍스트 보정** (S)
      라이트 `--text-mute` #8a91a0(3.1:1)는 WCAG AA 미달 → 4.5:1 이상으로 어둡게.
      다크 `--text-mute` #6b7080(≈4.4:1)도 경계선이라 함께 확인.

## P2 — 카피·글 (요약 층위가 문제, 위키 본문 문체는 유지)

- [x] **6. 히어로 리라이트 + CTA 추가** (S)
      추상문("판단과 결과를 실행 가능한 기록으로…") → 구체 장면("miniPC 한 대에 k3s를 올려 이 사이트를 직접 운영합니다…").
      "Saga 실패 직접 실행해보기 →" 같은 주 행동 버튼 1개 필수.
- [x] **7. BUILD/OPERATE/IMPROVE 카드를 클릭 가능하게** (S)
      현재 장식용. 각 카드 → 해당 카테고리 첫 문서(/wiki/...)로 연결.
- [x] **8. 허브 카드 요약문 패턴 통일** (M) — 2026-07-18 적용, 21개 전부 리라이트. 카드 본문은 사용자 결정으로 12px(--fs-xs).
      "장면 질문 1문장 → 조치 2개 짧은 문장" 패턴으로 21개 카드 리라이트.
      예: "예약과 판매 확정을 분리하고 중복 callback과 보상 전이를 제한하면…" →
      "**마지막 재고 1개에 주문 2건이 동시에 들어오면?** 예약과 확정을 분리해 한 건만 성공시킨다. 중복 callback은 한 번만 반영한다."
- [x] **9. 전문용어 풀이 재검토** (S) — 별도 용어집은 본문·모니터링 설명과 중복돼 2026-07-21 제거. 필요한 용어는 사용되는 문서 문맥에서 설명한다.
      멱등·보상(compensation)·outbox·DLQ·fan-out. 허브/카드 층위에서만 필요(위키 본문은 이미 잘 풀고 있음). 괄호 또는 툴팁.
- [ ] **10. 영문 섹션 라벨 정리** (S)
      RUN STATUS / POLICY IMPLEMENTATION / PRODUCTION BOUNDARY / EXAMPLE CASE / REVIEW CHECKLIST…
      한국어 라벨을 주로, 영문은 보조 장식으로 강등. 페이지당 2~3개 이하로.
- [ ] **11. 표 셀의 keyword 나열 정리** (M)
      경계표 셀("payment ID unique constraint, callback inbox와 원문 서명·replay 검증")처럼
      쉼표 나열이 긴 셀은 줄바꿈 리스트로. 모바일 표 스크롤 최소화.

## P3 — 구조·정보 밀도

- [ ] **12. 헤더 내비에 "위키" 항목 추가** (S)
      주력 콘텐츠인데 로고 클릭으로만 진입 가능. 검색·자유게시판·실무 사례·모니터링과 동급으로 노출.
- [ ] **13. 시나리오 상세의 보조 섹션 접기** (M)
      실행 흐름(01~05)을 주인공으로. POLICY IMPLEMENTATION·PRODUCTION BOUNDARY는
      `<details>` 기본 접힘 → 밀도 유지하면서 읽는 순서 생성.
- [ ] **14. 홈 첫 화면 정보량 재검토** (L)
      히어로 + 카드 3 + 탭 + 오케스트레이션 맵 + 대시보드 전문이 한 번에 노출.
      대시보드 글은 요약 + "전체 보기" 링크로 줄이는 안 검토.

## 작업 시 검증 방법

- 타이포 변경(1~5): 라이트/다크 양쪽 스크린샷 비교, 본문·카드·라벨이 있는 대표 3페이지(/, /scenarios, /wiki/아무글).
- 카피 변경(6~11): 소리 내어 읽었을 때 한 문장에 개념 3개 이상이면 분할.
- 대비(5): 변경한 색으로 4.5:1 이상인지 대비 계산기로 확인.
