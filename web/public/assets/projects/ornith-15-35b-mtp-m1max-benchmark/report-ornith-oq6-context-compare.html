컨텍스트 항목은 현재 상한 때문에 별도로 남겼다

ctx-64k와 ctx-96k는 모델 프로필의 max_context_window=49152보다 입력이 크다. 실행을 계속하면 유효한 속도 비교가 아니라 긴 프리필 대기만 발생하므로 이번 전체 스위트에서는 중단했다. 49,152 이상을 실제로 측정하려면 모델 프로필 상한을 먼저 올리고 재부팅한 뒤 다시 실행해야 한다.

해석할 때 주의할 점

  • 컨텍스트 상한은 입력 길이가 아니다.
  • 짧은 입력에서는 49k와 82k의 디코드 속도가 거의 같다.
  • 49k 설정에서는 90k 입력을 그대로 넣을 수 없어, 같은 자료의 44k 토큰 버전을 측정했다.
  • 장문 cold 속도는 프리필 대기와 분리된 생성 속도이며, TTFT는 별도로 봐야 한다.
  • oQ6의 속도 향상보다 Ornith의 A3B MoE 구조 효과가 크다.

정확한 1:1 비교의 한계: 지난번 29.32 tok/s는 90,171토큰 입력과 MLX 6bit 모델이었다. 이번 장문 측정은 같은 작업과 문서 앞부분을 사용했지만 44,000토큰 입력과 oQ6 모델이므로, 개선 폭 전체를 양자화나 context 절반의 효과로 귀속할 수 없다. 장문 테스트는 MTP off로 먼저 측정했으므로, MTP의 장문 효과는 아직 별도 검증이 필요하다.

VLM MTP 호환성: Qwen3.8-27B-MTP-4bit를 drafter로 연결하면 RMSNorm 차원 불일치가 발생했다. 타깃 모델 hidden size는 2048, drafter는 5120이므로 이 조합은 사용하지 않는다.
