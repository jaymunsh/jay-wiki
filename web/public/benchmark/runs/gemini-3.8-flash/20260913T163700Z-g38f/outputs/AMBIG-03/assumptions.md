# AMBIG-03 판단 근거 문서 (assumptions.md)

본 문서는 `ambig03-spec.md` 재시도 정책 명세서를 구현하는 과정에서 식별된 명세 내 모순점과 누락 사항, 그리고 이에 대해 내린 기술적 의사결정과 판단 근거를 기술한다.

---

## 1. 섹션 3과 섹션 7의 명세 모순 해결

- **명세 모순 식별**:
  - **섹션 3 (재시도 횟수)**: "일시 오류에 대해서만 재시도하며, **최초 호출 포함 최대 3회 시도한다**."
  - **섹션 7 (종료 조건 표)**: 일시 오류 발생 시 "**성공할 때까지 재시도**", 그리고 "최대 대기 총합 5초 초과 시 남은 횟수와 무관하게 중단하고 실패 반환".
  - 즉, 재시도 상한이 '최대 3회'인지 아니면 5초 데드라인 내에서 '성공할 때까지 무한 재시도'인지 서로 충돌함.
- **판단**: **섹션 3의 "최초 호출 포함 최대 3회"를 기본 시도 횟수 제약으로 채택**하되, **섹션 7의 "최대 대기 총합 5초 초과 시 중단"을 추가적인 안전 제약(Safety Guardrail)으로 결합**.
- **근거**:
  1. 결제 게이트웨이 연동 모듈(문서 상단 적용 범위)의 특성상, 사용자 요청 스레드가 결제 지연으로 무한정 대기하는 것은 심각한 클라이언트 타임아웃 및 UX 저하를 유발함.
  2. 섹션 3의 '최대 3회'는 구체적인 횟수 한도를 명시하고 있는 반면, 섹션 7의 '성공할 때까지'는 정책 목표 수준의 기술이거나 초안의 잔재일 가능성이 높음.
  3. 따라서 기본적으로 최대 3회(최초 1회 + 재시도 2회)를 시도하며, 어떠한 경우에도 누적 대기 시간이 5,000ms를 초과할 경우 즉시 실패 처리하도록 양대 제약을 모두 만족시킴.

---

## 2. 대기 간격 및 지터(Jitter) 정책

- **명세 내용**: 첫 대기 200ms, 매번 2배씩 증가, 상한 2,000ms, 지터 미사용.
- **구현 판단**:
  - 1회 실패 후: 200ms 대기
  - 2회 실패 후: 400ms 대기 (이후 지속 시 800ms, 1600ms, 최대 2000ms로 캡핑)
  - 지터(Random Jitter)는 명세에서 "지터는 사용하지 않는다"고 명시적으로 금지하였으므로 정확한 고정 지수 간격을 준수함.

---

## 3. 영구 오류와 일시 오류의 구체적 분류 기준

- **명세 내용**:
  - 영구 오류: 인증 실패(401/403), 잘못된 요청(4xx 중 429 제외), 한도 초과
  - 일시 오류: 네트워크 단절, 타임아웃, 게이트웨이 5xx 응답
- **판단**:
  - 에러 객체의 `status` 또는 `statusCode`를 확인하여 401, 403, 그리고 400~499 범위(408, 429 제외)는 즉시 throw.
  - 에러 코드 `LIMIT_EXCEEDED`, `PERMISSION_DENIED`도 영구 오류로 간주하여 즉시 throw.
  - 5xx, 429, 408 및 네트워크 에러(`ECONNRESET`, `ETIMEDOUT` 등)는 일시 오류로 간주하여 재시도.

---

## 4. 로깅 및 관측 이벤트

- **명세 내용**: `retry.attempt`, `retry.reason` 로그를 남기고 최종 실패 시 `retry.exhausted` 발행.
- **판단**: 콘솔/구조화 로그 형태로 `[retry.attempt]` 및 `[retry.exhausted]` 이벤트를 JSON 메타데이터와 함께 출력하도록 구현함.
