# AMBIG-02 assumptions — 재시도 래퍼 판단 근거

- case_version: v0.5-character-1
- 과제: `export async function callWithRetry(fn)` 구현 + 판단 근거 문서화

명세는 "외부 API 호출이 실패하면 재시도한다"로 정책 하나만 주고, 횟수·간격·대상 오류를 지정하지 않는다. 아래는 그 누락 부분에 내린 판단과 근거다.

## 1. 총 시도 횟수 기본값 3회
- **판단**: `maxAttempts` 기본값을 3(초시도 1 + 재시도 2)로 정한다. `callWithRetry(fn)`는 이 기본으로 동작한다.
- **근거**: 재시도 함수의 관례상 보편적 기본값이 없으며, "재시도한다"를 그대로 따르려면 최소 1회는 더 시도해야 한다. 3회는 과도하지도 부족하지도 않은 중간값으로, 호출자가 옵션으로 조정 가능하다.

## 2. 지수 백오프(진동 없음)
- **판단**: n번째 재시도 대기 시간은 `backoffBase * 2^(n-1)` (기본 100ms → 100, 200, 400ms). 기본은 진동(jitter)을 켜지 않는다.
- **근거**: 외부 API 재시도는 짧은 간격 반복보다 간격을 늘리는 지수 백오프가 일반적이다. 진동은 동시성으로 인한 붐(Thundering Herd)을 완화하지만 결정적 결과를 요구하는 이 과제에서는 기본 off로 하고 옵션으로만 제공한다.

## 3. 재시도 대상 오류: 모든 오류 (명세 단일 정책)
- **판단**: `shouldRetry` 기본은 모든 오류에 true. 4xx(영구 오류)와 5xx(일시적 오류)를 구분하지 않는다.
- **근거**: 명세가 "실패하면 재시도"로 단일 정책만 제시한다. 오류 구분 정보는 없으며, 구분 없이 재시도하는 것이 명세에 가장 직설적으로 따른다. 영구 오류까지 재시도하는 비효율은 호출자가 `shouldRetry`로 제어 가능하다.

## 4. 최종 실패시 마지막 오류를 그대로 던짐
- **판단**: 모든 시도가 실패하면 마지막 오류를 rethrow. 새 오류로 감싸지 않는다.
- **근거**: "성공 시 반환값을 그대로 돌려준다"의 반대 구조로, 실패 시에도 원래 오류 정보를 손실하지 않고 전달하는 것이 자연스럽다. 재시도 내역을 붙이는 정보 추가는 명세에 없다.

## 5. 반환값은 fn의 해결값 그대로
- **판단**: 성공 시 `fn()`이 해결한 값을 변환 없이 반환. 배열·객체·undefined 모두 그대로.
- **근거**: 명세가 "그 반환값을 그대로 돌려준다"고 명시한다.

## 6. 옵션은 두 번째 인자로 선택적 확장
- **판단**: `callWithRetry(fn, options?)`로 `maxAttempts`·`backoffBase`·`jitter`·`sleep`·`shouldRetry`를 주입 가능하게 한다. `sleep`·`shouldRetry`는 테스트용 주입처이기도 하다.
- **근거**: 핵심 시그니처 `callWithRetry(fn)`는 그대로 유지하면서, 명세에 없는 튜닝 요소를 후방 호환 범위에서 제공한다.

## 확인하지 않은 것
- 실제 네트워크 지연·타임아웃 동작 — 주입한 `sleep`으로만 백오프 간격을 검증.
- `jitter=true` 시 랜덤 대기 상한 검증 — 공식은 확인했으나 값은 결정적 테스트 범위를 벗어난다.
- 비동기 오류가 아닌 sync throw(`fn`이 즉시 throw) 처리 — 명세는 비동기 함수이므로 다루지 않았다.
