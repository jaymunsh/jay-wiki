# AMBIG-02 — 판단 근거 (assumptions)

- case_version: v0.5-character-1
- 과제: 외부 API 호출 재시도 래퍼 (`callWithRetry`)
- 입력: 없음 (고정 입력 없는 과제, 문제지 명세만 따름)

## 문제지 명세 (요약)

- `export async function callWithRetry(fn)` 제공.
- `fn`은 외부 API를 호출하는 비동기 함수, 성공 시 반환값을 그대로 반환.
- 정책: 실패하면 재시도.
- 명세에 없는 판단을 문서화.

## 내린 판단과 근거

명세는 함수 시그니처와 정책(실패 시 재시도)만 주고, 재시도 횟수·대기·오류 분류 등을 비워두었다. 아래는 그 빈칸을 채운 판단과 근거다.

### A. 재시도 횟수 기본값 = 3 (총 4회 시도)

- **결정**: `retries` 기본값을 3으로 정했다. `retries`는 "초호 호출 이후의 재시도 횟수"로 해석하므로, 초기 호출 1회와 합쳐 총 4회의 `fn` 호출이 가능하다.
- **근거**: 재시도 라이브러리(axios-retry, node-retry 등)가 재시도 횟수를 "초기 호출 이후"로 정의하는 관례와 맞춘다. "재시도"는 원래 시도를 제외한 추가 시도를 의미한다는 언어적 관례다.
- **대안**: `retries`를 "총 시도 횟수"로 보면 기본 3이 총 3회가 된다. 두 해석이 가능하므로 assumptions에서 명시했다. 이번 구현은 "초기 이후 재시도 횟수"로 확정한다.

### B. 대기(delay) 기본값 = 0 (대기 없음)

- **결정**: `delayMs` 기본값을 0으로 정해, 기본 상태에서는 재시도 간 대기하지 않는다.
- **근거**: 문제지에 대기 간격·백오프·지터에 대한 지정이 전혀 없다. 지시 없는 인위적 대기(예: 1초)를 기본에 끼워 넣으면 명세 밖 동작을 발명하는 것이므로, "대기 없음"을 기본으로 하고 원하는 대기를 옵션으로만 제공한다.
- **활용**: 호출자가 `delayMs`를 주면 고정/지수 백오프로 대기한다(판단 C).

### C. 백오프 방식: fixed / exponential (기본 fixed)

- **결정**: `backoff` 옵션으로 `'fixed'` 또는 `'exponential'`을 선택하게 했다. 기본은 `fixed`.
- **근거**: 지수 백오프가 일시 오류에 유리하지만 문제지가 지정하지 않았으므로 기본을 단순 `fixed`로 하고, 필요시 exponential을 선택할 수 있게 했다. exponential은 `delayMs * 2 ** attempt`로 계산한다(첫 재시도 `delayMs`, 이후 2배).

### D. 재시도 trigger: throw되는 모든 오류

- **결정**: `fn`이 `throw`하거나 reject되는 모든 오류를 재시도 조건으로 정했다.
- **근거**: 문제지 정책이 "실패하면 재시도한다"로 일반적이다(일시/영구 구분 지시 없음). 오류 종류 분류는 이 과제 범위를 벗어나므로, throw되는 모든 것을 재시도한다. (오류 분류가 필요한 AMBIG-03과 구분되는 지점.)

### E. 반환값 그대로 전달

- **결정**: `fn`이 성공(resolve)하면 그 반환값을 `await`해 그대로 돌려준다.
- **근거**: 명세 "성공 시 그 반환값을 그대로 돌려준다"에 그대로 따른다.

### F. 재시도 소진 시 마지막 오류 던지기

- **결정**: 모든 재시도 횟수를 소진하면 마지막에 발생한 오류(`lastError`)를 그대로 throw한다.
- **근거**: 호출자가 재시도 끝에 왜 실패했는지 알 수 있어야 디버깅이 가능하다. 첫 오류가 아니라 마지막 오류를 던지는 것이 현재 상태를 반영한다.

### G. onRetry 콜백 계약

- **결정**: 재시도 전에 `onRetry({ attempt, maxRetries, error, waitMs })`를 호출한다(기본 `null`).
- **근거**: 관측성(observability)을 위해 제공하되, 기본값 `null`로 강제하지 않는다. `attempt`는 "몇 번째 재시도였는지"(1부터), `maxRetries`는 설정된 최대 재시도 횟수, `waitMs`는 다음 대기 시간을 전달한다.

### H. sleep 주입 가능

- **결정**: 대기 구현 `sleep`을 옵션으로 받아 테스트에서 교체할 수 있게 했다(기본 `setTimeout` 기반).
- **근거**: 실제 대기를 테스트에서 기다리면 테스트가 느려지므로, `sleep`을 주입해 즉시 반환되도록 한다. 프로덕션 기본값은 `defaultSleep`(`setTimeout`)이다.

### I. fn이 함수가 아닌 경우

- **결정**: `fn`이 함수가 아니면 `TypeError`를 던진다(재시도하지 않음).
- **근거**: 타입 오류는 재시도로 해결될 성질의 문제가 아니므로 즉시 실패한다.

## 미해결 / 열린 문제

- **재시도 횟수의 정확한 해석**(초기 이후 vs 총 횟수)은 관례로 확정했으나, 명세 원문으로 검증한 것은 아니다.
- **대기 기본값 0**은 "명세 지정 없음"을 근거로 선택했으나, 실무에선 0대기가 붐 효과를 낼 수 있어 호출자가 `delayMs`를 주도록 유도하는 선에서만 안전장치를 뒀다.
- **onRetry 시그니처**의 필드명은 편의상 정했으므로, 별도 계약이 있으면 변경 가능한다.
