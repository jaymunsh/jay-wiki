# AMBIG-01 — 판단 근거 (assumptions)

- case_version: v0.5-character-1
- 과제: AMBIG-01 (주차 요금 계산 함수 구현)
- 입력: 없음 (고정 입력 없는 과제, 문제지 명세만 따름)

명세는 세 줄로 축약되어 있어, 여러 곳을 추가로 정해야 했다. 각 판단과 그 근거를 적는다.

## 1. 10분당 500원 — 올림 과금

"10분당 500원"을 **10단위 올림**(part of a 10-minute block counts as a full block)로 해석했다. 주차 요금이 소수 분까지 정산되기보다 10분 단위로 떼어 매기는 관례이고, "당"이 분할 단위를 나타내는 표현이기 때문이다.

- 예: 입차 후 30분 무료 초과 35분 → 과금 5분 → `ceil(5/10)=1`블록 → 500원.
- 50분 → 과금 20분 → 2블록 → 1000원.

대안으로 "분당 비례"를 고려했으나, 명세가 "10분당"과 금 단위를 제시하므로 과금 단위를 10분으로 잡는 것이 자연스럽다고 판단했다.

## 2. 기본 30분 무료 — 첫 30분에만 적용

30분 무료는 **방문 전체의 첫 30분**에 한 번 적용한다고 했다. 다일 주차라 해도 무료는 1회라는 해석이다. 구현상 24시간 단위 루프에서 첫 기간의 `billable`에서 30분을 빼고, 이후 잔여 기간은 무료 없이 계산한다.

- 이 또한 ambiguity이나, "기본 30분 무료"가 진입당 혜택으로 통용되는 관례 때문이다. (다일 주차 시 하루마다 30분이 무료라는 반대 해석도 가능함을 기록한다.)

## 3. "1일 최대 15,000원" — 24시간 단위 일일 캡

"1일 최대 15,000원"을 **24시간을 한 단위로 하는 일일 상한**으로 해석했다. "1일"이라는 절대 최고가 아니라 1일당 상한을 나타낸다고 봤기 때문이다. 따라서 24시간 초과 시에는 일수만큼 누적한다.

- 24시간 → 15,000원 (캡).
- 25시간 → 1일 15,000 + 1시간(1500) = 16,500원.
- 48시간 → 30,000원.

대안으로 "15,000원을 절대 상한(flat cap)"으로 잡을 수도 있으나, 이 경우 "1일"이라는 수식어가 의미를 잃는다. 따라서 일일 캡 해석을 택했다. 구현은 남은 시간을 24시간 단위로 나누고, 각 단위에서 (30분 무료 → 10분당 500원 → 15,000 캡)을 적용해 합산한다.

## 4. 과금 계산 순서

1. `duration = exit - entry` (분).
2. `duration <= 0` → RangeError (출차가 입차보다 늦지 않음).
3. 24시간 단위 루프:
   - 단위당 30분 무료 적용.
   - 과금 시간 = `max(0, 단위시간 - 30)`.
   - 블록 수 = `ceil(과금시간 / 10)`.
   - 단위 요금 = `min(블록 × 500, 15000)`.
4. 총합을 정수로 반환 (`Math.round`).

## 5. 입력 검증 — RangeError

"잘못된 입력은 RangeError"라고 했으므로 다음을 RangeError로 처리한다.

- 문자열이 아닌 입력 (`typeof !== 'string'`): `new Date(number)`가 타임스탬프로 해석되어 의도와 다르게 넘어가는 것을 막기 위해 문자열로 제한한다.
- 파싱 실패 (`NaN`): 유효하지 않은 ISO 8601.
- `duration <= 0`: 출차 입력이 입차 입력과 같거나 이전.

## 6. 미해결/열린 문제 (기록용)

- 다일 주차 시 30분 무료 적용 회수(1회 vs 1일당 1회)는 구현상 1회로 잡았으나, 운영 정책이면 1일당일 수도 있다.
- "10분당"의 올림 vs 내림/비례는 관례 기준 올림으로 확정했으나 명세상 엄밀 검증 불가.
- 타임존: ISO 8601 문자열을 `Date`가 해석(문자열에 잔여가 있으면 UTC/로컬 혼재) — 테스트는 모두 `Z`(UTC) 기준으로 진행.
