# ALG-01 — 알고리즘 설명

## 문제 요약
반열린 구간 `[start, end)` 작업들을 겹치지 않게 골라 **가치 합의 최댓값**을 구한다. 동시에 둘 이상 불가, 작업은 분할 불가, 일부/아무도 선택 가능.

## 알고리즘 — 가중 구간 계획 (Weighted Interval Scheduling)
1. **검증**: `jobs`가 배열인지, 개수 ≤ 200,000, 각 작업이 3개 요소 배열, 세 값이 유한 정수, `0 <= start < end <= 1e9`, `0 <= value <= 1e9`를 확인. 하나라도 어긋나면 `RangeError`.
2. **복사**: 원본을 건드리지 않으려면 `jobs`를 새 배열(`jobs2`)로 복사한다. 이후 정렬은 복제본에만.
3. **정렬**: `end` 기준(동점 시 `start` 기준)으로 오름차순 정렬.
4. **DP**: `dp[i]` = 정렬 후 **앞 i개 작업**만 쓸 때의 최대 가치.
   - `p = upperBound(start_{i-1})` = `end <= start_{i-1}`인 작업 수. 이 작업들은 모두 `start_{i-1}`보다 이르거나 같게 끝나므로 i-1번 작업과 겹치지 않는다.
   - `dp[i] = max(dp[i-1], value_{i-1} + dp[p])` (i-1번 작업을 "안 쓰는 경우" vs "쓰는 경우").
   - 답 = `dp[n]`.
5. `end_i > start_i`이므로 `p <= i-1 < i`이고, `dp[p]`은 이미 계산돼 있음을 이용한다. `ends`는 오름차순이므로 `upperBound`는 **이분 탐색 O(log n)**이다.

## 왜 맞는지
- 반열린 구간이라 `end_j == start_i`는 겹치지 않음 → 조건을 `end <= start`로 두면 맞음.
- `end`로 정렬하면, 어떤 작업을 끝으로 잡든 그와 양립하는 작업은 전부 "이르게 끝난" 연속 접두사(앞 p개) 안에 들어온다. 그래서 **접두사 DP**가 완전: 각 i에서 "i-1번 작업 선택/비선택" 두 가지만 보면 최적으로 좁혀진다(최적 부분 구조 + 중복 부분 문제).
- 비선택: `dp[i-1]`(앞 i-1개의 최적). 선택: `value_{i-1} + dp[p]`(i-1번과 양립하는 접두사 최적). 둘 중 큰 값이 앞 i개의 최적.

## 복잡도
- **시간**: 정렬 O(n log n) + 각 i마다 이분 탐색 O(log n) → **O(n log n)**.
- **추가 공간**: `jobs2`(n) + `ends`(n) + `dp`(n+1) → **O(n)**.
- **범위**: 최대 합 = 200,000 × 1e9 = 2e14 < 2^53 (안전 정수) → `Number` 그대로 안전.

## 직접 확인한 경계 사례 (test.mjs, 32건 모두 통과)
- 빈 입력 → 0. 단일 작업. `end==start` 연속 연결(3개 → 3). 정확히 같은 구간 여러 개([2,4,7],[2,4,9]→9, 둘 중 하나만).
- 정렬 순서 무관(무작위 순서 입력 → 동일 답). 최댓값 좌표(1e9). 합이 안전 정수 안(2e9).
- **입력 보존**: 호출 후 원본 배열·내부 배열 내용 불변 확인.
- **잘못된 입력 거부**: null/숫자/객체, 작업이 배열 아님, 길이 2/4, 실수, NaN, Infinity, 문자열, start==end, start>end, 음수, end>1e9, value>1e9, 200,001개 → 모두 `RangeError`.
- **대규모**: 200,000개(비중첩 체인, 전부 값 1 → 200,000) ≈ **41ms**; 200,000개(전체 겹침 → max 199,999) ≈ **16ms**. O(n log n) 목표 충족.
