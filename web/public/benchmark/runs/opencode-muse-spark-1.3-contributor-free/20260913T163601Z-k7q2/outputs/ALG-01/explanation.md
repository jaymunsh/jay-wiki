# ALG-01 해설

## 문제 요약

장비 하나로 처리할 작업 목록 `jobs`가 주어진다. 각 작업은 `[start, end, value]`이고 시간 구간은 **반열린 구간 `[start, end)`**이다. 서로 겹치지 않는 작업들의 가치 합의 최댓값을 구해 정수 하나로 반환한다. 고전적인 **가중 구간 스케줄링(weighted interval scheduling)** 문제다.

## 핵심 관찰

반열린 구간이므로 앞 작업의 종료 시각과 다음 작업의 시작 시각이 **같아도** 함께 선택할 수 있다. 두 작업 `a`, `b`가 양립 가능한 조건은

```
a.end <= b.start   또는   b.end <= a.start
```

이다. 공개 예시 `maxValue([[0,3,5],[3,5,6],[0,5,10]]) === 11`이 이 조건을 확인해 준다. `[0,3)`과 `[3,5)`는 시각 3에서 맞닿지만 겹치지 않으므로 함께 선택되어 `5 + 6 = 11`이 된다.

## 알고리즘

1. **검증과 복사** — 입력이 배열인지, 각 작업이 길이 3 배열인지, 세 값이 유한한 정수인지, `0 <= start < end <= 1e9` 및 `0 <= value <= 1e9`인지 확인한다. 위반 시 `RangeError`를 던진다. 검증하며 값을 새 평탄 배열(`starts`, `ends`, `values`)로 복사하므로 호출자의 배열과 내부 배열은 변경되지 않는다.
2. **종료 시각 기준 정렬** — 작업 인덱스를 `end` 오름차순으로 정렬한다. 정렬은 인덱스 배열에만 적용하므로 입력 순서는 그대로 유지된다.
3. **이진 탐색으로 호환 작업 개수 찾기** — 정렬된 `end` 값 배열 `sortedEnds`를 만든다. i번째 작업에 대해, 앞선 `i-1`개 중 `end <= start_i`인 작업의 개수 `p`를 이진 탐색으로 구한다.
4. **동적 계획법** — `dp[i]`를 "정렬 순서로 앞의 i개 작업을 썼을 때의 최대 가치 합"으로 정의하면

   ```
   dp[0] = 0
   dp[i] = max(dp[i-1], value_i + dp[p(i)])
   ```

   이다. `dp[i-1]`은 i번째 작업을 건너뛰는 경우, `value_i + dp[p(i)]`는 i번째 작업을 선택하고 그와 양립하는 앞선 작업들만 쓰는 경우다. 답은 `dp[n]`.

## 복잡도

- **시간**: 종료 시각 정렬 `O(n log n)` + 각 작업마다 이진 탐색 `O(log n)` → 전체 `O(n log n)`.
- **공간**: 평탄 배열들과 `dp`, `order`, `sortedEnds` 모두 길이 `n` → 추가 공간 `O(n)`.

## 검증

`test.mjs`로 다음을 확인했다(총 32개 검사 통과).

- **공개 예시 4개**: `[] → 0`, `[[0,3,5],[3,5,6],[0,5,10]] → 11`, `[[0,10,15],[0,4,8],[4,10,8]] → 16`, `[[2,4,7],[2,4,9]] → 9`.
- **기본 형태**: 단일 작업, 맞닿은 사슬(`[0,1),[1,2),[2,3)` → 3), 완전 중첩, 동일 구간 중복, 값 0, 경계 좌표(`end = 1e9`, `value = 1e9`).
- **잘못된 입력 15종 → `RangeError`**: 배열 아님, 길이 3 아님, `start >= end`, 음수 시작, `end > 1e9`, `value > 1e9`, 음수 값, 소수, `NaN`, `Infinity`, 작업 수 초과(200,001).
- **비변경성**: 호출 후 입력 배열과 내부 배열의 JSON 스냅샷이 동일함을 확인.
- **무작위 대조**: 소규모 무작위 입력 2,000건을 완전 탐색(brute force) 결과와 비교해 전부 일치.
- **성능**: n = 200,000에서 31.8ms에 완료(측정 환경: 로컬 Node.js 22.22.2).

## 경계 처리 메모

- 빈 입력은 0을 반환한다.
- 동일 구간 작업이 여러 개면 가장 큰 가치 하나만 선택된다(서로 겹치기 때문). 예: `[[2,4,7],[2,4,9]] → 9`.
- 값이 0인 작업은 선택해도 합에 영향이 없다.
- 합은 JavaScript 안전 정수 범위 안에 있으므로 별도의 큰 수 처리가 필요 없다.
