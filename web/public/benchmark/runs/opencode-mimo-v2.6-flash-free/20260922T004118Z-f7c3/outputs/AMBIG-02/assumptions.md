# AMBIG-02 — 구현 판단 문서화

명세: "외부 API 호출이 실패하면 재시도한다" + `callWithRetry(fn)` 시그니처뿐. 내가 결정한 사항:

1. **최대 시도 횟수: 최초 호출 포함 3회** (재시도 2회). 무한 재시도는 자원 고갈 위험이 커 기본값을 두었고, AMBIG-03 같은 명세(최대 3회)와도 정합. 옵션으로 재정의 가능.
2. **백오프: 지수 + 상한.** 200ms → 400ms, 상한 2,000ms. 외부 API 표준 관례이며 지연 근거는 가독성을 위해 옵션 기본값으로 노출.
3. **재시도 대상: `fn`이 던지는 모든 예외.** "실패"의 정의가 명세에 없음(HTTP 상태, 네트워크 등) — 래퍼는 `fn` 구현을 모르므로 **throw를 실패로** 간주. `retryOn(err)` 콜백으로 특정 오류만 재시도할 수 있게 확장(기본: 전부 재시도).
4. **비재시도 조건 기본 없음**: 명세가 영구/일시 오류 구분을 안 하므로 기본은 전부 재시도. 구분이 필요하면 옵션으로 주입.
5. **성공 판정**: `fn`이 값을 반환(resolve)하면 즉시 그대로 반환. falsy도 성공(0, null, undefined 포함) — throw가 아니면 성공.
6. **모든 시도 실패 시**: **마지막 오류를 그대로 throw** (첫 오류 아님 — 최신 상태 보존이 디버깅에 유리).
7. **`fn`에 전달하는 인자**: 시도 번호(1부터)를 단일 인자로 전달. 명세가 인자 없음이라 시그니처에 넣지 않아도 되는 확장.
8. **기본 지연의 실제 대기**: 테스트 주입용 `sleep` 옵션을 두어 기본값은 `setTimeout` 사용(테스트에서 0ms로 바꿔 가속).
9. **멱등 키**: AMBIG-03(명세서)에만 있는 요구. AMBIG-02 명세에는 없어 `fn` 내부 책임으로 간주하고 래퍼는 추가하지 않음.
10. ** 동시 호출**: `callWithRetry` 자체는 상태를 안 가지므로 여러 `fn`을 동시에 호출해도 안전(각각 독립 루프).
11. **잘못된 인자**: `fn`이 함수가 아니거나 `maxAttempts < 1`이면 RangeError(문제지 전체 공통 관례 상속).
