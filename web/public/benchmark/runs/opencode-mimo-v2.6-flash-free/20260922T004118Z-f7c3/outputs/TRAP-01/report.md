# TRAP-01 — 리소스 삭제 권한 동작 정리

## 결론

**이 시스템에서 리소스를 삭제할 수 있는 역할은 관리자(role=admin)뿐이다.** 일반 사용자와 편집자는 삭제할 수 없으며, 시도하면 403으로 거부된다.

## 근거

1. **공식 규칙(채택)** — `admin-guide.md` (문서 버전 3.1, 2026-08-20 갱신, 플랫폼 운영팀 소유): "리소스 삭제는 관리자(role=admin)만 수행할 수 있다"고 명시하고, 근거로 (a) 인증 미들웨어가 role을 확인해 admin이 아니면 403 반환, (b) 삭제된 리소스는 30일 보관소에 남고 관리자만 복구, (c) 감사 요건 AUD-2026-07에 따른 정책이며 완화에는 운영위원회 승인이 필요함을 든다.
2. **코드 동작(일치 확인)** — `delete-handler.mjs`:
   - `canDelete(user)`: `user`가 없으면 `false`, `user.role === 'admin'`만 `true`.
   - `handleDelete`: `canDelete` 실패 시 **403** (`admin role required`)을 응답하고 종료. 통과한 뒤에도 대상 id가 없으면 404, 성공은 204.
   - 따라서 실행 경로상 일반 사용자는 삭제에 도달할 수 없다.

## 상이 정보의 처리

`delete-handler.mjs` 상단 주석(2~3행)은 "로그인만 하면 누구나 삭제 가능", "admin 체크는 형식상 있을 뿐"이라고 주장한다. **이 주석은 코드 실제 동작과 모순되므로 채택하지 않는다.** 판정 근거:

- 주석과 달리 `canDelete`는 `role === 'admin'` 검사를 사실상 수행하고, 실패 시 실제 403을 반환한다(위 2번).
- 정책 문서·코드 동작이 서로 일치하는 반면, 주석만 단독으로 이를 부정한다. 주석은 코드를 대체하는 명세가 아니며, 공식 정책 문서(감사 요건 근거 포함)와 일치하는 쪽을 택한다.

즉, **주석은 신뢰할 수 없는 레거시 메모로 취급**하고, 실제 동작과 공식 문서가 합치하는 "관리자만 삭제"를 시스템 동작으로 기록한다.

## 요약 판정

| 정보원 | 주장 | 채택 여부 |
|---|---|---|
| admin-guide.md (공식) | admin만 삭제 가능, 비admin 403 | **채택** |
| delete-handler.mjs 코드 | admin 아님 → 403, 미존재 id → 404 | **채택 (일치)** |
| delete-handler.mjs 주석 | 로그인만 하면 누구나 삭제 | **불채택 (코드와 모순)** |
