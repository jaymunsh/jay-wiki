# ALG-01 설명

## 알고리즘

1. 잘못된 입력을 `RangeError`로 거부한다(길이·정수성·구간·값 범위, 작업 수 200,000 초과 포함). 입력은 수정하지 않고 사본을 정렬한다.
2. 작업을 **종료 시각 오름차순**으로 정렬한다. `dp[i]` = 정렬된 앞 `i`개 작업만 고려할 때의 최대 가치(반열린 구간이므로 `end <= start`인 작업은 compatible).
3. `i`번째 작업 `[s, e, v)`에 대해 이분 탐색으로 `ends[mid] <= s`를 만족하는 가장 큰 `j`(앞에서 끝나는 작업 수)를 찾고,
   `dp[i] = max(dp[i-1], dp[j] + v)`를 계산한다.
4. `dp[n]`이 답이다. 어떤 작업도 고르지 않는 경우(`dp[0] = 0`)를 포함한다.

## 맞는 이유

- 종료 시각 기준 정렬 + "선택하지 않음/선택함"의 최적 부분 구조: `i`번째를 고르면 그 앞에서 고를 수 있는 작업은 정확히 `end <= start_i`인 작업들뿐이고, 그들의 최대 가치는 `dp[j]`로 정의된다. 고르지 않으면 `dp[i-1]`. 둘 중 최대가 항상 최적이며 그리디(단순히 끝이 빠른 것)로는 최댓값을 보장할 수 없으므로(예: `[[0,10,15],[0,4,8],[4,10,8]]` → 16) DP가 필요하다.
- 반열린 `[start, end)`이므로 `end == start` 경계를 같은 조합에 넣을 수 있다. 이분 탐색 조건이 `ends[j] <= start`인 이유다.

## 복잡도

- 시간: 정렬 O(n log n) + 각 작업 이분 탐색 O(log n) → **O(n log n)**
- 공간: 정렬 사본·`ends`·`dp` 각 O(n) → **O(n)** 추가 공간
- 합은 안전 정수 범위(입력 제한상 최대 ~2e14).

## 직접 확인한 경계 사례 (test.mjs)

- 공개 예시 4개, 입력 순서 무관성, 입력 불변(JSON 스냅샷 비교)
- 반열린 경계: `[[0,5,10],[5,6,1]]` → 11, 연속 접합 3개 → 15
- 동일 구간 중복: 최댓값 하나만 선택(`[2,4,7/9/3]` → 9)
- 오염 입력 전부 `RangeError`(null, 길이≠3, 음수, 경계 초과, 실수, NaN, Infinity, 중간에 유효하지 않은 원소)
- 대규모: N=200,000 비중첩(45.6ms), N=200,000 전부 중첩(32.9ms), 패턴 입력(5,000,001)
- 무작위 200건을 O(2^n) 브루트포스와 교차 대조 — 전부 일치
