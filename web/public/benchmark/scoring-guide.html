02. 18개 과제에서 확인하는 것

분야 안에서는 과제별 비중이 같습니다. 각 항목을 펼치면 목적, 제출물, 검사 내용과 100점 배점을 확인할 수 있습니다. 아래 조건은 핵심 요약이며 링크된 고정 문제의 전체 요구사항이 우선합니다.

글쓰기 3개는 writing-v2.1 기준입니다. 기존 llama.cpp 답안에는 당시 문제를 적용합니다. 시간 한도는 응시 지침이며 앱이 강제로 종료하는 타이머를 뜻하지 않습니다.

03. 과제 하나는 어떻게 100점이 되나요?

자동 검사와 평가 AI의 판단을 구분합니다

알고리즘은 객관 검사 85점 + 품질 검토 15점, 국어·수학·과학은 각각 정답 검사 60점 + 근거·형식 검토 40점입니다. 나머지 14개에는 모든 항목을 한 번에 자동 채점하는 프로그램이 없습니다. 평가 AI가 테스트·도구 로그·브라우저 동작·원문 근거를 검토해 각 기준을 판정합니다.

자동 정답 확인은 정해진 조건을 확인하는 부분입니다. 테스트가 통과해도 설명력·문체·시각적 완성도까지 자동으로 증명되지는 않습니다. 반대로 동작 검증이 필요한 항목은 코드만 읽고 만점을 줄 수 없습니다.

평가 등급뜻배점 20점인 기준의 환산
0미충족0점
1대부분 다시 작업해야 함5점
2큰 수정이 필요함10점
3작은 수정이 필요함15점
4요구 수준을 충족함20점
미확인 (null)검사·관찰 근거가 부족함점수 확정 불가
기준 점수 = 그 기준의 최대 배점 × 평가 등급 / 4
과제 점수 = 객관 검사 점수 + 평가 기준별 점수의 합

계산 예시: 기술 블로그

아래는 계산법을 설명하기 위한 가상 평가이며 실제 모델 결과가 아닙니다.

기준배점등급환산
사실성30430
구성25318.75
설명력20315
문체 적합성1527.5
요구 준수10410
과제 점수81.25 / 100

점수와 통과 여부는 별개입니다

모든 필수 조건 통과 + 75점 이상이어야 잠정 성공입니다. 테트리스가 85점이어도 필수 Hold 동작이 실패하면 작업 실패입니다. 필수 조건을 아직 확인하지 못했다면 성공 여부도 미확정입니다. 75점은 파일럿용 기준이지 통계적으로 검증된 절대 경계가 아닙니다.

미확인은 0점이 아닙니다. 예를 들어 70점 배점의 기준까지만 검사해 55점을 얻었다면 “확인된 55 / 70, 전체 미채점”으로 남깁니다. 이를 78.57 / 100으로 확대하지 않습니다. 실제 실패를 확인한 경우에는 해당 기준에 0점 또는 부분 점수를 줄 수 있습니다.

04. 18개를 더하면 1,800점 아닌가요?

각 과제는 100점이지만 그대로 모두 더하지 않습니다. 먼저 분야 안의 과제 점수를 평균내고, 그 평균에 분야 가중치를 곱합니다. 아래 6개 비중은 합계 100%이며 과제는 중복 배정하지 않습니다.

분야과제 수분야 비중과제 1개가 종합에서 차지하는 비중
코딩·알고리즘3개25%8.33% (반올림)
도구·하네스4개20%5.00%
웹·게임3개20%6.67% (반올림)
글쓰기·요약3개15%5.00%
리서치2개10%5.00%
지식·추론3개10%3.33% (반올림)
종합 = 코딩 평균 × 0.25 + 도구 평균 × 0.20
     + 웹·게임 평균 × 0.20 + 글쓰기 평균 × 0.15
     + 리서치 평균 × 0.10 + 지식·추론 평균 × 0.10

예시 분야 평균: 80, 90, 70, 85, 75, 95
종합 = 20 + 18 + 14 + 12.75 + 7.5 + 9.5 = 81.75점

이 역시 계산용 예시입니다. 실제 집계에서는 중간 비중을 표시용 소수로 반올림해 계산하지 않습니다. 하나라도 미채점이면 그 분야와 전체 점수는 미확정(null)입니다. 남은 분야끼리 비중을 나누지 않습니다.

이전의 “14개 + 추가 4개”는 출제·응시 이력입니다. 현재 집계에서는 ALG-01이 코딩에, 국어·수학·과학이 지식·추론에 들어갑니다. 추가 보너스 점수가 아니므로 100%를 넘지 않습니다.

05. 누가 채점하고 무엇을 남기나요?

  1. 응시 AI가 답안을 제출합니다.

    현재 앱에서 과제를 풀고 outputs/와 RESULT.md에 결과·검증·관측 시간을 남깁니다. 자기 점수는 만들지 않습니다.

  2. 별도로 요청받은 평가 AI가 준비합니다.

    문제 버전·입력·산출물을 확인하고 원본 해시를 보존합니다. 평가 폴더를 새로 만들며 제출 코드를 먼저 검토합니다.

  3. 객관 검사와 근거 검토를 수행합니다.

    알고리즘/정답 검사를 실행하고, 나머지 기능·글·리서치를 요구별로 확인합니다. 각 등급에 이유와 파일 근거를 붙이고 필수 조건을 통과·실패·미확인으로 기록합니다.

  4. 검증된 평가 양식을 합산합니다.

    finish가 배점·근거 경로·원본 변경 여부를 검사해 evaluation.json을 만듭니다. 프로그램이 품질 점수를 알아서 판단하거나 다른 모델을 호출하는 것은 아닙니다.

“독립 평가”는 응시자의 자기 보고를 그대로 점수로 쓰지 않는다는 뜻입니다. 평가 모델이 반드시 다른 계열이어야 한다는 뜻은 아니지만, 평가자·설정이 달라지면 같은 조건의 점수로 취급할 수 없습니다. AI 평가에는 판단 편차가 있으므로 중요한 사례는 사람의 대조 검토가 유용합니다.

평가 요청과 실제 명령 예시

일반적으로 점수 측정 프롬프트에 모델/세션을 넣어 전달하면 됩니다. 평가자는 평가 절차를 읽습니다. 아래 명령은 평가자가 실행하는 예시이며, MODEL/SESSION/REVIEW_ID는 실제 값으로 바꿉니다. 응시자는 평가 자료를 읽거나 실행하지 않습니다.

python3 -B leneu-benchmark/scripts/review_report.py prepare \
  --run MODEL/SESSION \
  --out reports/MODEL/SESSION/REVIEW_ID

# 평가 AI가 assessment.json에 근거와 등급·필수 조건 판정을 기록

python3 -B leneu-benchmark/scripts/review_report.py finish \
  --review reports/MODEL/SESSION/REVIEW_ID

통합 점수 필드는 totals.overall.weighted_score입니다. 같은 평가 폴더를 덮어쓰지 않으며 재평가는 새 REVIEW_ID로 진행합니다. 블로그 발행이나 웹 카탈로그 갱신은 이 명령에 자동으로 포함되지 않습니다.

06. 빨리 끝내면 점수가 더 높나요?

아닙니다. 시간·토큰·비용은 품질 점수에 더하지 않습니다. 같은 품질을 얻는 데 필요한 자원과 사용 경험을 따로 비교하기 위한 기록입니다.

기록올바른 해석
과제 경과 시간자료 읽기·추론·도구 사용·작성·검증을 포함한 실제 관측 구간. 응시자가 기록했으면 agent-observed로 표시합니다.
사용자 대기실제 대기 시작/종료가 기록됐을 때만 구분합니다. 대기 구간을 알 수 없으면 전체 시간에서 임의로 빼지 않습니다.
첫 토큰 시간요청부터 최초 본문 토큰까지의 시간. 스트리밍 이벤트가 없으면 역산하지 않습니다.
출력 속도대응하는 출력 토큰과 본문 스트리밍 구간으로 계산합니다. 전체 작업 시간으로 나눈 값은 모델의 생성 속도가 아닙니다.
토큰·비용플랫폼이 제공한 값에 출처·범위를 붙입니다. 미노출은 null/not_exposed이며 0이 아닙니다. 추론·캐시 토큰 중복 집계를 피합니다.

중간에 앱이 멈추거나 사용자가 나중에 재개했다면, 그 공백을 모델이 계속 추론한 시간으로 단정할 수 없습니다. 기록이 없으면 과거 시간을 정확히 복원할 수 없습니다.

07. 버전과 비교의 한계

문제가 바뀌면 같은 이름이어도 다른 시험입니다

WRITE-01·WRITE-02·THINK-01은 기존 llama.cpp 자료에서 실무 글쓰기 자료로 교체했습니다. 기존 답안은 당시 조건으로, writing-v2.1 답안은 새 조건으로 평가합니다. WRITE-02의 제한시간도 8분에서 12분으로 바뀌었으므로 시간까지 같은 시험처럼 비교하면 안 됩니다.

세 과제를 재응시할 때는 같은 세션의 outputs/<ID>/ 아래에 새 답안을 두고, 이전 파일과 메타데이터는 .history/에 보관합니다. 나머지 15개는 유지합니다. 새 답안에 옛 점수를 붙이지 않고 별도 재채점을 진행합니다.

한 번의 결과는 모델의 절대 능력이 아닙니다

모델·추론 설정·앱·도구·문제 버전·고정 입력·연속/독립 세션·평가자 차이가 결과에 영향을 줍니다. 공통 프롬프트가 있다고 실행 환경까지 동일한 것은 아닙니다. 5개 모델을 한 번씩 실행한 기록은 같은 모델을 5회 반복한 실험이 아닙니다.

가중치는 Leneu가 중요하게 보는 작업 비중입니다. 보편적인 지능 척도나 다른 벤치마크의 점수와 동등한 단위가 아닙니다. 근소한 차이만으로 순위를 확정하기보다 실패 사례·원본·평가 근거를 함께 보세요.

기준 문서와 구현

이 페이지는 공개 설명서입니다. 실제 평가는 답안의 문제 버전과 아래 기준을 확인합니다. 집계 규칙은 v0.4가 과거 14+4 분리 집계보다 우선합니다.
