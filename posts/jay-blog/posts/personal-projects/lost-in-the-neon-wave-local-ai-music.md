처음부터 앨범을 만들 계획은 없었다. 늦은 밤의 젖은 아스팔트와 빨간 신호등, 편의점 불빛 사이를 계속 걷는 사람을 떠올리며 짧은 시티팝 훅 하나를 만들어보고 싶었다. 빠르고 밝은 리듬인데 가사는 미래가 보이지 않는 사람의 이야기라면 재미있겠다고 생각했다.

이번 실험의 결과물은 **Lost in the Neon Wave**라는 약 2분 길이의 리릭 비디오다. 자연스럽게 걷는 캐릭터가 나오는 애니메이션 MV까지 만들지는 못했지만, 로컬 음악 생성 모델과 이미지·자막 편집 도구를 조합해 한 곡을 끝까지 완성했다.

## 장르 이름만으로는 원하는 곡을 만들 수 없었다

처음 입력한 방향은 다음과 같았다.

```text
Modern Japanese City Pop, Fast-tempo Future Funk,
Upbeat Groovy Slap Bass, Talk-singing,
Deadpan laid-back female vocals, Staccato catchy hook,
Crisp drum snare, Neon urban nostalgia, 126 BPM
```

시티팝, 퓨처 펑크, 여성 보컬, 126 BPM처럼 조건을 구체적으로 적었지만 결과가 항상 이 설명을 따르지는 않았다. 시티팝을 요청했는데 일반 팝이나 소울에 가까운 곡이 나오기도 했고, 무심한 여성 보컬을 원했는데 감정이 과하거나 남성처럼 들리는 보컬이 나오기도 했다.

생성형 음악 모델은 편곡 프로그램처럼 체크리스트를 순서대로 실행하지 않았다. BPM·악기·보컬 성별·창법은 강제 옵션이라기보다 생성 방향에 가까웠다. 그래서 장르 이름을 더 많이 나열하기보다 원하지 않는 결과를 같이 적는 쪽으로 프롬프트를 바꿨다.

```text
dry female vocal
talk-singing
restrained delivery
short staccato phrases
no soulful belting
no gospel phrasing
no EDM drop
no cinematic ballad
```

이 실험에서 프롬프트는 완성품을 만드는 명령문이라기보다 후보를 좁히는 탐색 도구에 가까웠다.

## MiniMax Music 3와 ACE-Step 1.5를 서로 다른 단계에 배치했다

처음에는 하나의 모델로 짧은 훅부터 최종 곡까지 만들 수 있을 것이라고 생각했다. 실제 결과를 확인하고 나서는 두 모델의 역할을 분리하는 편이 정확했다.

| 단계 | 사용한 도구 | 이번 작업에서 맡긴 일 |
|---|---|---|
| 스타일 탐색 | MiniMax Music 3 | 여러 프롬프트로 15초 훅을 만들고 방향을 찾기 |
| 곡 완성 | ACE-Step 1.5 | 가사와 분위기를 바탕으로 처음부터 끝까지 2분 곡 생성 |
| 후반 작업 | Whisper·FFmpeg·이미지 편집 도구 | 가사 타이밍 분석, 장면 전환, 자막 합성, 영상 출력 |

MiniMax Music 3에서 마음에 가까운 15초 코러스가 나왔지만, 그 파일을 그대로 늘려 최종곡으로 사용한 것은 아니다. 사람이 듣고 리듬과 분위기를 판단하는 기준으로 삼았고, 최종 멜로디·반주·보컬은 ACE-Step 1.5에서 별도로 생성했다.

이 구분은 중요하다. 두 모델이 하나의 오디오 파이프라인으로 연결된 것처럼 쓰면 실제 제작 과정을 잘못 설명하게 된다. 이번 작업은 **MiniMax Music 3로 방향을 찾고 ACE-Step 1.5로 한 곡을 새로 완성한 과정**이었다.

참고한 공식 자료는 다음과 같다.

- [MiniMax Music 3 공식 소개](https://www.minimax.io/blog/minimax-music-3-0-next-generation-open-weights-production-ready-versatile-music-model)
- [MiniMax Music 3 공식 데모](https://minimax-ai.github.io/music3-demo/)
- [ACE-Step 1.5 공식 GitHub](https://github.com/ace-step/ACE-Step-1.5)
- [ACE-Step 1.5 공식 가이드](https://ace-step.github.io/ACE-Step-1.5/en/)

## M1 Max에서는 모델을 바로 연결할 수 없었다

사용한 환경은 Apple Silicon M1 Max와 통합 메모리 64GB를 갖춘 Mac이다. 평소에는 oMLX를 사용했기 때문에 Music 3도 oMLX에서 내려받으면 바로 실행할 수 있을 것으로 생각했다.

하지만 oMLX는 일반 LLM·VLM을 OpenAI 호환 API 형태로 실행하는 도구에 가깝고, Music 3는 음악 토큰과 RVQ, Flow Matching, 오디오 디코더를 포함한 별도의 생성 경로가 필요했다. 결국 Music 3 생성에는 `mlx-audio`를 사용했다.

```text
oMLX
└─ 일반 LLM·VLM 실행

mlx-audio
└─ MiniMax Music 3 음악 생성
```

MiniMax Music 3로 15초 훅을 탐색할 때 사용한 구성은 다음과 같다. 이 표는 최종 2분 음원을 만든 구성과는 구분해서 봐야 한다.

| 항목 | 선택 |
|---|---|
| 실행 환경 | Apple Silicon M1 Max, 64GB |
| 실행 도구 | mlx-audio |
| Music 3 모델 | `mlx-community/MiniMax-Music3-mxfp8` |
| 모델 용량 | 약 13GB |
| 생성 방식 | 텍스트 설명과 가사 입력 |

사용한 MXFP8 모델은 MLX 커뮤니티에서 변환한 버전으로, 모델 카드 기준 디스크 용량은 약 13GB였다. 같은 변환 계열의 BF16 버전은 약 27GB로 안내되어 있다. [MLX Music 3 모델 카드](https://huggingface.co/mlx-community/MiniMax-Music3-mxfp8)

다만 이 숫자를 LLM 하나의 크기처럼 읽으면 안 된다. 음악 생성 모델은 언어 모델과 음악 생성부, VAE와 디코더가 함께 동작하므로 디스크 용량만으로 품질이나 실행 난이도를 판단할 수 없다.

최종 2분 음원은 이 Music 3 구성에서 만든 것이 아니라, 별도로 설치한 ACE-Step 1.5에서 생성했다.

| 항목 | 최종 구성 |
|---|---|
| 실행 환경 | Apple Silicon M1 Max, 64GB |
| 최종 생성 도구 | ACE-Step 1.5 |
| 보조 작업 | 가사 정리, 음성 인식 기반 싱크 분석, FFmpeg 영상 편집 |
| 세부 양자화 조합 | 실행 기록에 정확히 남아 있지 않아 표기하지 않음 |

ACE-Step 1.5도 마찬가지다. `0.6B`, `1.7B`, `4B`는 주로 곡을 계획하고 조건을 해석하는 LM 구성의 크기이며, 실제 오디오 생성부가 별도로 붙는다.

## 15초 훅을 먼저 만들고 마음에 드는 방향만 남겼다

처음부터 2분짜리 곡을 생성하는 대신 코러스 일부만 넣은 15초 테스트를 반복했다. 긴 결과가 마음에 들지 않으면 생성 시간뿐 아니라 청취와 프롬프트 수정 시간까지 한꺼번에 버려지기 때문이다.

여러 후보를 비교하면서 발견한 것은 “시티팝”이라는 장르보다 짧은 리듬과 보컬의 태도가 더 중요하다는 점이었다. 최종적으로 기준점이 된 문장은 다음과 같았다.

> Lost in the neon wave / No future in sight / Green light blinking / But I'm frozen tonight

처음에는 한국어 가사로 시작했다. `도망치고 싶어 나아가고 싶어`, `멈추고 싶어 걷고 싶어`처럼 주제를 직접 표현했지만, 빠른 템포에서 음절이 뭉치고 훅이 길어졌다. 이후 영어의 짧은 문장과 내부 라임을 사용해 발음과 반복성을 우선했다.

```text
No map, no sign / Neon on my mind
Heavy shoes / City blues
Cold night / Red light
No reply / No clear sky
Run away / Move ahead
Break down / Hold on / Shine on
```

## 짧은 샘플을 같은 프롬프트로 다시 생성하는 것으로는 부족했다

15초 훅이 괜찮았으니 같은 설명을 넣어 2분으로 만들면 될 것 같았다. 그러나 텍스트 프롬프트를 다시 넣는 것은 기존 오디오의 다음 구간을 계산하는 일이 아니었다. 비슷한 조건의 새 곡을 다시 생성할 뿐이었다.

짧은 결과를 여러 개 이어 붙이는 방식도 한계가 분명했다.

- 구간마다 보컬의 성별과 음색이 달라졌다.
- 조성·템포·공간감이 이어지지 않아 메들리처럼 들렸다.
- 30~40초 부근에서 음악이 갑자기 끊기거나 구조가 무너졌다.
- 같은 프롬프트라도 시드와 시도에 따라 멜로디와 편곡이 크게 달라졌다.

그래서 최종곡은 ACE-Step 1.5에서 처음부터 전체 구조를 생성했다. 첫 결과가 정답은 아니었지만, 여러 후보 중 보컬과 전체 분위기가 가장 자연스러운 버전을 선택했다. 최종곡은 Music 3의 15초 오디오를 이어 붙인 파일이 아니다.

## 모델 성능은 순수 추론시간보다 한 곡을 고르는 전체 반복시간으로 기록했다

이번 실행에서는 생성 명령 앞에 `time`을 붙이지 않아 순수 추론시간을 분리해 측정하지 못했다. 대신 파일 저장 시각과 실제 작업 흐름을 기준으로 체감 시간을 기록했다.

| 작업 | 이번 기록에서 확인한 시간 | 의미 |
|---|---:|---|
| 15초 테스트 1회 | 약 15분 | 생성·청취·프롬프트 수정까지 포함한 반복 간격 |
| 15초 후보 비교 | 약 30~60분 | 여러 후보를 만들고 훅을 선택한 시간 |
| ACE-Step 2분 후보 반복 | 후보 하나당 약 30~50분 | 생성·가사 수정·보컬 확인·재시도를 포함 |
| 최종 2분 버전 선택 | 대략 1시간 전후 | 후보 생성과 비교를 합친 체감 작업시간 |

따라서 이 표를 모델 간 벤치마크로 읽으면 안 된다. M1 Max 64GB에서 한 곡을 완성하기 위해 실제로 얼마나 기다리고 판단했는지를 남긴 작업 기록이다. 다음 실험에서는 생성 명령에 `/usr/bin/time -p`를 붙여 순수 생성시간과 전체 작업시간을 분리할 예정이다.

## 완전한 애니메이션 MV 대신 리릭 비디오로 범위를 줄였다

처음에는 캐릭터가 네온 도시를 자연스럽게 걷는 애니메이션 MV를 만들고 싶었다. 그러나 장면마다 이미지-투-비디오 생성을 반복하면 2분 분량에 필요한 클립 수와 재생성 비용이 빠르게 늘어난다. 캐릭터의 옷과 체형, 얼굴 노출 여부, 색감과 움직임을 장면마다 유지하는 문제도 남았다.

그래서 이번 목표를 다음처럼 바꿨다.

> 완전한 애니메이션 MV 대신, 곡의 분위기에 맞는 일러스트 위에 가사를 정확한 타이밍으로 보여주는 리릭 비디오를 만든다.

영상의 시각적 기준은 비에 젖은 도시, 파란색과 자홍색 네온, 빨간 신호등, 뒷모습만 보이는 여성 캐릭터였다. 이 기준으로 다음 여덟 장면을 만들었다.

```text
01. 빨간 신호등 앞을 걷는 장면
02. 넓은 교차로
03. 네온이 가득한 도심
04. 편의점과 골목
05. 자판기가 있는 밤거리
06. 편의점 유리와 반사 장면
07. 원형 교차로를 내려다본 장면
08. 새벽빛이 보이기 시작한 도로
```

각 장면을 기계적으로 15초마다 바꾸지 않고 Intro, Verse, Pre-Chorus, Chorus, Bridge와 같은 곡의 흐름에 맞춰 전환 시간을 나눴다. 정지 이미지 여덟 장만 사용했지만, 음악과 자막의 타이밍을 맞추니 단순한 이미지 슬라이드보다 곡의 구조가 잘 보였다.

## Whisper와 FFmpeg로 가사 싱크를 다시 맞췄다

처음에는 눈대중으로 자막 시간을 정해 5초와 10초짜리 테스트 영상을 만들었다. 하지만 실제 보컬과 자막이 어긋나면서 영상이 어색해졌다.

최종 음원을 음성 인식 모델로 분석해 문장별 시작·종료 시간을 추출하고, 자동 인식 결과를 원래 가사와 대조해 직접 교정했다.

```text
00:00.65 - 00:03.14  No map, no sign
00:03.78 - 00:07.20  Neon on my mind
00:08.28 - 00:10.42  Heavy shoes, city blues
...
01:39.94 - 01:41.16  Shine on
```

약 101초 이후는 보컬이 끝난 연주 구간이어서 가사를 억지로 추가하지 않았다. 가사는 화면 왼쪽과 하단에 배치하는 시도도 했지만 장면마다 위치가 달라져 불안정해 보였다. 최종적으로는 화면 중앙선을 기준으로 고정하고, `KCC은영체`와 밝은 아이보리색 글자, 어두운 외곽선을 적용했다. 영상에 사용한 폰트와 효과도 특정 서비스의 자동 템플릿에 맡기기보다 편집 과정에서 직접 정했다.

그 결과물은 본격적인 애니메이션 MV라기보다 여덟 장의 일러스트와 동기화된 영어 가사를 사용하는 리릭 비디오에 가깝다. 처음 목표보다 범위는 작아졌지만, 현재 로컬 환경에서 완성도와 작업량 사이의 현실적인 타협점이었다.

## 썸네일은 첫 장면의 여백을 활용해 다시 만들었다

최종 썸네일은 첫 번째 도시 일러스트를 바탕으로 만들었다. 화면 오른쪽에는 캐릭터와 빨간 신호등을 두고, 왼쪽의 어두운 공간에 제목을 배치했다. 처음에는 작은 YouTube 미리보기에서 제목이 가장자리에 가까워 보여 제목 블록을 조금 오른쪽으로 옮겼다.

이 글의 첫 이미지가 바로 그 최종 썸네일이다. 곡의 결과물과 글의 대표 이미지가 따로 놀지 않도록, 제작 과정에서 실제로 사용한 이미지를 그대로 연결했다.

완성한 리릭 비디오는 [YouTube에서 볼 수 있다](https://youtu.be/xuWCNbn3vk0). 처음에는 일부 공개(Unlisted)로 업로드했고, 2026년 8월 25일 공개(Public)로 전환했다. 업로드 시각과 공개 전환 시각은 YouTube Studio에서 별도로 기록했다.

## AI가 만든 음악에서도 사람의 선택은 제작 과정의 대부분을 차지했다

이번 작업을 “프롬프트 한 줄로 노래 한 곡 만들기”라고 설명하면 실제 과정을 놓치게 된다.

- 곡의 주제와 장르적 방향을 정했다.
- 긴 한국어 가사를 짧은 영어 훅으로 다시 썼다.
- 수십 개의 생성 결과를 듣고 버렸다.
- Music 3와 ACE-Step의 역할을 나눴다.
- 최종 보컬과 곡 전체 구조를 선택했다.
- 음성 인식 결과를 원래 가사와 대조해 교정했다.
- 장면 전환과 자막 위치를 조정했다.
- 작은 썸네일에서 읽히는 제목 위치를 다시 잡았다.

AI가 멜로디·화성·반주·생성 보컬을 만들었지만, 무엇을 남기고 버릴지 결정하는 일과 최종 영상으로 묶는 일은 별도의 작업이었다. 이번 실험에서 모델의 성능은 생성 버튼을 누른 순간보다, 실패한 결과를 얼마나 빨리 버리고 다음 가설을 세울 수 있는지에서 더 크게 체감됐다.

<details>
<summary>AI 음악의 권리를 판단하기 전에 기록해둔 것</summary>

이번 글에서 AI 음악 결과물 전체의 권리를 단정하려는 것은 아니다. 실제 판단은 사용한 도구의 이용약관, 입력한 데이터, 사람이 한 창작·편집의 정도, 공개와 이용 방식에 따라 달라질 수 있다. 그래서 이번 작업에서는 곡 전체를 등록한다고 보기보다, 사람이 직접 창작한 부분이 가장 분명한 영어 가사를 별도 저작물로 등록하는 방안을 검토했다. 다만 최종적으로는 별도의 저작권 등록을 진행하지 않기로 했다.

| 구분 | 이번 작품에서 정리한 내용 |
|---|---|
| 등록 검토 대상 | `Lost in the Neon Wave` 영어 가사 |
| 등록 유형 | 한국저작권위원회 `어문저작물·가사` |
| 제출 복제물 | 구조 표기를 정리한 영어 가사 PDF |
| 사람의 기여 | 주제, 전체 구성, 후렴구 방향, 가사 수정·배열·최종 확정 |
| AI 산출 비중이 큰 부분 | ACE-Step 1.5가 생성한 멜로디·화성·반주·보컬 |
| 최종 결정 | 별도 저작권 등록은 진행하지 않음 |

한국저작권위원회 등록은 저작자·창작연월일·공표연월일 등을 등록부에 공시하고, 등록된 내용에 일정한 추정력을 부여하는 제도다. 이것이 AI가 생성한 멜로디·반주·보컬 전체에 대한 인간 저작권을 자동으로 확정해주는 것은 아니다. [저작권 등록 안내](https://www.copyright.or.kr/business/registration/index.do)

등록을 검토하면서 공표 여부는 실제 신청 시점에 맞춰 적어야 한다는 점도 확인했다. 아직 공개하지 않았다면 `아니오`, 먼저 YouTube에 공개했다면 실제 최초 공개일을 기준으로 `예`를 선택하는 식이다. AI 사용 기재에는 다음처럼 실제 작업을 과장하지 않는 문장을 사용할 수 있다.

> 영어 가사의 초안 작성 및 일부 표현 정리에 생성형 AI를 보조적으로 활용하였습니다. 작품의 주제, 전체 구성, 반복되는 후렴구의 방향, 최종 문구의 선택·수정·배열 및 최종 확정은 본인이 직접 수행하였습니다. 음악과 보컬은 ACE-Step 1.5를 활용하여 생성하였습니다.

등록 대신 최종 음원과 가사, 프롬프트, 생성 로그, 수정 이력을 압축하고 SHA-256 해시를 남겼다. 여기에 YouTube 업로드·공개 전환 기록과 공개 화면을 함께 보관했다. YouTube 공개는 등록을 대신하지 않지만, 특정 시점에 어떤 가사와 음원을 공개했는지 보여주는 보조 자료가 될 수 있다. KOMCA의 신탁계약·작품신고는 한국저작권위원회의 저작권 등록과 목적이 다른 별도 절차이므로, 이번 기록에서는 두 절차를 섞지 않았다. [KOMCA 신탁 관련 서식](https://www.komca.or.kr/dat2/dat_contents_0101.jsp)

AI 활용 저작물의 등록 기준은 한국저작권위원회의 [생성형 인공지능 활용 저작물의 저작권 등록 안내서](https://www.copyright.or.kr/information-materials/publication/research-report/view.do?brdctsno=54253)도 함께 참고했다. 실제 등록 가능성과 제출 내용은 신청 시점의 공식 안내와 상담 결과를 기준으로 확인해야 하며, 이 글은 법률 자문이 아니다.

## 다음에는 생성시간을 정확히 재고 외부 영상 AI로 MV를 확장할 예정이다

이번 실험의 가장 큰 결론은 로컬 AI 음악 제작이 “모델 하나를 실행하면 끝나는 작업”이 아니라는 점이다. MiniMax Music 3는 스타일과 훅을 탐색하는 데 유용했고, ACE-Step 1.5는 전체 곡을 완성하는 단계에 더 잘 맞았다. 두 도구를 억지로 하나의 모델처럼 설명하는 것보다 각 단계에서 무엇을 검증했는지 나누는 편이 정확했다.

먼저 다음 생성부터는 명령 앞에 `/usr/bin/time -p`를 붙이겠다. 모델을 불러오는 시간과 순수 추론시간, 후처리 시간, 후보를 듣고 최종 버전을 고르는 시간을 따로 기록해 실제 모델 성능과 작업 흐름을 분리해서 비교할 예정이다.

영상은 현재 로컬 환경만으로 자연스러운 2분짜리 애니메이션 MV까지 만들기에는 부담이 크다고 판단했다. M1 Max 64GB에서 음악 생성과 정지 이미지 기반 리릭 비디오는 충분했지만, 여러 장면을 이미지-투-비디오로 생성하고 캐릭터의 모습과 색감, 움직임을 유지하려면 생성 횟수와 렌더 시간이 크게 늘어난다.

그래서 다음 MV는 역할을 나눌 생각이다.

- 로컬 환경: 음악 생성, 가사 정리, 콘티와 기준 이미지 제작
- 외부 AI 영상 도구: 장면에 움직임을 넣고 짧은 클립 생성
- 로컬 편집: 클립 연결, 가사 싱크, 최종 음원과 영상 출력

이번에 만든 여덟 장의 일러스트는 버리는 결과물이 아니라 다음 영상 작업의 콘티와 스타일 기준으로 남긴다. 다음 실험의 목표는 로컬 모델의 생성시간을 정확히 측정하는 것과, 외부 영상 AI 도구를 활용해 이 정지 이미지 기반 리릭 비디오를 실제 MV에 가깝게 확장하는 것이다.
