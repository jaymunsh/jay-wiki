> **업데이트: 2026년 8월 29일** — 8월 26일 Z.ai가 Ox Alpha를 출시 전 익명 테스트에 사용한 `GLM-5.3-Flash`라고 공식 공개했다. 무료 제공은 영구적인 무료 요금제가 아니라 한시적인 프리뷰였고, OpenCode가 8월 20일부터 “다음 일주일”이라고 안내한 흐름은 8월 27일 전후 종료로 보는 것이 현재 가장 정확하다.

Ox Alpha라는 이름은 8월 20일 공개된 **GLM-5.3-Flash의 출시 전 테스트명**이었다. Z.ai는 공식 글에서 실제 트래픽을 받기 위해 이 모델을 `ox-alpha`라는 익명 이름으로 OpenCode와 OpenRouter에 먼저 노출했다고 밝혔다. 이후 Z.ai가 정식 모델명과 구조·벤치마크를 공개하면서, 한동안 따로 보이던 `stealth/ox-alpha`, `x-preview-f-free`, `ox-alpha-free`가 하나의 출시 전 경로였다는 퍼즐이 맞춰졌다.

이제는 제작자가 완전히 미상인 모델이라고 부를 수 없다. 다만 **Ox Alpha라는 프리뷰 엔드포인트의 데이터 처리와 정식 GLM-5.3-Flash의 정책을 같은 것으로 섞어 읽으면 안 된다.** OpenRouter의 현재 Ox Alpha 페이지는 제공자가 프롬프트와 완료 결과를 보존하지만 학습에는 사용하지 않는다고 안내하고, OpenCode Zen은 별도의 zero-retention 정책을 설명한다.

그래서 이 글은 “무료 모델” 소개에서 멈추지 않고, 정체 공개 전후의 성능 자료를 분리해 읽는다. 마지막에는 무료 프리뷰가 끝난 뒤 어떤 모델 ID와 실행 경로를 사용해야 하는지, 현재 프로젝트 점검에 적용할 때의 경계를 덧붙인다.

## Ox Alpha의 정체: Z.ai GLM-5.3-Flash

8월 26일 [Z.ai 공식 발표](https://z.ai/blog/glm-5.3-flash)의 문장은 명확하다. **GLM-5.3-Flash를 정식 출시하기 전에 `ox-alpha`라는 이름으로 OpenCode와 OpenRouter에서 익명 테스트했다**는 것이다. [OpenRouter 모델 페이지](https://openrouter.ai/stealth/ox-alpha)도 현재 FAQ에서 Ox Alpha가 ZAI GLM-5.3-Flash로 공개됐다고 표시하고 있다.

따라서 Ox Alpha는 별도의 오픈 웨이트 모델명이 아니라 **GLM-5.3-Flash의 출시 전 서비스 별칭**으로 이해하는 것이 맞다. 지금 내려받아 실행할 수 있는 것은 [zai-org/GLM-5.3-Flash](https://huggingface.co/zai-org/GLM-5.3-Flash) 가중치이며, 과거의 무료 Ox Alpha 엔드포인트를 그대로 복원하는 것은 아니다.

정식 공개 후 확인되는 GLM-5.3-Flash의 사양은 이렇다.

| 항목 | 확인된 값 |
|---|---|
| 정식 모델명 | `GLM-5.3-Flash` |
| 제작자 | Z.ai (Zhipu AI) |
| 출시 전 별칭 | `stealth/ox-alpha` · `x-preview-f-free` |
| 전체 / 활성 파라미터 | 320B / 18B |
| 컨텍스트 | 1,048,576 토큰(1M) |
| 최대 출력 | 131,072 토큰 |
| 입력 / 출력 | 텍스트·이미지·비디오 / 텍스트 |
| 구조 | 희소 어텐션 + 선형 어텐션 하이브리드, 네이티브 멀티모달 |
| 추론 | 강제. 기본 `max`, `high`·`low` 지원 |
| 도구·구조화 출력 | 지원 |
| 오픈 웨이트 | Hugging Face 모델 저장소 공개 |

파라미터 수와 구조는 [Z.ai 공식 발표](https://z.ai/blog/glm-5.3-flash), 현재 모델 ID와 가격은 [OpenRouter 모델 API](https://openrouter.ai/api/v1/models)와 [모델 페이지](https://openrouter.ai/stealth/ox-alpha)를 기준으로 했다. 가격은 제공자와 시점에 따라 바뀔 수 있으며, `stealth/ox-alpha`의 과거 무료 표기와 정식 `z-ai/glm-5.3-flash`의 현재 유료 표기를 혼동하면 안 된다.

## 1M 컨텍스트보다 추론이 항상 켜진다는 점이 더 중요하다

100만 토큰은 눈에 잘 띄는 숫자지만, 실제 사용감은 그 숫자 하나로 결정되지 않는다. Ox Alpha는 추론이 강제되어 있고 기본 reasoning effort가 `max`다. 짧은 질문에도 답변 전에 내부 추론 토큰을 사용하므로 첫 응답이 느리거나, 단순한 작업에도 출력 비용이 커지는 것처럼 느껴질 수 있다.

OpenRouter의 API 메타데이터에는 최대 출력이 131,072토큰으로 표시된다. 이것은 한 번의 응답이 그만큼 길어질 수 있다는 뜻이지, 모든 요청이 1M 컨텍스트와 131K 출력을 실제로 안정적으로 사용할 수 있다는 뜻은 아니다. 제공자의 순간적인 용량, 라우팅 경로, OpenCode가 요청을 구성하는 방식이 모두 영향을 준다.

코드베이스 전체를 넣는 실험을 한다면 다음을 따로 재야 한다.

| 따로 볼 것 | 왜 필요한가 |
|---|---|
| 첫 토큰까지의 시간 | 강제 추론과 큐 대기 시간이 섞인다 |
| 실제 생성 속도 | 긴 답변을 받을 때의 체감이 달라진다 |
| 입력 토큰 수 | 컨텍스트 창에 들어갔는지 확인해야 한다 |
| 추론 토큰 수 | 답변 길이만으로 비용·지연을 판단하면 안 된다 |
| 도구 호출 성공 여부 | 채팅 답변과 에이전트 작업은 다른 평가다 |

즉 "1M이라서 저장소를 전부 넣으면 된다"가 아니라, **넣을 수 있는 상한이 넓으니 어떤 구간에서 실제로 이득이 나는지 측정할 수 있다**에 가깝다.

## 공개된 성능 수치를 비교 가능한 것부터 다시 읽어보자

이제는 정식 모델명이 공개됐으므로, **출시 전 Ox Alpha 테스트 결과**와 **출시 후 GLM-5.3-Flash 이름으로 발표된 결과**를 분리해서 읽어야 한다. 같은 모델에서 나온 수치라도 평가 하니스·추론 설정·시점이 다르면 직접적인 순위표가 되지 않는다.

### 정식 공개 후 GLM-5.3-Flash 공식 결과

[Z.ai 공식 발표](https://z.ai/blog/glm-5.3-flash)는 GLM-5.3-Flash를 GLM-5.2, Claude Opus 4.8 등과 비교한 결과를 공개했다. 아래는 코딩·에이전트 작업에서 핵심적인 항목만 옮긴 것이다. Z.ai가 직접 수행한 평가이므로, 독립 재현 결과가 아니라 **제작자 공개 수치**로 읽어야 한다.

| 평가 | GLM-5.3-Flash | GLM-5.2 | Claude Opus 4.8 | Flash - GLM-5.2 |
|---|---:|---:|---:|---:|
| Terminal Bench 2.1 | **84.3** | 81.0 | 85.0 | +3.3 |
| DeepSWE v1.1 | **63.4** | 46.2 | 58.0 | +17.2 |
| Toolathlon Verified | **78.4** | 59.9 | 76.2 | +18.5 |
| AutomationBench v1.0.6 | **48.8** | 26.2 | 41.0 | +22.6 |
| HLE with Tools | 55.3 | 54.7 | **57.9** | +0.6 |

이 결과는 Ox Alpha가 단순히 “무료라서 써 볼 만한 모델”을 넘어, 정식 공개된 GLM-5.3-Flash의 코딩·도구 사용 성능을 보여 주는 자료가 생겼다는 뜻이다. 다만 평가 조건은 각주와 공식 글의 방법론을 확인해야 하며, 위 수치를 앞서 소개한 10개 저장소 실험이나 LiveCodeBench 단일 시도와 합산해서 평균 내면 안 된다.

Z.ai는 구조 측면에서 GLM-5.3 대비 어텐션 연산량 약 3.0배 감소, KV Cache 크기 약 4.4배 감소를 주장한다. 320B 전체 중 18B만 활성화하는 MoE 구조와 선형·희소 어텐션의 조합이 1M 컨텍스트와 에이전트 작업을 겨냥한 설계다. 이것은 “1M 컨텍스트를 지원한다”는 표기보다, 긴 문맥을 유지하면서 메모리·연산 부담을 줄이려는 구조적 이유를 설명해 준다.

### 출시 전 Ox Alpha의 10개 실무 저장소 작업 비교

[Ox Alpha 벤치마크 상세 페이지](https://oxalpha.com/ox-alpha-benchmarks)의 10개 작업 결과다. 비교 모델은 과제마다 네 번 시도했고, Ox Alpha는 과제별 한 번의 pass/fail로 기록되어 조건이 완전히 같지는 않다.

| 모델 | 평균 통과율 | Ox Alpha 대비 | 측정 방식 |
|---|---:|---:|---|
| **Ox Alpha** | **80% (8/10)** | 기준 | 10개 과제 pass/fail |
| Fable 5 | 65% | -15%p | 과제당 4회 시도 |
| GLM-5.3 | 62% | -18%p | 과제당 4회 시도 |
| Grok 4.6 | 62% | -18%p | 과제당 4회 시도 |
| GPT-5.6 Sol | 52% | -28%p | 과제당 4회 시도 |

이 표만 보면 Ox Alpha가 앞서지만, 10개 작업뿐이고 측정 방식도 비대칭이다. “Ox Alpha가 GPT-5.6 Sol보다 28%p 좋다”가 아니라, **이 작은 작업 묶음에서 28%p 높은 결과가 나왔다**고 읽어야 한다.

### 더 큰 DeepSWE 재실행 비교

같은 계열의 평가를 더 큰 표본으로 다시 실행했다는 [커뮤니티 재실행 정리](https://www.ai-primer.com/engineer/stories/ox-alpha-deepswe-retest)에서는 순서가 달라진다. 이 자료는 2차 정리이므로 확정적인 공식 점수로 보기는 어렵다.

| 모델·계열 | 보고된 점수 | Ox Alpha 대비 |
|---|---:|---:|
| Sol·Opus 계열 | 약 71~74% | +8~11%p |
| Fable 5 Medium | 약 65% | +약 2%p |
| **Ox Alpha** | **약 63%** | 기준 |

이 결과가 중요한 이유는 10개 표본의 80%를 그대로 일반화하기 어렵다는 점을 보여주기 때문이다. Ox Alpha의 실무형 성능을 하나의 고정된 점수로 쓰기보다, **작은 샘플에서 80%였지만 더 큰 재실행에서는 약 63%까지 내려온 모델**이라고 표현하는 편이 낫다.

### Kingbench 커스텀 평가 비교

[Kingbench 평가 정리](https://thegeekinsights.com/ox-alpha-ai-explained/)에서는 Ox Alpha가 80점 만점 중 70점을 얻었다. 다만 비공개·비표준 하니스라서 공식 순위표가 아니라 참고용 비교로만 봐야 한다.

| 모델 | 점수 | Ox Alpha 대비 |
|---|---:|---:|
| GLM-5.3 | 91.25% | +3.75%p |
| **Ox Alpha** | **87.5% (70/80)** | 기준 |
| Fable 5 | 약 82.5% | -약 5%p |
| Qwen 3.8 Max | 약 81.25% | -약 6.25%p |
| Opus 4.8 | 약 80% | -약 7.5%p |

반대로 [LiveCodeBench v6 단일 시도](https://www.reddit.com/r/LLMDevs/comments/1vv4h4mb/ox_alpha_livecodebench_v6/)에서는 175문제 중 49개, **Pass@1 28.0%였다**. 이 시험은 Python을 도구 없이 temperature 0으로 한 번 생성한 raw 코드 정답률이라 위의 저장소·에이전트형 결과와 직접 섞을 수 없다. 출시 전 [OpenRouter 운영 지표](https://openrouter.ai/stealth/ox-alpha)에 표시됐던 P50 24 tok/s·지연 5.47초·Uptime 99.99%도 모델 품질이 아니라 당시 서비스 응답 속도와 가용성의 기록이다.

숫자로 요약하면 출시 전 Ox Alpha 평가에서 **63~87.5% 범위와 raw 코딩 Pass@1 28%가 함께 관찰됐다.** 이 수치는 정식 GLM-5.3-Flash 발표 후 제작자 벤치마크와 평가 목적·조건이 다르므로 하나의 평균 점수로 합치면 안 된다.

## 성능만 놓고 내리는 결론

현재 공개 수치로 판단하면 Ox Alpha의 위치는 다음과 같다.

| 사용 상황 | 판단 | 근거 |
|---|---|---|
| 저장소를 넓게 읽고 여러 단계로 수정하는 에이전트 작업 | **시험해볼 가치가 있다** | 작은 실무형 비교에서 80%, 더 큰 재실행에서 약 63% |
| 짧은 코드 조각을 한 번에 완성하는 작업 | **기대치를 낮춰야 한다** | LiveCodeBench raw Pass@1 28% |
| 빠른 응답이 중요한 작업 | **주의해서 써야 한다** | P50 24 tok/s, 지연 5.47초, 추론 effort 기본값 `max` |
| 운영 장애 비용이 큰 핵심 업무 | **검증 후 제한적으로** | 제작자 공개 수치와 커뮤니티 결과는 있지만, 환경별 재현성과 운영 정책을 별도로 확인해야 함 |

따라서 성능 결론은 “GLM-5.3-Flash가 모든 모델보다 전반적으로 좋다”가 아니다. **정식 공개 후에는 코딩·도구 사용에 대한 제작자 평가가 추가됐고, 출시 전 Ox Alpha 실험에서도 저장소 단위 작업에 강한 신호가 있었지만, 평가 하니스와 환경에 따른 편차까지 사라진 것은 아니다**가 가장 정확하다. 무료 프리뷰가 끝난 지금은 보조 에이전트로 무조건 붙이기보다, 유료 API나 공개 가중치를 사용할 조건에서 내 저장소 작업으로 다시 검증해야 한다.

### 실제로 무엇을 테스트했는가

이 비교는 알고리즘 문제를 새로 풀게 한 표가 아니다. 원문 방법론에 따르면 오픈소스 저장소에서 가져온 10개의 실제 코드 변경 작업을 대상으로 했고, 각 작업은 프로젝트 이름과 변경 요구를 조합한 식별자로 공개되어 있다. 다만 공개 페이지에서 확인할 수 있는 것은 아래 작업명과 모델별 통과 수까지다. 전체 프롬프트, 기준 커밋, 패치 평가 스크립트가 모두 공개된 표준 리더보드로 읽어서는 안 된다.

| 테스트 작업 | 작업명에서 확인되는 대상 |
|---|---|
| `anko-typed-variable-bindings` | Anko의 typed variable bindings |
| `arktype-json-schema-refs` | ArkType의 JSON Schema refs |
| `fastapi-deprecation-headers` | FastAPI의 deprecation headers |
| `helm-unified-manifest-stream` | Helm의 unified manifest stream |
| `igel-persist-feature-schema` | Igel의 persist feature schema |
| `katex-multicolumn-array-spans` | KaTeX의 multicolumn array spans |
| `meriyah-explicit-resource-decl` | Meriyah의 explicit resource declaration |
| `query-persist-restored-state` | query의 persist restored state |
| `scc-bounded-memory-spilling` | SCC의 bounded-memory spilling |
| `vulture-persistent-analysis-cache` | Vulture의 persistent analysis cache |

작업별 결과까지 펼치면 비교의 모양이 조금 달라진다. `4/4`는 비교 모델이 네 번 시도해서 네 번 통과했다는 뜻이고, `✓`와 `✕`는 Ox Alpha의 단일 pass/fail 기록이다.

| 작업 | Fable 5 | GLM-5.3 | GPT-5.6 Sol | Grok 4.6 | Ox Alpha |
|---|---:|---:|---:|---:|:---:|
| `anko` | 4/4 | 4/4 | 2/4 | 1/4 | ✓ |
| `arktype` | 2/4 | 1/4 | 3/4 | 1/4 | ✓ |
| `fastapi` | 4/4 | 3/4 | 3/4 | 4/4 | ✓ |
| `helm` | 4/4 | 4/4 | 4/4 | 4/4 | ✓ |
| `igel` | 3/4 | 3/4 | 0/4 | 4/4 | ✓ |
| `katex` | 2/4 | 4/4 | 3/4 | 4/4 | ✓ |
| `meriyah` | 1/4 | 0/4 | 0/4 | 0/4 | ✓ |
| `query` | 2/4 | 3/4 | 1/4 | 2/4 | ✓ |
| `scc` | 4/4 | 3/4 | 4/4 | 4/4 | ✕ |
| `vulture` | 0/4 | 0/4 | 1/4 | 1/4 | ✕ |

이 표에서 읽을 수 있는 구체적인 장면도 있다. Ox Alpha는 `meriyah` 작업에서 비교 모델들이 최대 1/4에 그친 상황에서도 통과했지만, `scc`에서는 네 비교 모델이 모두 적어도 3/4을 기록한 가운데 실패했다. `vulture`는 대부분의 모델이 어려워한 작업으로, Ox Alpha만의 약점이라고 보기는 어렵다. 결국 8/10이라는 평균보다 **어떤 유형의 저장소 변경에서 강했고 어디서 무너졌는지**가 실제 프로젝트에 적용할 때 더 중요한 정보다.

두 결과는 모순이라기보다 측정 대상이 다르다. 첫 번째는 실무에 가까운 작은 과제 묶음이고, 두 번째는 정해진 코딩 문제를 한 번 생성해 맞혔는지를 보는 시험이다. 에이전트가 파일을 읽고 테스트를 돌리며 여러 번 수정하는 능력과, 도구 없이 한 번에 정답 코드를 내는 능력은 같은 축의 성능이 아니다. 따라서 이 숫자만으로 "Ox Alpha가 최고다" 또는 "코딩에 약하다"고 결론내리기 어렵다.

실제 사용에서 체감되는 성능은 품질 점수 하나보다 다음 항목의 조합에 가깝다.

| 확인할 항목 | 기록할 값 |
|---|---|
| 응답 지연 | 첫 토큰까지의 시간, 전체 완료 시간 |
| 생성 효율 | 입력·출력·추론 토큰 수 |
| 에이전트 작업 | 도구 호출 성공 여부, 재시도 횟수, 테스트 통과 여부 |
| 결과 품질 | 실제 결함을 찾았는지, 제안한 수정이 재현 가능한지 |

특히 Ox Alpha는 기본 reasoning effort가 `max`이고 OpenRouter의 라우팅·무료 엔드포인트 상태에도 영향을 받는다. 같은 프롬프트라도 요청 시점과 제공 경로에 따라 지연과 결과가 달라질 수 있다. 그래서 이 모델을 평가할 때는 공개 벤치마크 숫자를 그대로 믿기보다, 같은 저장소·같은 프롬프트·같은 권한으로 기준 모델과 비교한 기록을 남기는 편이 더 유용하다.

## 정식 공개 후 현재 상태: 무료 프리뷰는 종료됐다

Ox Alpha를 지금도 무료 모델이라고 소개하면 시점이 어긋난다. [OpenCode의 출시 당시 안내를 인용한 보도](https://siliconangle.com/2026/08/23/nobody-knows-who-built-ai-coding-model-ox-alpha-or-where-the-code-goes)에 따르면 OpenCode는 8월 20일부터 “다음 일주일” 무료라고 안내했으므로 **8월 27일 전후가 무료 프리뷰의 종료 시점**으로 정리하는 것이 맞다. OpenRouter는 별도의 사용자 안내에서 8월 24일까지 무료 경로가 제공된 것으로 보도됐고, 현재는 정식 모델 ID와 유료 가격이 확인된다. 두 경로의 종료일을 하나의 무료 기간으로 합치면 안 된다.

| 항목 | 2026년 8월 29일 기준 |
|---|---|
| 정식 모델 ID | `z-ai/glm-5.3-flash` |
| 과거 OpenRouter 별칭 | `stealth/ox-alpha` |
| 과거 OpenCode 별칭 | `x-preview-f-free` 또는 `ox-alpha-free` |
| 컨텍스트 | **1,048,576 토큰(약 1M)** |
| 최대 출력 | **131,072 토큰** |
| 입력·출력 | 텍스트·이미지·비디오 입력, 텍스트 출력 |
| 추론 | 강제 실행. 기본값 `max`, `high`·`low` 지원 |
| 무료 상태 | OpenCode의 한시 무료 프리뷰는 8월 27일 전후 종료로 판단. 남아 있는 목록 표기는 최신 호출 가능 여부를 별도 확인 |
| OpenRouter 현재 가격 | 입력 $0.075/M, 출력 $0.25/M, 캐시 입력 $0.015/M 기준 |
| 오픈 웨이트 | [Hugging Face](https://huggingface.co/zai-org/GLM-5.3-Flash)에서 GLM-5.3-Flash로 공개 |

OpenCode의 Zen 문서에는 한동안 `Ox Alpha Free` 항목이 “limited time”으로 남아 있을 수 있고, [OpenCode 통계 페이지](https://opencode.ai/data/unknown/ox-alpha)는 과거 사용량을 `GLM-5.3-Flash (formerly ox-alpha)`로 표시하면서 집계 구간을 8월 27일까지로 보여 준다. 따라서 문서에 모델명이 보인다는 사실만으로 무료 호출이 현재도 된다고 단정하지 말고, OpenCode의 `/models`와 실제 요청 결과를 확인해야 한다.

1M 컨텍스트와 131K 출력은 카탈로그상 상한이지, 모든 요청에서 안정적으로 보장되는 처리량은 아니다. 또한 OpenRouter 모델 페이지는 제공자가 프롬프트와 완료 결과를 보존하지만 학습에는 사용하지 않는다고 안내한다. OpenCode Zen의 zero-retention 정책은 별도 경로의 정책이므로 두 서비스의 데이터 처리 조건을 섞어 읽지 말아야 한다. 처음 테스트할 때는 비밀정보가 없는 작은 저장소를 사용하자.

## 에이전트에 붙일 때는 무료보다 실패 격리를 먼저 준비한다

Ox Alpha는 도구 호출을 지원하는 것으로 표시되어 있어 OpenCode 같은 코딩 에이전트와 잘 맞을 가능성이 있다. 그러나 도구를 호출할 수 있다는 것과 실제 저장소 작업을 안정적으로 끝낸다는 것은 다른 주장이다. 정식 공개 후 제작자 벤치마크가 추가됐지만, 내 환경에서의 재현성은 별도로 확인해야 하므로 아래 정도의 실험이 적당하다.

1. 버릴 수 있는 작은 저장소에서 시작한다.
2. 읽기·수정·테스트 실행 권한을 한 번에 주지 말고 단계별로 확인한다.
3. 매 요청의 diff, 실행한 명령, 테스트 결과와 총 시간을 남긴다.
4. 같은 프롬프트를 기준 모델에도 넣어 코드 품질과 실패 유형을 비교한다.
5. 가격·호출 한도·제공자 정책이 바뀌었을 때 다른 모델로 자동 전환할지 명시한다.

제공자 장애나 과부하 때 라우팅·fallback이 개입할 수 있으므로, 같은 모델 ID라도 요청 시점에 따라 지연과 결과가 달라질 수 있다. 비밀정보와 운영 데이터는 넣지 않고, 실제 실행 경로와 모델 정책을 확인한 뒤 사용한다.

## 정체 공개 이후에도 남는 확인 경계

이제 “누가 만들었는가”라는 질문에는 답이 나왔다. Z.ai가 GLM-5.3-Flash를 출시하기 전 `ox-alpha`라는 이름으로 실제 트래픽을 받아 테스트했다고 공식 발표했고, OpenRouter도 모델 페이지의 FAQ를 업데이트했다. 다만 정체가 공개됐다고 해서 출시 전 프리뷰의 모든 운영 조건과 정식 모델의 성능이 자동으로 같아지는 것은 아니다.

| 확인된 내용 | 여전히 확인해야 할 내용 |
|---|---|
| Ox Alpha는 Z.ai GLM-5.3-Flash의 출시 전 테스트명이다 | 프리뷰 기간 중 특정 라우트의 세부 설정이 정식 API와 같았는지 |
| 정식 모델은 320B 전체 / 18B 활성 파라미터의 네이티브 멀티모달 모델이다 | 1M 컨텍스트와 131K 출력이 모든 요청에서 보장되는지 |
| 정식 가중치가 Hugging Face에 공개됐다 | 로컬 백엔드별로 동일한 기능·속도·도구 호출이 재현되는지 |
| Z.ai가 코딩·에이전트 성능 수치를 공개했다 | 제작자 수치가 독립 평가와 같은 순서를 보이는지 |
| OpenCode의 무료 프리뷰는 8월 27일 전후 종료로 정리된다 | 과거 `x-preview-f-free` 별칭이 언제까지 응답할지 |

따라서 지금의 핵심은 정체 추측이 아니라 **출시 전 별칭으로 얻은 실사용 신호와, 정식 GLM-5.3-Flash의 공개 가중치·가격·벤치마크를 어떤 조건에서 비교할지**를 기록하는 데 있다.

## 성능을 직접 확인하는 작은 테스트

무료 별칭을 전제로 한 테스트는 이제 재현하기 어렵다. 현재는 OpenRouter에서 `z-ai/glm-5.3-flash` 유료 엔드포인트를 사용하거나, 하드웨어가 허용한다면 공개 가중치를 지원하는 SGLang·vLLM·TokenSpeed 경로로 실행해야 한다. OpenCode에서 과거 `opencode/x-preview-f-free`를 선택할 수 있더라도, 실제로 어떤 모델과 가격 정책으로 연결되는지 `/models`와 요청 응답을 먼저 확인한다. 처음부터 복잡한 기능 구현을 맡기기보다, 현재 프로젝트의 구조·테스트·문서 상태를 읽고 문제 후보를 찾는 작업부터 시작한다.

내가 이 모델을 실제 프로젝트에 넣는다면 순서는 이렇다.

1. 작은 테스트 저장소에서 동일한 GLM-5.3-Flash 모델을 OpenRouter와 로컬 실행 환경에 각각 호출한다.
2. 같은 작업의 diff와 테스트 결과를 비교한다.
3. API 한도와 provider 정책을 확인하기 전까지는 비밀·운영 데이터·자동 배포 권한을 주지 않는다.
4. 가격·엔드포인트가 바뀌어도 멈추지 않도록 fallback 모델과 수동 중단 지점을 남긴다.

성능만 놓고 보면 Ox Alpha, 즉 GLM-5.3-Flash는 **출시 전 실무형 에이전트 테스트와 정식 공개 벤치마크에서 강한 신호를 보였지만, 평가 하니스와 실행 경로에 따른 편차까지 사라진 모델은 아니다.** 따라서 지금 필요한 결론은 “최고의 무료 모델”이 아니라, 정식 모델 ID와 동일한 작업 조건에서 실제 성공률·소요 시간·재시도 횟수를 기록해 보는 것이다.

우선은 이 모델을 현재 프로젝트를 가볍게 점검하는 용도로 활용해볼 예정이다. 저장소 구조와 테스트·문서의 빈틈을 확인하고, 결과는 파일 경로·diff·테스트 실행으로 직접 검증할 생각이다.
