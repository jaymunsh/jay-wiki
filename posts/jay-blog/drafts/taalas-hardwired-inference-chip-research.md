> 이 글은 2026년 8월 26일 기준으로 Taalas와 AMD의 공식 자료, The Next Platform의 창업자 인터뷰, 공개 API 문서를 대조해 정리했다. HC1의 핵심 성능과 비용 수치는 Taalas가 공개한 자체 측정 결과이며, 독립적인 동일 조건 재현 결과로 보지는 않았다.

AI 반도체 이야기를 하면 보통 더 큰 GPU, 더 빠른 HBM, 더 많은 연산 유닛을 먼저 떠올린다. Taalas는 질문을 반대로 던진다.

**모델이 바뀔 때마다 무엇이든 돌릴 수 있어야 한다는 전제를 버리면, 추론 칩을 얼마나 단순하고 빠르게 만들 수 있을까?**

캐나다 토론토의 Taalas는 이 질문에 모델의 가중치와 일부 연산 구조를 칩 제조 과정에서 고정하는 방식으로 답했다. 회사가 말하는 이름은 **Hardcore Model**이고, 첫 번째 기술 시연 칩은 **HC1**이다. HC1은 Llama 3.1 8B 한 모델을 대상으로 사용자당 약 17,000 tokens/sec를 제시했다.

이 숫자만 보면 GPU의 다음 세대처럼 보이지만, 실제로는 성격이 다르다. HC1은 범용 GPU보다 빠른 GPU가 아니라, **한 모델을 매우 빠르게 실행하도록 만든 모델 특화 반도체**다. 따라서 이 기술의 핵심은 최고 속도 자체보다 속도를 얻기 위해 무엇을 고정했는지에 있다.

## Taalas는 범용 칩의 유연성을 줄이고 추론 속도를 얻었다

Taalas는 2023년 설립된 토론토 기반 스타트업이다. 창업자 Ljubisa Bajic은 Tenstorrent의 공동창업자로 알려져 있고, 다른 창업 멤버들도 AMD·Tenstorrent 등에서 칩 설계 경험을 쌓았다. 초기 팀의 배경부터 모델 연구보다 **AI 추론 하드웨어를 실제 칩과 서버로 옮기는 일**에 맞춰져 있었다.

현재 회사의 상태를 표현할 때는 주의가 필요하다. AMD는 2026년 8월 6일 Taalas를 인수하기 위한 **확정 계약(definitive agreement)** 을 발표했지만, 공식 발표문에는 규제 승인과 통상적인 종결 조건이 남아 있다고 적혀 있다. 따라서 이 글의 기준일에는 “AMD가 이미 인수를 끝냈다”보다 **AMD가 Taalas 인수 계약을 체결했다**고 쓰는 편이 정확하다. [AMD 공식 발표](https://ir.amd.com/news-events/press-releases/detail/1296/amd-acquires-taalas-to-advance-compute-solutions-for-rapidly-growing-ai-inference-market)

AMD가 설명한 방향은 Taalas 칩을 단독 제품으로만 보는 것이 아니다. Instinct GPU, EPYC CPU, ROCm 소프트웨어와 함께 시스템 수준의 추론 솔루션으로 통합하겠다는 계획이다. 이 점이 Taalas의 기술을 단순한 스타트업용 특수 칩이 아니라 AMD의 추론 로드맵 안에서 읽어야 하는 이유다.

## 모델의 가중치를 메모리가 아니라 칩의 일부로 취급한다

일반적인 GPU 추론에서는 모델 가중치가 HBM이나 다른 메모리에 저장되어 있다. 토큰을 하나 생성할 때마다 연산 장치가 필요한 가중치를 읽고, 계산하고, 다음 단계로 넘긴다. 모델이 커질수록 계산 유닛의 숫자만큼이나 **가중치를 얼마나 빠르게 옮길 수 있는가**가 병목이 된다.

Taalas는 이 이동을 줄이기 위해 가중치를 소프트웨어 파일처럼 취급하지 않는다. 공개된 인터뷰에서 설명한 구조를 단순화하면 다음과 같다.

```text
고정된 모델 가중치
        ↓
Mask-ROM recall fabric
        ↓
가중치 저장과 연산을 가까운 위치에서 수행

동적으로 변하는 정보
        ↓
SRAM recall fabric
        ↓
KV Cache · 어댑터 · 일부 미세조정 데이터
```

Mask-ROM 영역에는 베이스 모델의 가중치와 모델 실행에 필요한 고정 부분을 배치하고, SRAM 영역에는 대화가 진행되며 계속 바뀌는 KV Cache와 LoRA 같은 어댑터를 둔다. 그래서 “모델을 칩에 새긴다”는 표현은 단순히 파일을 ROM에 복사한다는 뜻이 아니라, **가중치를 저장하는 구조와 연산 구조를 함께 모델에 맞춰 만든다**는 뜻에 가깝다.

Taalas는 회로의 세부 구현을 모두 공개하지 않았다. The Next Platform 인터뷰에서 회사가 설명한 수준에 따르면, 현재 세대는 하드와이어드 부분에 약 8B 파라미터를 담고 SRAM으로 KV Cache와 어댑터를 처리한다. 단일 트랜지스터에 4비트 값과 관련 곱셈을 함께 배치할 수 있다는 설명도 나왔지만, 이 부분은 회사의 기술 설명이지 독립적인 회로 검증 보고서는 아니다. [The Next Platform의 HC1 인터뷰](https://www.nextplatform.com/compute/2026/02/19/taalas-etches-ai-models-onto-transistors-to-rocket-boost-inference/4092140)

## HC1은 Llama 3.1 8B 하나를 위해 만들어졌다

Taalas가 공식 제품 페이지에서 공개한 HC1의 기본 사양은 다음과 같다.

| 항목 | 공개된 내용 |
|---|---|
| 대상 모델 | Llama 3.1 8B |
| 제조 공정 | TSMC 6nm |
| 다이 크기 | 815mm² |
| 트랜지스터 | 53B |
| 서버 구성 | HC1 카드 10장을 넣은 2소켓 서버, 약 2.5kW |
| 성능 주장 | 사용자당 약 17,000 tokens/sec |

815mm²는 현재 칩의 레티클 한계에 가까운 큰 면적이다. 그 안에 53B 트랜지스터를 배치하고, 일반적인 외장 HBM 없이 모델 가중치와 동적 데이터를 온칩 구조로 처리하려는 설계다. 카드 한 장의 전력은 약 200W로 소개됐다. [Taalas HC1 제품 페이지](https://taalas.com/products/)

여기서 “Llama 3.1 8B 모델이 칩 하나에 들어간다”는 말은 8B 파라미터 파일을 일반 메모리에 올린다는 뜻이 아니다. 이 모델에 맞춘 가중치 표현과 연산 경로가 칩에 고정되어 있다는 뜻이다. 그래서 동일한 하드웨어에서 Llama 3.1 8B와 전혀 다른 구조의 모델을 자유롭게 바꿔 실행하는 범용 GPU식 사용법은 기대하기 어렵다.

## 실제로 사용하려면 일반 PC가 아니라 서버에 카드를 장착해야 한다

HC1은 칩 패키지만 따로 사서 메인보드에 붙이는 부품이 아니다. 공개된 설명상 모델이 고정된 **PCIe 가속 카드** 형태로 제공되며, Taalas는 2소켓 x86 서버에 HC1 카드 10장을 넣은 구성을 예로 들었다. 즉 사용자가 상상해야 할 모습은 그래픽카드 한 장을 데스크톱에 꽂는 장면보다, CPU 서버에 추론 전용 카드를 여러 장 장착하고 API나 추론 서버를 연결하는 모습에 가깝다. [The Next Platform의 HC1 인터뷰](https://www.nextplatform.com/compute/2026/02/19/taalas-etches-ai-models-onto-transistors-to-rocket-boost-inference/4092140)

현재 공개 자료에서 확인되는 도입 조건과 아직 공개되지 않은 항목을 나누면 다음과 같다.

| 구분 | 현재 확인 가능한 내용 |
|---|---|
| 장착 형태 | PCIe 가속 카드 형태로 설명됨 |
| 권장 시스템 예시 | 2소켓 x86 서버 + HC1 카드 10장 |
| 카드 전력 | 약 200W로 소개된 수치. 정확한 공식 TDP는 별도 확인 필요 |
| 서버 전력 | 10장 서버 약 2.5kW. 카드만의 합계로 단정하지 말고 서버 전체 수치로 봐야 함 |
| 모델 메모리 | 베이스 가중치용 외장 HBM 없음. KV Cache·어댑터는 온칩 SRAM 영역에서 처리하는 구조 |
| PCIe 세대·레인 수 | 공개 자료에서 확인하지 못함 |
| 카드 길이·높이·두께 | 공개 자료에서 확인하지 못함 |
| 보조전원 커넥터·정확한 냉각 요건 | 공개 자료에서 확인하지 못함 |
| 판매 가격·일반 구매 가능 여부 | HC1이 Technology Demonstrator로 소개된 단계라 공개되지 않음 |

따라서 “PCIe 슬롯만 있으면 바로 쓸 수 있다”고 이해하면 곤란하다. 서버 섀시가 카드의 물리 규격과 공기 흐름을 지원해야 하고, 전원 공급 장치는 카드와 CPU·메모리·스토리지·네트워크를 모두 감당해야 한다. 10장 구성을 실제로 운영한다면 2.5kW라는 시스템 전력 자체가 데이터센터 전원·랙·열 설계의 문제가 된다.

또 하나 놓치기 쉬운 부분은 HC1이 혼자 모든 추론 단계를 처리하는 범용 GPU가 아니라는 점이다. 프롬프트를 읽고 전처리하는 호스트 또는 다른 가속기, 사용자 요청을 분배하는 서버 소프트웨어, 결과를 애플리케이션으로 전달할 네트워크 계층이 함께 필요하다. AMD가 설명한 Instinct GPU와 Taalas 칩의 조합도 이런 역할 분담을 전제로 한 방향으로 볼 수 있다.

반대로 일반적인 M1 Max나 데스크톱 PC에 PCIe 변환 장치를 붙여 곧바로 HC1을 사용하는 경로는 현재 공개된 자료만으로 확인되지 않는다. Thunderbolt 외장 GPU처럼 소비자용 주변기기로 접근할 수 있다고 단정할 근거도 없다. 지금 공개된 형태만 보면 HC1은 **개인용 로컬 가속기보다 서버용 추론 인프라**에 가깝다.

## Llama 3.1 8B는 반복적인 업무형 서비스에 먼저 쓰인다

그렇다면 Taalas가 하필 Llama 3.1 8B를 HC1의 대상으로 삼은 이유는 무엇일까. 이 모델이 최신 프런티어 모델이라서라기보다, **성능과 운영 비용 사이의 균형이 맞는 8B급 범용 모델**이기 때문이다. 작은 모델은 더 큰 모델보다 배포 선택지가 많고, 특정 업무에 RAG나 LoRA를 붙여 서비스 형태로 만들기 쉽다.

Meta가 소개한 Llama 3.1의 용도에도 장문 요약, 다국어 대화형 에이전트, 코딩 보조가 포함되어 있다. 실제 적용 사례로는 기업 교육 플랫폼의 콘텐츠 생성과 RAG 기반 검색, 개인 정보가 기기 밖으로 나가지 않도록 하는 상품 추천·엔티티 추출 사례가 공개되어 있다. 다만 이 사례들이 HC1에서 동작한다는 뜻은 아니고, **Llama 3.1 8B급 모델이 실무에서 어떤 역할을 맡을 수 있는지**를 보여주는 사례다. [Meta의 Llama 3.1 소개](https://ai.meta.com/blog/meta-llama-3-1/), [Cornerstone의 RAG·교육 콘텐츠 사례](https://ai.meta.com/blog/cornerstone-transforming-training-llama/), [기기 내부 처리를 사용한 추천 사례](https://ai.meta.com/blog/untukmu-built-with-llama/)

실무 환경으로 옮기면 다음과 같은 업무가 먼저 떠오른다.

| 환경 | Llama 3.1 8B가 맡을 수 있는 일 | HC1 방식과의 궁합 |
|---|---|---|
| 사내 지식 검색·RAG | 규정, 매뉴얼, 제품 문서를 검색하고 답변 초안 생성 | 같은 모델을 대량 호출하면 유리 |
| 고객지원 자동화 | FAQ 답변, 문의 분류, 상담원 답변 초안 | 낮은 지연과 높은 반복성이 장점 |
| 문서 처리 | 계약서·주문서·보고서의 요약, 분류, 항목 추출 | 출력 형식이 고정된 업무에 적합 |
| 다국어 안내 | 번역 초안, 다국어 챗봇, 현지화 문구 생성 | 언어와 응답 형식이 정해져 있으면 유리 |
| 사내 개발 도구 | 코드 설명, 단순한 코드 변환, 테스트 초안 | 빠른 보조 응답에는 적합하지만 복잡한 구현은 별도 검증 필요 |
| 엣지·온프레미스 서비스 | 개인정보를 외부로 보내지 않는 추천·분류·요약 | 모델을 고정할 수 있다면 전력·지연 이점 기대 |

특히 고객지원이나 문서 처리처럼 업무 흐름이 정해져 있고 요청량이 꾸준한 서비스라면, 매번 더 큰 GPU를 빌리는 대신 하나의 모델을 빠르게 반복 실행하는 편이 운영상 의미가 생긴다. 반대로 연구팀이 매주 새로운 모델을 교체하거나, 여러 모델을 동시에 실험하는 환경에서는 HC1의 모델 고정성이 바로 제약이 된다.

따라서 “Llama 3.1 8B가 실무에서 쓰인다”는 말은 이 모델 하나로 모든 업무를 해결한다는 뜻이 아니다. 정형화된 RAG, 요약, 분류, 추천, 상담 보조 같은 **반복형 업무의 백엔드 모델**로 쓰인다는 의미에 가깝다. 고난도 수학·복잡한 에이전트 계획·고위험 의사결정은 더 큰 모델이나 별도의 검증 계층이 필요하다.

## 17,000 tokens/sec는 어떤 조건의 숫자인가

성능 숫자만 옮기면 HC1이 모든 AI 칩을 압도하는 것처럼 보인다. 하지만 공개된 조건을 함께 적어야 한다. Taalas 제품 페이지는 Llama 3.1 8B, 입력 1K·출력 1K 시퀀스를 기준으로 비교했고, HC1의 결과는 Taalas 자체 측정이라고 명시한다.

| 플랫폼 | 사용자당 생성 속도 | 수치의 성격 |
|---|---:|---|
| **Taalas HC1** | **약 17,000 tokens/sec** | Taalas 자체 측정 |
| Cerebras WSE-3 | 약 2,100 tokens/sec | 회사 발표·외부 집계 혼합 |
| SambaNova SN40L | 약 998 tokens/sec | Artificial Analysis 인용 |
| Groq LPU | 약 587~780 tokens/sec | 외부 벤치마크 인용 |
| Nvidia H200 | 약 230 tokens/sec | Taalas가 사용한 기준값 |
| Nvidia B200 | 약 353~400 tokens/sec | Taalas 측정값 |

이 표는 같은 하드웨어에서 재현한 공통 벤치마크 결과가 아니다. 모델, 입력·출력 길이, 양자화, 런타임, 동시 사용자 수, 측정 시점이 모두 완전히 같다고 보기 어렵다. Taalas도 경쟁사 수치는 Artificial Analysis와 공개 자료를 인용하고, HC1 수치는 자사 랩에서 측정했다고 구분한다.

따라서 이 표에서 읽을 수 있는 결론은 “HC1이 어떤 상황에서도 48배 빠르다”가 아니다. 더 정확한 표현은 다음과 같다.

> Taalas는 Llama 3.1 8B 단일 사용자 스트리밍이라는 좁은 조건에서 기존 GPU와 특화 가속기보다 훨씬 높은 속도를 보고했다. 다만 이 수치는 모델 품질, 범용성, 대규모 동시 사용자 처리 능력까지 비교한 종합 점수가 아니다.

초당 17,000토큰이라는 숫자는 체감상 매우 크지만, 실제 서비스에서는 첫 토큰까지 걸리는 시간, 동시 사용자 수, 긴 컨텍스트에서의 KV Cache 용량, 출력 품질, 모델 교체 비용을 함께 봐야 한다. Taalas의 공개 API는 현재 `llama3.1-8B` 모델과 어댑터를 지정해 호출하는 형태로 제공된다. [Taalas API 문서](https://api.taalas.com/docs)

## 속도의 원인은 연산 유닛보다 메모리 이동을 줄인 데 있다

HC1의 성능을 단순히 “트랜지스터가 많아서”라고 설명하면 핵심을 놓친다. 중요한 변화는 다음 세 가지다.

1. **가중치 이동을 줄인다.** 매 토큰마다 외부 메모리에서 거대한 베이스 모델을 읽는 비용을 크게 줄인다.
2. **모델에 불필요한 유연성을 제거한다.** 어떤 모델도 돌려야 하는 디코더·메모리 계층·소프트웨어 스택을 모두 유지할 필요가 없다.
3. **낮은 지연을 우선할 수 있다.** GPU는 처리량을 높이기 위해 요청을 배칭하는 경우가 많지만, HC1은 단일 사용자 응답 속도를 목표로 설계되어 배칭 의존도를 낮출 수 있다.

이 구조는 메모리 벽을 없애는 대신 모델의 선택권을 줄인다. 즉 Taalas의 아이디어는 GPU를 대체하는 하나의 정답이라기보다, **충분히 많이 반복되는 단일 추론 워크로드에 범용성을 지불하고 토큰당 비용과 지연을 낮추는 방법**이다.

## 모델이 바뀌면 칩도 다시 만들어야 한다

이 접근의 가장 명확한 약점은 모델 고정성이다. Llama 3.1에서 Llama 4로, 혹은 다른 아키텍처의 모델로 바꾸려면 기존 칩에 새 파일을 내려받는 것으로 끝나지 않는다. 베이스 가중치와 모델 구조가 고정되어 있기 때문에 새로운 칩 리스핀이 필요하다.

Taalas는 이 문제를 일반적인 ASIC 설계와 다르게 풀려고 한다. 전체 칩을 처음부터 다시 설계하는 것이 아니라, 대부분의 공통 베이스 웨이퍼를 미리 준비하고 모델별로 상위 금속 레이어 일부만 바꾸는 방식이다. 회사와 인터뷰 보도는 이 과정을 약 2개월의 모델별 제조 사이클로 설명한다.

```text
범용 GPU
모델 변경 → 파일 교체와 소프트웨어 배포

Taalas 방식
모델 변경 → 상위 금속 레이어 재설계 → 새 칩 제조
```

2개월은 기존 대형 AI 프로세서의 설계·제조 주기와 비교하면 짧지만, 모델 릴리스 주기보다 항상 짧다고 보장되는 것은 아니다. 모델이 한 달마다 크게 바뀌거나, 서비스가 여러 모델을 동시에 지원해야 한다면 범용 가속기의 유연성이 다시 중요해진다.

반대로 특정 모델이 기업 내부 상담, 번역, 문서 요약처럼 24시간 반복되고 모델이 쉽게 바뀌지 않는다면 이야기가 달라진다. 모델을 충분히 오래 사용하고 요청량도 많다면 초기 칩 제작비를 토큰당 비용 절감으로 회수할 여지가 있다.

## LoRA 지원은 고정 모델의 약점을 조금 줄인다

모델을 칩에 고정했다고 해서 모든 사용자 맞춤화를 포기하는 것은 아니다. Taalas는 SRAM 영역에 LoRA와 같은 어댑터를 올릴 수 있다고 설명한다. 베이스 모델 자체는 바꾸지 않고 특정 도메인의 말투, 용어, 업무 패턴을 보정하는 식이다.

다만 LoRA 지원을 모델 교체와 혼동하면 안 된다.

| 변경하려는 것 | Taalas 방식에서의 처리 |
|---|---|
| 특정 도메인 말투·용어 보정 | LoRA 어댑터로 대응 가능하다고 설명 |
| 대화 중 누적되는 문맥 | SRAM의 KV Cache로 처리 |
| 베이스 모델의 가중치 변경 | 새 칩 리스핀 필요 |
| 모델 아키텍처 변경 | 기존 칩으로 대응하기 어려움 |

이 구분을 보면 Taalas의 포지션이 분명해진다. “모델을 바꿀 수 없는 칩”이라기보다, **베이스 모델은 고정하고 그 위의 작은 변형만 허용하는 칩**에 가깝다.

## AMD는 Taalas를 Instinct GPU와 조합하려 한다

AMD 인수 계약에서 흥미로운 부분은 Taalas를 기존 GPU의 경쟁자로만 보지 않는다는 점이다. AMD의 공식 발표는 Taalas 기술을 Instinct GPU와 함께 시스템 수준으로 통합하겠다고 설명한다.

추론을 단순화하면 다음처럼 역할을 나눌 수 있다.

| 추론 단계 | 특성 | 어울리는 하드웨어 |
|---|---|---|
| 프롬프트 처리(Prefill) | 입력 토큰을 한꺼번에 처리하는 연산 중심 단계 | AMD Instinct GPU 등 범용 가속기 |
| 토큰 생성(Decode) | 한 토큰씩 순차적으로 생성하며 메모리 이동이 병목이 되는 단계 | Taalas 모델 특화 칩 |

이렇게 되면 모든 단계를 GPU에서 처리하지 않고, GPU가 잘하는 부분과 Taalas가 잘하는 부분을 나눌 수 있다. AMD가 말하는 Helios 랙 스케일 시스템 안에서 Taalas를 읽어야 하는 이유도 여기에 있다.

물론 이것은 AMD가 발표한 통합 방향과 공개 인터뷰를 바탕으로 한 해석이다. 실제 제품에서 어느 모델을 어떤 비율로 배치하고, ROCm과 어떤 방식으로 연결할지는 인수 종결과 제품화 과정을 더 지켜봐야 한다.

## 이 기술이 잘 맞는 곳과 맞지 않는 곳

Taalas 방식이 잘 맞을 가능성이 있는 워크로드는 조건이 뚜렷하다.

- 하나 또는 소수의 모델이 전체 요청량의 대부분을 차지한다.
- 모델이 자주 바뀌지 않고 충분히 오래 서비스된다.
- 낮은 지연과 토큰당 비용이 모델 선택의 유연성보다 중요하다.
- 고객 지원, 정형 문서 요약, 번역처럼 반복 요청이 크다.
- 데이터센터에서 전력과 냉각 비용이 운영비의 큰 비중을 차지한다.

반대로 다음 상황에서는 범용 GPU나 프로그래머블 가속기가 더 현실적이다.

- 여러 모델을 빠르게 교체하거나 동시에 운영해야 한다.
- 새 모델과 새로운 아키텍처를 바로 시험해야 한다.
- 모델 품질이 속도보다 중요하고 낮은 비트 양자화의 영향도 검증해야 한다.
- 요청량이 부족해 전용 칩을 계속 바쁘게 유지하기 어렵다.
- 대규모 모델을 여러 칩으로 나누는 통신과 KV Cache 확장이 아직 검증되지 않았다.

결국 비교 기준은 “HC1이 GPU보다 빠른가”에서 끝나지 않는다. **모델의 수명과 요청량이 칩 제작 비용을 회수할 만큼 충분한가**가 더 중요한 질문이다.

## Taalas가 아직 증명해야 할 것

현재 공개 자료만으로 확인할 수 있는 것은 HC1이라는 기술 시연 칩의 좁은 조건에서 나온 결과다. 아직 다음 질문에는 답이 더 필요하다.

1. 독립 기관이 동일한 입력·출력 길이와 양자화 조건에서 17,000 tokens/sec를 재현할 수 있는가.
2. 긴 컨텍스트와 큰 KV Cache에서도 속도와 품질이 유지되는가.
3. 여러 HC1 카드를 연결해 더 큰 모델을 구동할 때 통신 비용이 얼마나 늘어나는가.
4. LoRA 어댑터를 여러 고객이 교체하는 환경에서 SRAM과 서비스 계층이 어떻게 동작하는가.
5. 모델별 칩 제조 비용, 수율, 실제 판매 가격이 GPU 대비 어느 수준인가.
6. AMD Instinct·EPYC·ROCm과 결합한 실제 랙 시스템이 언제 어떤 형태로 출시되는가.

특히 성능 표의 숫자만으로는 3비트·6비트 등 저정밀 표현이 결과 품질에 미치는 영향을 알 수 없다. 속도와 비용을 얻었지만 코딩, 수학, 도구 호출 같은 작업에서 품질이 얼마나 유지되는지는 별도 평가가 필요하다.

## 결론: Taalas는 GPU를 없애려는 것이 아니라, 모델을 고정할 수 있는 구간을 노린다

Taalas HC1의 아이디어는 과장된 속도 숫자 하나로만 평가하기 어렵다. 가중치를 외부 메모리에서 계속 읽어오는 범용 구조 대신, 모델을 칩의 저장·연산 구조에 포함시켜 메모리 벽을 피하려는 설계다. 그 결과 회사는 Llama 3.1 8B, 입력·출력 1K라는 조건에서 사용자당 약 17,000 tokens/sec를 제시했다.

대신 대가는 분명하다. 베이스 모델을 바꾸려면 칩을 다시 만들어야 하고, 공개된 성능은 아직 회사 자체 측정에 의존한다. 따라서 Taalas의 현실적인 시장은 “모든 AI를 실행하는 범용 가속기”가 아니라, **오랫동안 유지될 모델을 대량·저지연으로 서비스하는 추론 인프라**다.

AMD의 인수 계약은 이 접근을 더 큰 시스템 안에서 시험할 기회를 준다. Instinct GPU가 프롬프트 처리를 맡고 Taalas 칩이 토큰 생성을 맡는다면, 범용성과 특화를 한 랙 안에서 나누는 구조가 가능하다. 다만 이 가설이 실제 제품과 고객 환경에서 증명되기 전까지 HC1의 17,000 tokens/sec는 “AI 추론의 새로운 기준”이라기보다 **조건이 명확한 기술 시연 수치**로 읽는 것이 안전하다.

앞으로 확인할 지표는 단순한 최고 속도가 아니다. 독립 벤치마크, 모델 교체 주기와 2개월 리스핀 경제성, 긴 컨텍스트·멀티칩 확장, 그리고 AMD의 실제 시스템 통합 결과를 함께 봐야 한다.
