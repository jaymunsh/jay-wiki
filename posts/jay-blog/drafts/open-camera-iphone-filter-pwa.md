![Open Camera 앱 아이콘](/api/wiki-assets/11b12ff4-f1ca-4fdb-850c-5bc520f38982 "width=180 align=center")

iPhone용 필터 앱을 받았는데 마음에 드는 필터는 구독 뒤에 있었다. 필요한 것은 사진에 색감을 입히고,
원하는 질감으로 찍는 일이었다. 이 정도는 브라우저에서도 해볼 수 있겠다고 생각해 설치형 카메라 PWA
**Open Camera**를 만들었다.

[앱 열기](https://open-camera-leneu.vercel.app)에서 Safari로 실행하고 홈 화면에 추가할 수 있다.
코드는 [GitHub](https://github.com/jaymunsh/open-camera)에 공개했다. 처음에는 실시간 필터가 중심이었지만,
지금은 촬영 프레임과 질감을 고르고 같은 설정을 다시 쓰는 방향으로 확장하고 있다.

## 2026-10-05에는 촬영 구성과 필름 질감을 함께 확장했다

이번 수정은 필터 이름만 늘리는 작업이 아니었다. 필터를 같은 사진에서 비교하고, 선택한 색감에
질감을 더한 다음, 그 조합을 저장하는 흐름을 연결했다. 기존 필터의 색 변환 값과 일반 촬영 기본값은 유지했다.

| 영역 | 이번에 정리한 기능 |
|---|---|
| 촬영 | 하프프레임, 자동·수동 네 컷, 다중노출, 한 장짜리 즉석사진 |
| 프레임 | 네 컷 배치 6종, 즉석 정사각·세로, 여백 색과 하단 문구 |
| 색감 | 공개 필름 LUT 6종 추가, 사용자 제공 LUT 2종 별도 등록, 동일 원본 A/B 비교 |
| 질감 | 입자 크기·강도·컬러·암부 분포, 광원 번짐과 전후 비교 |
| 재사용 | 카메라 레시피, 고정 패턴·매 컷 새 패턴, 선택형 원본 보관과 다시 현상 |
| 화면 | 스튜디오 탭·접이식 설정 정리, 변경 취소·효과 해제, 선택형 설정 요약 |
| 날짜·카메라 | 바랜 빨강·호박색 날짜와 숫자 간격, 전면 줌 표시·복귀 처리 |

본문의 새 화면은 390×844 브라우저에서 캡처했다. 사진이 보이는 편집·비교 화면은 앱에 들어 있는
AI 생성 카페 샘플을 사용했다. 실제 iPhone 촬영 결과나 필름 재현 정확도의 근거로 쓰는 사진은 아니다.

## 네 컷은 현재 한 장을 크게 찍고 합성 상태만 작게 보여준다

하프프레임은 두 장, 네 컷은 네 장을 하나의 사진으로 합친다. 처음에는 촬영 화면 자체를 여러 칸으로
나눴지만 현재 찍는 장면이 너무 작아졌다. 메인 화면에서는 한 컷을 크게 보고, 전체 배치는 오른쪽 아래
반투명 합성 미리보기에서 확인하는 방식으로 바꿨다.

미리보기는 확대·축소·접기가 가능하다. 찍은 칸은 고정되고 현재 칸만 실시간으로 바뀐다.
창을 접어도 자동 촬영과 카운트다운은 계속되며, 이 창의 크기는 저장 사진이나 카메라 줌과 무관하다.

네 컷은 자동과 수동을 모두 지원한다. 자동은 첫 컷을 셔터로 찍은 뒤 3·5·10초 중 선택한 간격으로
이어지고, 일시정지와 재개가 가능하다. 수동은 셔터를 누를 때마다 한 장씩 찍는다.
첫 컷 이후에는 촬영 방식·간격·비율과 공통 질감을 잠가 중간에 구성이 바뀌지 않게 했다.

완성 화면에서는 컷별 썸네일을 눌러 해당 컷만 다시 찍을 수 있다. 프레임 배치와 여백은 촬영 뒤에도
바꿀 수 있고, 공유·저장 버튼은 하단에 남긴다. 다중노출은 두 장을 겹치며 두 번째 촬영에 첫 사진을
가이드로 보여준다.

## 즉석사진은 필름 색감과 프레임을 따로 고르게 했다

한 장짜리 즉석 정사각·즉석 세로를 추가했다. 네 컷에는 기본 2×2, 클래식 스트립, 메모리 2×2,
메모리 스트립, 가로 네 컷, 필름 스트립을 제공한다. 메모리 프레임은 하단 여백을 넓게 남긴다.

여백은 흰색·검은색·크림·연분홍에서 고르고, 문구를 지원하는 프레임에는 짧은 글을 넣는다.
즉석사진 프레임을 골랐다고 특정 색감이 강제로 붙지는 않는다. 프레임과 필름을 분리해야
같은 색감으로 일반 사진도, 여백 있는 사진도 찍을 수 있다.

![즉석사진의 크림 여백과 하단 문구를 선택한 스튜디오 화면](/api/wiki-assets/ef8c6032-0cf1-412b-8314-ec06cbd98f32 "width=390 align=center")

스튜디오는 템플릿·촬영 모드·효과 탭으로 나누고, 세부 옵션은 접었다 펼치게 정리했다.

효과 탭의 변경 취소는 진입 전 효과로 돌아가고, 효과 해제는 필름·렌즈·추가 질감을 끈다.

일반 닫기는 변경을 유지한다. 어느 버튼도 뷰티·색상 보정·날짜·촬영 구성을 한꺼번에 초기화하지 않는다.

## 필터는 같은 원본에서 비교해야 차이가 보인다

필터마다 다른 사진을 쓰면 색감 차이보다 사진 자체의 차이가 먼저 보인다.

인물·음식·풍경·카페·거리·야간·실내의
기준 사진 7종을 만들고, 선택한 한 사진으로 필터 썸네일을 생성하도록 했다.
샘플을 바꾸는 것은 같은 필터를 다른 장면에서 보는 것이지 새 필터를 추가하는 일이 아니다.

필터 전체 보기의 색감 비교는 한 원본에 A와 B의 LUT와 각 강도를 적용한다.
샘플뿐 아니라 멈춘 현재 장면, 불러온 편집 사진, 보관된 필터 적용 전 원본도 비교 소스로 쓴다.
원본 전환과 공통 중앙 확대를 제공하고, 적용 버튼을 눌러야 선택한 색감이 현재 설정에 반영된다.

![같은 카페 원본에 FUJI 160C와 SUPERIA 400을 적용한 A/B 색감 비교](/api/wiki-assets/db740a7b-8148-41c8-89dc-3b29395ef5f3 "width=390 align=center")

색감만 비교·적용할 때는 기존 입자·렌즈·CCD 효과·날짜 등 나머지 설정을 보존한다.
전체 룩 강도는 질감까지 함께 줄이고, 색상만 강도는 색 변환만 줄인다.
비교 사진을 바꾸는 일과 촬영 카메라 설정을 바꾸는 일도 분리했다.

## 새 LUT와 기존 색감에 붙이는 질감을 구분했다

공개 필름 컬렉션에 실제 HaldCLUT 데이터 6종을 추가했다.

| 추가 LUT | 별도 질감 설정 |
|---|---|
| FUJI 160C | 입자·렌즈는 사용자가 별도로 선택 |
| SUPERIA 400 | 입자·렌즈는 사용자가 별도로 선택 |
| ULTRA COLOR 100 | 입자·렌즈는 사용자가 별도로 선택 |
| ELITE CHROME 200 | 입자·렌즈는 사용자가 별도로 선택 |
| INSTANT 690 | 즉석사진 프레임과 별개로 선택 |
| NEOPAN 1600 | 흑백 색 변환과 입자 강도를 별도로 선택 |

이 6종은 Pat David / Natron CLUT의 CC BY-SA 4.0 자료이며 출처·저작자·라이선스를 앱과 저장소에 남겼다.
제조사 공식 LUT나 실제 필름의 측정 기반 재현으로 소개하지 않는다.
원본 파일 대응과 데이터 검증 기록은 [필름 출처 문서](https://github.com/jaymunsh/open-camera/blob/main/public/luts/film/CREDITS.md)에 있다.

사용자 제공 파일 2종은 MUTED CHROME과 DEEP NEGATIVE로 별도 등록했다.

표시 이름만 바꿨고 파일과 색 변환 값은 유지했다.
이 두 파일의 원저작자·역추출 방법·재배포 조건은
확인하지 못했다.

공개 필름 컬렉션의 라이선스를 적용하지 않는다.
[별도 출처 기록](https://github.com/jaymunsh/open-camera/blob/main/public/luts/provided/CREDITS.md)에 이 제한을 남겼다.

대표 룩 후보 6종은 위 색 데이터와 자체 질감 설정의 조합이다. 새 LUT 6개를 더 만든 것은 아니다.
아직 실제 사진 평가 전이므로 일반 목록이 아닌 [시험용 경로](https://open-camera-leneu.vercel.app/?film-quality-preview=1)에서만 보여준다.

## 빈티지는 색감뿐 아니라 디테일과 입자도 다뤄야 했다

기존 디지캠 효과에는 JPEG 블록, 저가 렌즈 왜곡, CCD 노이즈·블루밍·핫픽셀, 먼지·빛샘 등이 있었다.

구형 디지캠·일회용 필름·바랜 인화사진 프리셋은 저장 단계에서 실제 축소와 JPEG 압축도 거쳐
디테일을 의도적으로 낮춘다. 저장 이미지의 크기는 유지한다.

날짜와 프레임 문구는 그 뒤에 합성해 글씨까지 손상시키지 않는다.

실시간 화면은 가벼운 GPU 근사이므로 추가 압축을 거친 저장 결과와 완전히 같지는 않다.
원본 보관에는 이 처리를 적용하지 않는다.

새 필름 처리는 별도의 선택형 입자 모델이다. 스튜디오의 효과 → 필름 질감에서 켜고,
고운·보통·거친 입자와 입자 강도·광원 번짐을 고른다. 세부 조정에서는 입자 크기·컬러·암부 분포·번짐 범위를 바꾼다.
기존 처리도 그대로 선택할 수 있다.

![새 필름 처리의 입자 크기·강도와 광원 번짐을 조절하는 화면](/api/wiki-assets/c6f100b2-693b-4973-a9bf-add13357ac2c "width=390 align=center")

기존 수동·프리셋 그레인과 새 입자를 무조건 두 번 겹치는 방식은 아니다.
유효 입자 강도를 합산해 새 모델에서 한 번 처리하며, CCD 색 노이즈처럼 다른 효과는 별도로 남는다.
질감 비교에서는 같은 사진을 멈춰 놓고 적용 전후를 본다.

추가 입자·빛샘·먼지·색 편차의 우연성은 매 컷 새 패턴과 패턴 고정으로 나눴다.
마음에 드는 패턴은 저장하고, 재현상에는 촬영 당시의 컷별 패턴을 복원한다.
바랜 빨강과 연한 호박색 날짜에는 각진 세그먼트 숫자를 쓰고, 연·월·일 사이 간격은 실제 숫자 획 기준으로 맞췄다.

## 나만의 색감은 LUT로, 나머지 효과는 레시피로 저장한다

LUT는 RGB 색 변환을 담는다. 입자·광원 번짐·렌즈·얼굴 보정·날짜처럼 위치나 장면에 따라 달라지는
효과를 하나의 색 표에 저장할 수는 없다. 그래서 두 저장 방식을 구분했다.

| 기능 | 저장하는 내용 | 제외하는 내용 |
|---|---|---|
| LUT 만들기 | 현재 LUT·강도와 색상 조절의 조합 | 입자·번짐·렌즈·뷰티·날짜·프레임 |
| 카메라 레시피 | 필터 ID·강도, 보정·뷰티·날짜·렌즈·비율, 질감과 추가 패턴 설정 | 사진·사용자 LUT 파일, 프레임·자동 촬영 구성 |

LUT 만들기는 64³ 색 그리드를 현재 색 변환에 통과시킨다.
결과는 512×512 PNG HaldCLUT로 기기에 등록한다.

색 조절값만 초기화하고 굽지 않은 효과는 현재 설정에 별도로 남긴다.
현재는 앱 안에서 사용하는 기능이며, .cube 다운로드나 외부 편집기로 내보내기는 없다.

카메라 레시피는 우측 상단 메뉴에서 이름을 입력하고 현재 설정 저장을 누른다.
최대 20개를 저장하고 적용·이름 변경·삭제할 수 있다.
나만의 색감과 질감을 다시 쓰려면 LUT를 만든 뒤 레시피도 저장하면 된다.

![필터와 고운 입자 설정을 카메라 레시피로 저장한 화면](/api/wiki-assets/66ff6370-2f69-4fe4-a871-03c809e33d94 "width=390 align=center")

레시피는 같은 기기·브라우저에만 남는다. 사용자 LUT 파일을 함께 보관하거나 다른 기기로 동기화하지 않는다.
해당 LUT가 없으면 적용 전에 안내하며, 브라우저 데이터를 지우면 저장 내용이 사라질 수 있다.

## 최근 사진은 임시 보관함이고 원본은 선택해서 남긴다

상단 비율 버튼 왼쪽 썸네일과 메뉴의 최근 촬영에서 사진을 확인한다.
최근 10묶음, 완성본과 원본 합계 50 MiB를 한도로 기기에 보관한다.
저장 공간을 쓸 수 없으면 현재 세션에서 확인하고 직접 저장·공유하는 경로를 제공한다.
장기 앨범이나 클라우드 백업은 아니다.

원본도 보관은 기본 꺼짐이다. 켜면 앱의 필터·뷰티·날짜를 넣기 전 JPEG를 함께 남긴다.
센서 RAW가 아니라 크롭·미러가 적용된 카메라 이미지다.

원본이 있는 사진은 다시 현상할 수 있다. 원래 완성본과 촬영 날짜를 유지하고 결과를 새 사진으로 남긴다.
합성본은 컷별 원본과 패턴을 사용하지만, 합성 사진 재현상에는 뷰티 보정을 지원하지 않는다.

## WebGL 처리와 저장 단계를 나눠 유지했다

React·TypeScript·Vite 화면 아래에서 WebGL2 파이프라인이 색 변환과 실시간 이펙트를 처리한다.

LUT는 3D 텍스처로 올리고, 얼굴 보정과 기본 조절·렌즈·입자는 설정에 따라 적용한다.

새 필름 모델은 명시적으로 선택할 때만 사용하며, 기존 처리 결과를 유지하도록 경로를 나눴다.

프리뷰와 출력은 별도 파이프라인을 쓴다. 프리뷰는 preserveDrawingBuffer를 끄고,
저장용은 보존 가능한 버퍼에서 렌더링한다. 얼굴 인식은 뷰티를 쓸 때 지연 로딩한다.
날짜·합성 프레임·문구와 일부 빈티지 압축은 사진 처리 뒤에 붙인다.

LUT 파일은 파싱과 IndexedDB 저장이 끝난 뒤 성공을 알린다.
GPU 컨텍스트가 중단된 경우 빈 출력을 성공한 사진으로 저장하거나 비교하지 않게 했고,
비동기 비교·레시피 요청이 늦게 도착해 취소된 설정을 덮는 경로도 검사했다.

PWA는 앱 자산과 사용한 LUT·모델을 캐시한다. 처음부터 모든 필터와 뷰티 자산이 오프라인에 준비되는 것은 아니다.
필터 썸네일은 선택한 소스와 설정에 따라 생성하며, 보이는 항목부터 처리하고 제한된 캐시에 보관한다.

## iPhone 화면과 복귀 처리는 계속 확인하고 있다

10월 1~2일에는 상단과 저장 안정성을 먼저 손봤다. 카메라 사용 표시 때문에 앱 헤더가 옅어 보이던 부분은
불투명 검정 헤더와 안전 영역으로 조정했다.

시스템의 카메라 사용 표시 자체를 숨기는 기능은 아니다.
GPU 프리뷰와 격자·날짜의 정렬 기준도 맞췄고, 현재는 1:1·3:4·4:5를 포함해 촬영 화면을 중앙에 놓는다.

전면에 의미 없이 나오던 후면용 3·5배 버튼은 제거했다. 웹 카메라가 보고하는 줌 범위에서 선택지를 만들고,
요청 뒤 실제 적용값을 다시 읽는다. 웹에서 0.5가 보고되지 않으면 광각 버튼을 만들어 지원한다고 표시하지 않는다.

전면 카메라의 백그라운드 복귀는 새 스트림으로 연결하고 확인된 줌과 비율을 복원하도록 정리했다.
다만 웹 줌 값이 iPhone 기본 카메라 앱의 배율과 같은 의미라고 단정하지 않는다.
가상 카메라 테스트는 실제 iPhone의 화각·발열·권한·공유 경험을 대신하지 못한다.

자동 검증은 Chromium 가상 카메라 기반의 촬영·저장·복귀·레시피·비교·재현상 회귀 테스트,
타입 검사와 프로덕션 빌드로 구성한다.

## 기능 수보다 실제 사진의 차이를 더 확인해야 한다

필터와 템플릿을 늘려도 사진에서 차이가 설득력 없으면 의미가 없다.
다음에는 같은 인물·거리·음식 사진에서 색과 질감을 비교하고, 마음에 드는 조합을 대표 레시피로 다듬으려 한다.

- 대표 룩 6종은 아직 실제 사진으로 충분히 평가하지 않았다.
- 일부 빈티지 저장 질감은 실시간 프리뷰와 차이가 있다.
- 실제 iPhone Safari/PWA의 성능·발열·화각·장기 복귀 검증은 더 필요하다.
- 사용자 제공 LUT 2종은 재배포 조건이 미확인이다. 이름 변경이나 무료 공개를 권리 확인의 근거로 삼지 않는다.
- 원본과 레시피는 로컬 저장이며 백업·기기 간 동기화가 없다.
- 영상·일괄 편집·필름롤·추가 피부 보호 기능은 이번에 구현하지 않았다. 기존 뷰티는 유지한다.

Open Camera는 유료 카메라의 기능 목록을 모두 복제하는 앱보다,
**원하는 색감과 촬영 구성을 만들고 다시 쓰는 작은 카메라**로 다듬고 있다.
