iPhone용 필터 앱을 찾아보면 하나같이 같은 패턴이다 — 무료라고 받았더니 필터 몇 개만 열어주고 나머지는 주간 구독.

그런데 필터 앱이 하는 일의 본질은 "센서 프레임에 색 변환 함수를 적용하는 것"이다. 그건 브라우저의 WebGL로도 충분히 할 수 있다.

그래서 직접 만들었다 — 설치형 PWA 카메라 필터 앱 **Open Camera**다. [open-camera-leneu.vercel.app](https://open-camera-leneu.vercel.app)에서 바로 쓸 수 있고("홈 화면에 추가"로 설치), 코드는 [GitHub에 공개](https://github.com/jaymunsh/open-camera)했다.

이 글의 앞부분은 처음 앱을 만들 때의 개발기다. 이후 변경 사항은 본문을 갈아엎는 대신 맨 아래 날짜별 업데이트로 이어서 기록한다.

## 무엇을 만들었나

- **실시간 카메라 프리뷰** — 전/후면 전환, 핀치 줌 + 프리셋 줌 버튼, 토치
- **필터** — 수식으로 직접 생성한 프로시저럴 LUT + RawTherapee 계열 HaldCLUT 필름 시뮬레이션(CC BY-SA), 강도 조절
- **디지캠 이펙트** — JPEG 아티팩트, 저가 렌즈 왜곡, CCD 블루밍/핫픽셀, 플래시, 수직 스미어, 먼지, 라이트 리크, 할레이션, 그레인 — 요즘 유행하는 "디지캠 감성"을 한 프리셋으로
- **일본풍 프리셋** — UTSURUN / SHINSEN / TOUMEI / MORI / SHOWA / NEON / MIDORI
- **날짜 스탬프** — DSEG7 세그먼트 폰트로 찍히는 디지캠 날짜, 포맷·크기·방향 설정
- **뷰티 보정** — MediaPipe 얼굴 랜드마크 기반 스킨 스무딩·워프(최대 3인)
- **커스텀 LUT** — `.cube` / HaldCLUT PNG 가져오기, 그리고 "현재 설정을 LUT로 굽기"
- **PWA** — 홈 화면 설치, 서비스 워커 오프라인 동작, JPEG 저장/Web Share 공유

![앱의 카메라 화면 — 하단 필터 스트립에 프리셋 썸네일이 나란히 놓이고, 좌하단에 필터/보정/조절 탭이 있다. 1:1 비율로 레터박스된 상태](/api/wiki-assets/00c4f54b-a0eb-484b-8926-c8eeb0ad76b2 "width=340 align=center")

초기 필터 스트립의 각 썸네일은 현재 프레임에 그 프리셋을 실제로 적용한 미리보기였다 — 재미있는 구현 디테일인데, 별도 오프스크린 `FilterPipeline`(128px) 하나를 공유해 순차로 생성한다.

처음엔 프리셋마다 소스 텍스처를 다시 업로드해서 시트가 느렸는데, `setSource`를 루프 밖으로 빼 한 번만 하도록 고치니 빨라졌다.

아래는 AI 생성 샘플 이미지에 필름 계열 프리셋을 적용한 결과다 — 앱의 LUT/조절/그레인 체인이 그대로 타는 출력물.

## 모든 처리는 셰이더 한 방에 — WebGL2 uber-shader

핵심은 `FilterPipeline`이라는 WebGL2 파이프라인이다. 프리셋마다 셰이더를 갈아끼우는 대신, **하나의 uber-shader**(초기 구현 기준 약 525행 GLSL)에 모든 처리를 넣고 유니폼으로 켜고 끈다. 프래그먼트 셰이더 안에서 대략 이런 순서로 진행된다:

1. 소스 샘플 (mirror/줌/렌즈 왜곡/픽셀화까지 uv 변환으로)
2. 얼굴 마스크 영역 보정 (스무딩·톤·다크서클 — `u_beautyMask`가 실질 0이면 통째로 건너뜀)
3. 디지캠 플래시
4. **3D LUT 적용** (`texImage3D`로 올린 3D 텍스처 × 강도; 초기 구현에서는 33³ 그리드)
5. 기본 조절 11종 (노출/대비/채도/색온도/틴트/하이라이트/쉐도우/화이트/블랙/비브란스/명료함)
6. 공간 이펙트 — soft/bloom/halation(`textureLod`로 낮은 밉 샘플) → 비네트 → 먼지 → 노이즈 → 밴딩 → JPEG 블록
7. 선명도, 그레인

날짜와 합성 프레임은 저장 단계에서 별도로 붙인다. 위 순서는 초기 색 변환·이펙트 파이프라인을 설명한 것이며, 이후 추가한 필름 질감과 저장 압축은 아래 업데이트에 정리했다.

각 단계는 `u_x > 0.001` 같은 유니폼 가드로 생략 가능하다. 프리셋별 셰이더 분리는 복잡도 대비 이득이 없어 유니폼 분기를 택했다.

**프리뷰와 익스포트는 파이프라인이 두 개다.** 프리뷰는 `preserveDrawingBuffer: false` — 픽셀 리드백이 없어 프레임당 복사 비용을 아낀다.

저장할 때만 별도 지연 생성 파이프라인(`preserve: true`)을 띄워 원본 해상도로 렌더하고 `toBlob`으로 뽑는다.

preserve를 켠 채 프리뷰를 돌리면 느려지고, 끈 채 `toBlob`을 부르면 빈 버퍼를 읽어 검은 이미지가 나온다 — 이 분리는 그 사고를 막기 위한 것이다.

얼굴 인식(MediaPipe Face Landmarker)은 **dynamic import**로 필요할 때만 로드한다 — 뷰티 기능을 안 쓰면 메인 번들에서 143KB + wasm/models 37MB가 아예 빠진다. 대신 첫 뷰티 진입 시 로딩이 살짝 있는데 이건 의도된 트레이드오프다.

## LUT를 번들할 수 없다는 것을 배웠다 — 저작권 문제

기능만큼이나 고민했던 문제가 있었다. 후지 필름 시뮬레이션이나 유명 LUT 팩의 색감을 앱에 넣고 싶었지만, 파일을 내려받을 수 있다는 것과 앱에 재배포할 수 있다는 것은 구분해야 했다. 당시에는 재배포 조건이 불명확한 파일을 번들에서 빼는 방향으로 정리했다.

그래서 **각자 가진 파일을 가져오는 기능**을 만들었다. 앱에는 `.cube`/HaldCLUT PNG import가 있다(메뉴 → LUT 가져오기, 다중 선택 지원). 내 경우에는 LUMIX PhotoStyle을 변환한 `.cube` 파일을 가져와 사용했다.

사용자 import가 파일의 이용 조건까지 해결해 주는 것은 아니므로, 이 기능을 권리 확인을 대신하는 장치로 소개하지는 않는다.

직접 수식으로 만든 필터와 출처·라이선스를 표기한 공개 HaldCLUT도 함께 제공했다. 이후 사용자 제공 파일 2종을 추가한 경위와 아직 확인하지 못한 재배포 조건은 10월 5일 업데이트에 따로 남겼다.

부가 기능으로 **현재 설정을 LUT로 굽기**도 만들었다. identity 색 그리드를 현재 색 변환에 통과시켜 앱에서 다시 선택할 수 있는 HaldCLUT로 등록한다.

입자·렌즈·날짜까지 하나의 LUT에 담거나 다른 툴로 내보내는 기능은 아니다. 현재의 저장 범위와 레시피 기능은 아래에 구분했다.

## iOS PWA에서 실제로 터진 함정들

웹뷰/브라우저 환경은 만만치 않았다. 겪은 것 중 기록할 만한 것들:

**`.cube` 파일을 선택할 수 없다.** `<input accept=".cube,.png">`를 넣으면 iOS가 `.cube`라는 UTI를 모른다며 파일 선택 자체를 막는다. `accept`를 빼고 JS에서 확장자를 검증하는 쪽으로 바꿨다.

**카메라 권한은 컨텍스트마다 따로 묻는다.** Safari와 홈 화면에 설치된 PWA는 별도 권한 컨텍스트다 — 각각 최초 1회씩 승인해야 한다. 임시 터널 도메인으로 테스트하면 매번 묻는 것처럼 보이는데, origin 단위 기억이라 당연한 동작이었다.

**백그라운드에서 돌아오면 카메라가 죽어 있다.** `visibilitychange`에서 트랙이 `ended`거나 비디오 `readyState < 2`면 `getUserMedia`를 재실행하게 했다.

**격자선이 사진 가장자리를 벗어났다.** 3:4 레터박스에서 GL 뷰포트는 중앙 정렬인데 오버레이 좌표만 하단 정렬로 바꿔 생긴 버그. `render()`에 `valign: 'bottom'`을 추가해 GL과 DOM이 같은 정렬을 쓰게 고쳤다 — "GL 렌더와 오버레이는 반드시 같은 정렬을 써야 한다"가 교훈.

## 배포도 순탄하지는 않았다

`open-camera.vercel.app`은 다른 사람이 이미 점유하고 있어서 — 그래서 도메인이 `open-camera-leneu.vercel.app`이다.

게다가 팀 기본값의 `ssoProtection` 때문에 새 도메인이 SSO 로그인으로 튕기는 사고도 있었다(API로 해제). GitHub 연동이 안 돼 있어 지금은 `npx vercel --prod` 수동 배포다.

PWA 캐시 전략은 이렇게 잡았다 — JS/CSS/아이콘/폰트(~473KB)는 precache, `wasm/`(34MB)과 모델은 precache에서 빼고 첫 사용 시 CacheFirst 런타임 캐시, `/luts/*`도 CacheFirst라 한 번 쓴 필터는 오프라인에서 돈다.

## 한계와 다음

- **iOS(Safari/WebKit) 위주로만 검증했다.** Android·데스크탑은 돌아가더라도 카메라/설치/공유가 다르게 동작할 수 있다.
- `generateMipmap`을 매 프레임 돌린다 — bloom/halation용 밉 체인 때문인데 발열이 문제 되면 저해상도 FBO 패스로 교체할 여지가 있다.
- 초기에는 조절값(params)을 세션마다 리셋했다. 이후 원하는 설정을 명시적으로 저장하는 카메라 레시피를 추가했다(아래 10월 5일 업데이트).
- 앱 스토어 배포는 없다 — PWA라서 애플 심사·수수료와 무관한 대신 "홈 화면에 추가" 흐름을 사용자가 알아야 한다.

## 2026-10-02 — 프리뷰 정렬과 저장 안정성을 손봤다

10월 1~2일에는 기능을 늘리기보다 실제로 쓰면서 드러난 화면과 저장 문제를 정리했다.

- iOS 27에서 카메라 사용 표시가 켜질 때 앱 상단이 옅어져 보이는 현상을 줄이도록, 상단 헤더를 불투명한 검정색으로 고정하고 안전 영역만큼 공간을 확보했다. 시스템의 카메라 사용 표시는 그대로 남는다.
- 4:5 프리뷰는 남는 여백이 작아도 항상 중앙에 놓이게 바꿨다. GPU 화면과 격자·날짜 표시의 기준을 함께 맞췄고, 다른 비율의 정렬과 저장 사진의 크롭 방식은 유지했다.
- 현재 설정을 LUT로 저장한 뒤 조절값이 다시 적용되는 문제를 고쳤다. 색 변환에 구운 값만 초기화하고, 그레인·비네트처럼 LUT에 담지 못하는 공간 효과는 별도로 남긴다.
- LUT 파일은 검증을 마친 뒤 저장하고, 저장 실패를 성공으로 처리하지 않도록 고쳤다. 사진 저장과 얼굴 인식 초기화 실패도 오류 표시나 재시도로 이어지게 정리했다.
- 사진 편집 중에는 카메라를 중지하고, 번들 LUT·얼굴 인식 자산의 캐시에는 파일 버전을 붙여 배포 뒤 예전 자산이 계속 남는 일을 줄였다.

정렬 회귀 검사는 가짜 카메라를 사용하는 브라우저 테스트로 확인했다. iPhone 실기기의 시스템 UI까지 자동 검증한 것은 아니므로, iOS 버전과 화면 방향에 따른 확인은 계속 필요하다. 앱은 기존 주소에 수동 배포하는 방식을 유지한다.

## 2026-10-05 — 촬영 구성과 질감을 고르고 다시 쓰는 흐름으로 확장했다

이번에는 필터 이름만 늘리기보다, 같은 사진에서 색감을 비교하고 질감을 더한 다음 그 조합을 다시 쓰는 흐름을 연결했다. 기존 필터의 색 변환 값과 일반 촬영 기본값은 유지했다.

| 영역 | 추가·개선한 내용 |
|---|---|
| 촬영 | 하프프레임, 자동·수동 네 컷, 다중노출, 한 장짜리 즉석사진 |
| 프레임 | 네 컷 배치 6종, 즉석 정사각·세로, 여백 색과 하단 문구 |
| 비교 | 인물·음식·풍경·카페·거리·야간·실내 샘플, 같은 원본의 LUT A/B 비교 |
| 질감 | 입자 크기·강도·컬러·암부 분포, 광원 번짐, 패턴 고정·매 컷 새 패턴 |
| 재사용 | 카메라 레시피, 최근 사진 확인, 선택형 원본 보관과 다시 현상 |
| 화면 | 스튜디오 탭·접이식 설정, 변경 취소·효과 해제, 선택형 설정 요약 |

아래 새 화면은 390×844 브라우저에서 캡처했다. 편집·비교 화면의 사진은 앱에 들어 있는 AI 생성 카페 샘플이다. 실제 iPhone 촬영 결과나 필름 재현 정확도를 입증하는 사진은 아니다.

### 한 컷은 크게 보고 전체 구성은 작게 확인하게 했다

하프프레임은 두 장, 네 컷은 네 장을 하나로 합친다. 촬영 화면을 여러 칸으로 나누면 현재 장면이 너무 작아져, 메인 화면은 한 컷을 크게 유지하고 오른쪽 아래 반투명 창에서 전체 구성을 보게 했다. 창은 확대·축소·접기가 가능하며 저장 사진의 크기나 카메라 줌을 바꾸지 않는다.

네 컷은 자동·수동을 모두 지원한다. 자동은 첫 컷 이후 3·5·10초 간격으로 이어지고 일시정지·재개가 가능하다. 첫 컷 이후에는 촬영 방식·간격·비율과 공통 질감을 잠근다. 완성 화면에서는 컷별 재촬영, 프레임 변경, 저장·공유를 할 수 있다.

다중노출은 두 장을 겹치고 첫 사진을 다음 촬영의 가이드로 보여준다. 한 장짜리 즉석사진은 정사각·세로 두 종류다. 네 컷 배치는 기본 2×2, 클래식 스트립, 메모리 2×2, 메모리 스트립, 가로 네 컷, 필름 스트립으로 늘렸다.

![즉석사진의 크림 여백과 하단 문구를 선택한 스튜디오 화면](/api/wiki-assets/ef8c6032-0cf1-412b-8314-ec06cbd98f32 "width=390 align=center")

여백은 흰색·검은색·크림·연분홍에서 고르고 지원 프레임에는 하단 문구를 넣는다. 프레임과 색감은 분리해 같은 필터를 일반 사진과 즉석사진에 모두 쓸 수 있게 했다.

스튜디오는 템플릿·촬영 모드·효과로 정리했다. 효과 탭의 변경 취소는 진입 전 효과로 돌아가고, 효과 해제는 필름·렌즈·추가 질감을 끈다. 일반 닫기는 변경을 유지한다. 뷰티·색상 보정·날짜·촬영 구성까지 한꺼번에 초기화하지는 않는다.

### 같은 원본에서 비교하고 새로운 LUT의 출처를 남겼다

초기의 현재 프레임 썸네일과 달리, 지금은 기준 사진 7종 중 하나를 골라 같은 소스로 필터 썸네일을 만든다. 샘플이 달라지는 것은 같은 필터를 다른 장면에서 보는 것이지 새 필터를 추가하는 일이 아니다.

색감 비교에서는 한 원본에 A·B의 LUT와 각 강도를 적용한다. 샘플, 멈춘 현재 장면, 편집 사진, 보관된 원본을 쓸 수 있다. 원본 전환과 공통 중앙 확대를 제공하며 적용 버튼을 눌러야 현재 설정에 반영된다.

![같은 카페 원본에 FUJI 160C와 SUPERIA 400을 적용한 A/B 색감 비교](/api/wiki-assets/db740a7b-8148-41c8-89dc-3b29395ef5f3 "width=390 align=center")

공개 필름 컬렉션에는 **FUJI 160C, SUPERIA 400, ULTRA COLOR 100, ELITE CHROME 200, INSTANT 690, NEOPAN 1600**을 추가했다.

Pat David / Natron CLUT의 CC BY-SA 4.0 자료로, [출처·라이선스](https://github.com/jaymunsh/open-camera/blob/main/public/luts/film/CREDITS.md)를 남겼다. 제조사 공식 LUT나 실제 필름의 측정 기반 재현으로 소개하지 않는다.

사용자 제공 파일 2종은 **MUTED CHROME, DEEP NEGATIVE**로 별도 등록했다. 표시 이름만 바꿨고 색 변환 값은 그대로다. 원저작자·역추출 방법·재배포 조건은 확인하지 못했다.

이 두 파일에는 공개 필름 컬렉션의 라이선스를 적용하지 않는다. [별도 출처 기록](https://github.com/jaymunsh/open-camera/blob/main/public/luts/provided/CREDITS.md)에 미확인 상태를 명시했다. 이름 변경이나 무료 공개를 권리 확인의 근거로 삼지는 않는다.

대표 룩 후보 6종은 색 데이터와 자체 질감 설정을 조합한 것으로, 또 다른 새 LUT 6개는 아니다. 실제 사진 평가 전이므로 [시험용 경로](https://open-camera-leneu.vercel.app/?film-quality-preview=1)에만 둔다.

### 색감뿐 아니라 입자와 디테일도 조절하게 했다

기존 디지캠 효과는 유지했다. 구형 디지캠·일회용 필름·바랜 인화사진 프리셋에는 저장 단계의 축소와 JPEG 압축을 더해 디테일을 의도적으로 낮췄다. 출력 크기는 유지하고 날짜·문구는 그 뒤에 합성한다.

새 필름 처리는 별도로 선택하는 입자 모델이다. 스튜디오의 효과 → 필름 질감에서 켜고 고운·보통·거친 입자, 입자 강도와 광원 번짐을 고른다. 세부 조정에는 입자 크기·컬러·암부 분포·번짐 범위를 넣었다.

![새 필름 처리의 입자 크기·강도와 광원 번짐을 조절하는 화면](/api/wiki-assets/c6f100b2-693b-4973-a9bf-add13357ac2c "width=390 align=center")

기존 그레인을 무조건 한 번 더 겹치는 방식은 아니다. 유효 강도를 합산해 새 모델에서 한 번 처리하며 CCD 색 노이즈 같은 다른 효과는 남긴다. 질감 비교는 같은 사진을 멈춰 놓고 전후를 본다.

추가 입자·빛샘·먼지·색 편차는 매 컷 새 패턴과 패턴 고정으로 나눴다. 재현상에는 촬영 당시 컷별 패턴을 복원한다. 날짜는 바랜 빨강·연한 호박색과 각진 세그먼트 숫자로 다듬었고, 연·월·일 간격은 실제 숫자 획 기준으로 맞췄다.

실시간 화면은 가벼운 근사라 추가 압축을 거친 저장 결과와 완전히 같지는 않다. 원본 보관에는 이 질감 처리를 적용하지 않는다.

### 색감은 LUT로, 촬영 설정은 레시피로 다시 쓰게 했다

LUT는 RGB 색 변환을 저장한다. 입자·광원 번짐·렌즈·얼굴 보정·날짜처럼 위치나 장면에 따라 달라지는 효과는 한 색 표에 담을 수 없어 카메라 레시피와 구분했다.

| 기능 | 저장하는 내용 | 제외하는 내용 |
|---|---|---|
| LUT 만들기 | 현재 LUT·강도와 색상 조절의 조합 | 입자·번짐·렌즈·뷰티·날짜·프레임 |
| 카메라 레시피 | 필터 ID·강도, 보정·뷰티·날짜·렌즈·비율, 질감·추가 패턴 | 사진·사용자 LUT 파일, 프레임·자동 촬영 구성 |

LUT 만들기는 64³ 색 그리드를 변환해 512×512 PNG HaldCLUT로 기기에 등록한다. 구운 색 조절값만 초기화하고 나머지 효과는 별도로 남긴다. 현재는 앱 내부 기능이며 .cube 다운로드나 외부 편집기로 내보내기는 없다.

![필터와 고운 입자 설정을 카메라 레시피로 저장한 화면](/api/wiki-assets/66ff6370-2f69-4fe4-a871-03c809e33d94 "width=390 align=center")

우측 상단 메뉴의 카메라 레시피에서 이름을 입력하고 현재 설정을 저장한다. 최대 20개를 보관하며 적용·이름 변경·삭제를 지원한다. 사용자 LUT 파일은 함께 저장하지 않아, 해당 LUT가 없으면 적용 전에 안내한다.

최근 사진은 상단 비율 버튼 왼쪽 썸네일이나 메뉴에서 확인한다. 최근 10묶음, 완성본과 원본 합계 50 MiB까지 보관하는 임시 보관함이다. 저장 공간을 사용할 수 없으면 세션 내 확인과 직접 저장·공유를 제공한다.

원본도 보관은 기본 꺼짐이다. 켜면 앱의 필터·뷰티·날짜 적용 전 JPEG를 남긴다. 센서 RAW가 아니라 크롭·미러가 적용된 이미지다. 원본이 있으면 다시 현상해 기존 완성본과 촬영 날짜를 유지하고 결과를 새 사진으로 남긴다. 합성 사진 재현상에는 뷰티를 지원하지 않는다.

레시피와 사진은 같은 기기·브라우저에만 남고 클라우드 백업이나 기기 간 동기화가 없다. 브라우저 데이터를 지우면 사라질 수 있다.

### iPhone 정렬과 복귀 처리는 계속 확인하고 있다

10월 2일의 4:5 정렬 수정 이후 1:1·3:4를 포함한 촬영 화면을 중앙에 놓도록 정리했다. 격자·날짜와 GPU 프리뷰의 기준도 함께 맞췄다. 상단 헤더 수정은 시스템 카메라 사용 표시를 숨기는 기능이 아니다.

전면에는 의미 없이 나오던 후면용 3·5배 버튼을 제거했다. 웹 카메라가 보고하는 줌 범위에서 선택지를 만들고 실제 적용값을 다시 읽는다. 보고되지 않는 0.5배를 임의로 지원한다고 표시하지 않는다.

백그라운드 복귀는 새 스트림을 연결하고 확인된 줌과 비율을 복원하도록 정리했다. 다만 웹 줌 값이 iPhone 기본 카메라 앱의 배율과 같은 의미라고 단정하지 않는다. 가상 카메라 테스트는 실제 iPhone의 화각·발열·권한·공유 경험을 대신하지 못한다.

### 기능을 늘린 뒤에도 남은 한계는 따로 기록한다

촬영·저장·복귀·레시피·비교·재현상은 Chromium 가상 카메라 기반 회귀 테스트, 타입 검사, 프로덕션 빌드로 검증했다. [변경 기록](https://github.com/jaymunsh/open-camera/blob/main/CHANGELOG.md)과 [질감 검증 기록](https://github.com/jaymunsh/open-camera/blob/main/docs/signature-film-quality-verification.md)에 실제 확인 범위를 남겼다.

main 푸시와 Vercel 배포 완료는 따로 확인한다. 이번 앱 반영은 수동 운영 배포였으며, Git 연결 상태와 Ready 상태, 실제 새 번들을 확인했다.

- 대표 룩은 아직 실제 사진에서 충분히 평가하지 않았다.
- 일부 저장 질감은 실시간 프리뷰와 다르고, 실제 iPhone의 성능·발열·화각·장기 복귀 검증이 더 필요하다.
- 사용자 제공 LUT 2종의 재배포 조건은 미확인이다.
- 사진·레시피는 로컬 저장이며 백업과 기기 간 동기화가 없다.
- 영상·일괄 편집·필름롤·추가 피부 보호 기능은 이번에 구현하지 않았다. 기존 뷰티는 유지한다.

다음에는 같은 인물·거리·음식 사진에서 색과 질감을 비교하고, 마음에 드는 조합을 대표 레시피로 다듬으려 한다. 기능 목록을 늘리는 것보다 실제 사진에서 차이가 설득력 있는지 확인하는 일이 남았다.
