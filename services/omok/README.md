# OMOK

이 폴더(`services/omok/`)가 게임 본체와 서버의 정본입니다. 이전 `Local-Test/gomoku/` 폴더 없이 개발·검사·배포할 수 있습니다.

입체 원목 보드의 웹 오목 게임. Node.js 24 권장.

## 로컬 실행

저장소 루트에서 `cd services/omok`로 이동한 뒤 실행합니다. 블로그는 별도 터미널에서 `cd web && npm run dev`로 실행합니다.

```sh
npm ci
PORT=3100 npm run dev
```

http://localhost:3100 에 접속합니다. 기본 포트는 3000입니다. 같은 Wi-Fi의 다른 기기는 호스트의 LAN IP와 포트로 접속합니다.

## 구현 기능

- 15×15 기본 렌주 금수 적용: 흑 선공, 흑은 정확히 5개·백은 5개 이상 연결 승리. 자유룰 선택 가능
- 쉬움 / 보통 / 어려움 봇. 어려움은 위협 패턴 평가와 최대 4수 깊이의 제한된 알파베타 탐색을 사용합니다. Web Worker에서 약 1.6초 예산으로 계산하며 실행 환경에 따라 완료 깊이가 달라집니다. 기력 등급은 아직 측정하지 않았습니다.
- 흑 / 백 / 무작위 선택, 무르기, 기권, 새 대국, 사운드와 설정 저장
- 진행 중 봇 대국 자동 저장 및 새로고침 복원
- 한 기기에서 둘이 대전: 흑백 교대 착수, 한 돌 무르기, 현재 차례 플레이어의 기권, 독립 저장·복원·복기
- 방 코드와 초대 링크, 입장 전 규칙·시간 확인, 닉네임, 실시간 대국, 선택형 한 수 60초 제한
- 서버가 턴·좌표·승패·시간을 검증. 합의 재대결 시 흑백 교체
- 연결 중단 시 시계 정지 및 2분 재접속 대기, 토큰으로 좌석 복구
- 최근 완료 대국 30개 로컬 저장, 전적, 한 수씩 복기, JSON 내보내기
- 명시적인 기권·방 이탈·새 대국에 확인 다이얼로그
- 모바일 레이아웃, 착수 위치 읽기 레이블, 화살표 포커스 이동, 모션 감소 설정 대응

## 한 기기에서 둘이 대전

상단의 **둘이 대전**을 선택하면 같은 브라우저에서 흑백을 번갈아 놓습니다. 봇 작업 스레드나 온라인 방 연결을 사용하지 않습니다. 기본 렌주 / 자유룰을 선택할 수 있고, 진행 중에는 규칙을 잠급니다. 새 대국 창에서 다음 대국의 규칙을 선택합니다.

무르기는 돌 한 개를 되돌려 해당 플레이어의 차례로 돌아갑니다. 기권 확인 창에 현재 차례의 색을 명시하고 그 플레이어의 패배로 기록합니다. 둘이 대전 기록은 흑·백 승리로 표시하고 개인 승패 통계에는 합산하지 않습니다.

진행 상황은 `omok:local`에 저장하여 봇 대국(`omok:bot`)과 분리합니다. 마지막으로 선택한 오프라인 모드를 기억하여 새로고침 후 이어갑니다. 온라인 재접속 세션 또는 초대 링크로 접속한 경우 해당 온라인 흐름을 먼저 엽니다.

파비콘은 OMOK 로고의 대각선 원형 심볼을 SVG로 사용합니다 (`public/favicon.svg`).

## 대국 규칙

새 대국과 새 방은 **렌주 금수 적용**이 기본입니다. 봇 설정 / 새 대국 창, 온라인 방 생성에서 자유룰을 선택할 수 있습니다. 온라인 입장자는 서버가 반환한 방 규칙을 확인한 뒤 참가하며, 잘못된 규칙으로 참가하려는 요청은 거절합니다. 진행 중인 대국의 규칙은 수정하지 않습니다. 재접속·서버 재시작·재대결에서도 같은 규칙을 유지하고 기록·복기에도 저장합니다.

| 규칙 | 렌주 금수 적용 | 자유룰 |
| --- | --- | --- |
| 흑 승리 | 정확히 5개 | 5개 이상 |
| 백 승리 | 5개 이상 | 5개 이상 |
| 흑 금수 | 삼삼·사사·장목 | 없음 |
| 백 금수 | 없음 | 없음 |

삼삼은 합법적인 비승리 수로 열린 사를 만들 수 있는 삼만 셉니다. 연장 수 자체가 장목·사사·금지된 삼삼인 경우는 재귀적으로 제외합니다. 열린 사의 두 끝을 두 개의 사로 중복 계산하지 않으며, 같은 방향의 별개 사는 각각 계산합니다. 흑이 동시에 정확한 오목을 완성하면 금수보다 승리를 우선합니다. 판정 기준은 [국제렌주연맹 규칙 9.2–9.3](https://gomoku.renju.net/rifrules/)입니다.

**캐주얼 모드 범위:** 대회 오프닝·색 교환 절차는 생략하며 첫 수 위치는 자유입니다. 금수는 패배로 처리하지 않고 착수를 차단하여 이유를 안내합니다. 보드의 × 표시는 자신이 흑인 차례에만 표시합니다. 판이 가득 차거나 현재 차례에 합법적인 수가 전혀 없으면 무승부로 종료합니다(패스 기능 없음).

예전 저장 데이터에 규칙 필드가 없으면 **자유룰로 복원**하여 진행하던 대국과 복기 결과를 바꾸지 않습니다. 이전 데이터에 규칙 선호도가 없으면 다음 새 대국의 기본값은 렌주입니다.

## 저장과 재접속

온라인 방은 `DATA_DIR/rooms.json`에 저장합니다. 기본 폴더는 `./data`입니다. 저장은 변경 후 100ms 이내에 예약하고 임시 파일을 원자적으로 교체합니다. 강제 종료 직전의 아직 저장되지 않은 변경은 유실될 수 있습니다. 정상 종료에서는 저장 완료 후 종료합니다.

서버 재시작 후 저장된 대국을 복구하고 모든 좌석에 새 2분 재접속 유예를 부여합니다. 정상 종료 시 착수 시계 잔여 시간을 보존합니다. 비정상 종료 시 마지막 저장된 deadline으로 남은 시간을 복원합니다(최소 1초). 기한 내 복귀하지 않은 플레이어는 패배하고, 두 플레이어 모두 기한을 넘기면 무승부입니다. 명시적으로 방을 나가면 방을 닫습니다. 상대의 최종 대국은 연결된 브라우저에 기록합니다.

재접속 토큰은 탭의 sessionStorage에 보관합니다. 같은 탭의 새로고침과 일시적 연결 끊김을 복구하며, 다른 기기로의 이전이나 탭 종료 후 복구는 보장하지 않습니다. 토큰은 서버에서 SHA-256 해시로 저장합니다. 봇 대국·설정·최근 기록은 브라우저 localStorage에 저장하며 계정 간 동기화되지 않습니다.

대기 방은 생성 후 10분 안에 상대가 입장하지 않으면 닫습니다. 종료된 방은 5분간 활동이 없으면 정리하며, 두 명이 합의해 재대결하면 대국을 이어갑니다. 진행 중 아무 활동이 없는 방은 2시간 후 정리합니다. 24시간 넘게 지난 저장된 방은 부팅 때 복구하지 않습니다.

온라인 화면에서 사용 중인 방 수와 서버 한도를 확인할 수 있습니다. 대기·진행·종료 후 남아 있는 모든 방을 포함하며 15초마다(화면이 보이는 동안) 갱신합니다. 한도에 도달하면 새 방 생성만 막고 기존 방 입장·대국·재접속은 유지합니다. 기본 한도 100개는 초기 운영 설정이며 검증된 동시 처리 용량이 아닙니다. 실제 서버의 부하 검사 결과에 따라 `MAX_ROOMS`를 조정하세요.

명시적 퇴장은 서버의 확인을 받은 뒤 화면에서 완료됩니다. 대기 취소는 승패를 기록하지 않습니다. 대국 중 방 나가기·모드 변경은 내 패배로 종료하고 양쪽에 최종 결과를 보낸 뒤 방을 닫습니다. 대국 종료 후 나가면 기존 결과를 유지하고 방을 닫습니다. 새로고침·네트워크 중단은 명시적 퇴장과 구분하며 2분 재접속 유예를 적용합니다. 온라인에서는 무르기를 지원하지 않습니다.

퇴장 당시 상대가 연결되어 있지 않으면 닫힌 대국의 최종 결과만 최대 2분 보관합니다. 상대가 같은 탭에서 복귀하면 결과를 전달하고 즉시 정리합니다. 이 대국은 입장·재대결할 수 없으며 결과 보관 중에는 서버 방 수에 포함됩니다. 같은 브라우저의 두 탭이 서로 대전한 경우 기록은 흑·백 관점별로 저장합니다. 전적은 브라우저에 보관된 기록을 합산하며 계정별 전적이 아닙니다.

## 공개 서버 배포

Docker와 Docker Compose가 설치된 서버에서 도메인을 연결하고 TCP 80/443을 개방합니다.

```sh
cp .env.example .env
# .env의 DOMAIN을 실제 도메인으로 변경
# 프로젝트 폴더에서 실행
docker compose up -d --build
```

Caddy가 HTTPS 인증서와 WebSocket 프록시를 처리합니다. `games` 볼륨은 대국 데이터를, `caddy_data`는 인증서를 보존합니다. `docker compose down -v`는 데이터를 삭제하므로 사용하지 마세요.

```sh
docker compose logs -f app
curl https://YOUR_DOMAIN/health
docker compose up -d --build app
```

`/health`는 방 수·연결 수·가동 시간과 저장 상태를 반환합니다. 저장 오류 시 503을 반환하고 구조화된 JSON 로그를 남깁니다. 로그 수집·알림은 배포 환경에 연결해야 합니다. 저장 파일 손상 시 덮어쓰지 않고 부팅을 중지하므로 백업에서 복원해야 합니다. 볼륨은 주기적으로 백업하세요.

환경 변수:

| 이름 | 기본값 | 용도 |
| --- | --- | --- |
| PORT | 3000 | HTTP/WebSocket 포트 |
| DATA_DIR | ./data | 영구 데이터 폴더 |
| PUBLIC_ORIGIN | 미설정 | 허용할 정확한 웹 Origin 및 SEO 공개 주소, 예: https://omok.example.com. 미설정 시 검색 제외 |
| NODE_ENV | 미설정 | development/test에서는 검색 제외. npm run dev는 development, Compose는 production 사용 |
| PUBLIC_PATH | 빈 문자열 | 같은 도메인의 경로에 배포할 때 접두사, 예: /omok |
| MAX_ROOMS | 100 | 최대 방 개수, 양의 정수 |
| TRUST_CLOUDFLARE | 0 | 1이면 Cloudflare가 설정한 CF-Connecting-IP를 사용. 운영 k3s는 Traefik만 접근 가능하도록 NetworkPolicy 적용 |
| TRUST_PROXY | 0 | 1이면 프록시가 추가한 X-Forwarded-For의 마지막 IP를 신뢰 |

연결당 메시지 50개/10초, 방 생성·입장 8회/분, 직접 연결 IP당 동시 연결 20개·연결 시도 60회/분, 전체 연결 1500개 제한을 적용합니다. Origin 검증, 2KB 메시지 제한, 15초 heartbeat, 정적 파일 허용 목록, CSP가 적용됩니다. 기본 실행은 X-Forwarded-For를 신뢰하지 않습니다. 제공된 Compose에서는 앱 포트를 외부에 열지 않고 Caddy 뒤에서만 실행하므로 TRUST_PROXY=1로 실제 접속 IP를 사용합니다. 이 설정에서는 앱 포트를 인터넷에 직접 노출하면 안 됩니다.

이 구성은 **단일 Node 프로세스**용입니다. 여러 인스턴스가 같은 JSON 파일에 쓰면 안 됩니다. 수평 확장은 공유 DB 및 방 라우팅 구조를 추가해야 합니다. 계정, 랭킹, 공개 자동 매칭, 관전, 채팅은 현재 범위에 포함하지 않았습니다.

## 기본 SEO와 공유 미리보기

첫 HTML 응답에 한국어 제목·설명, canonical, Open Graph 및 Twitter 공유 메타데이터를 넣습니다. 기존 로고와 원목 보드를 사용한 `public/og-image.png`는 1200×630px 이미지이며, `/robots.txt`와 `/sitemap.xml`도 서버가 제공합니다.

공개 도메인은 요청의 Host 헤더 대신 **명시적으로 설정한 `PUBLIC_ORIGIN`**을 사용합니다. 제공된 Docker Compose는 `.env`의 `DOMAIN`으로 `https://DOMAIN`을 설정합니다. Node를 직접 운영할 때는 실제 HTTPS 주소를 지정하세요. 경로나 초대 코드 없이 Origin만 지정합니다.

```sh
NODE_ENV=production PUBLIC_ORIGIN=https://omok.example.com npm start
```

`PUBLIC_ORIGIN`이 없거나 localhost·로컬 도메인·IP 주소이면 검색을 제외합니다. `NODE_ENV=development/test`에서도 공개 주소 설정 여부와 무관하게 검색을 제외합니다. 초대 코드가 있는 `?room=...` 페이지는 noindex이며, canonical과 공유 주소에는 방 코드를 넣지 않습니다. 사이트맵에는 공개 게임의 루트 주소만 포함합니다. 블로그 서버의 `OMOK_PUBLIC_URL`도 동일한 공개 주소로 설정해야 `/works`에서 연결됩니다.

공유 이미지 수정 시 설치된 Chrome으로 `node scripts/build-og-image.mjs`를 실행해 재생성할 수 있습니다. 공개 배포·검색엔진 사이트 등록은 별도이며 이 설정만으로 실제 검색 수집 여부를 보장하지 않습니다.

## 검증 상태

2026-09-10 규칙 변경 후 단위·서버 통합 테스트 27개 통과. 금수와 예외, 흑 봇의 합법 수, 서버 금수 거절, 규칙 불일치 입장 거절, 재대결 규칙 유지, 레거시 방 복원, 서버 재시작 시 규칙 보존을 포함합니다. `scripts/renju-ui-check.mjs`로 금수 표시·클릭 안내, 규칙 잠금, 새 대국 선택, 구버전 저장 호환, 입장 전 안내, 양쪽 규칙 대국, 새로고침·재대결과 320px 화면을 확인했습니다.

2026-09-08 UI/UX 정리 후 Chrome에서 320·390·768·1024·1440px 화면을 확인했습니다. 어려움 봇 착수, 설정 변경 취소, 돌 불투명도, 결과 화면, 복기 슬라이더, 방 코드 오류 표시, 두 브라우저 대국, 새로고침 후 대국 복구, 모달과 빈 기록 화면을 확인했습니다. 화면 가로 넘침과 페이지 JavaScript 오류는 없었습니다.

이번 확인은 UI 및 주요 사용 흐름에 한정합니다. 전체 회귀·부하·서버 장애 복구·실제 기기별 검증을 완료했다는 의미는 아닙니다.

준비된 검사 명령:


## jay-blog 연결

블로그의 실제 공개 소스 checkout은 `visualStudy/leneu/public-snapshot/`입니다. `/works` 최하단 게임 목록의 OMOK는 `/game/omok` 연결 경로를 통해 **전용 HTTP/WebSocket 서버**를 새 탭으로 엽니다. 정적 파일만 블로그에 복사하면 온라인 기능이 동작하지 않습니다.

개발 환경에서는 기본적으로 `http://localhost:3100/?from=works`로 연결합니다. 오목 서버와 블로그 개발 서버를 함께 실행하세요. 공개 환경에서는 오목 서버를 HTTPS로 별도 배포한 다음 **블로그 서버의** `OMOK_PUBLIC_URL` 환경 변수에 실제 주소를 설정합니다. 예: `OMOK_PUBLIC_URL=https://실제-게임-도메인`. 설정되지 않았거나 유효한 HTTPS 주소가 아니면 공개 준비 중 안내를 표시하며 방문자를 localhost로 보내지 않습니다.

블로그에서 연 오목 화면에는 작업물로 돌아가는 링크가 있습니다. 초대 링크는 오목 서버의 주소를 공유하므로 초대받은 사람도 같은 서버에서 플레이합니다. 운영 반영에는 오목 서버 배포와 블로그 코드·환경 변수 반영이 모두 필요합니다. 이번 로컬 연결 작업만으로 공개 배포가 이루어지지는 않습니다.

## jay-wiki 운영 구성

운영 게임 주소는 `https://game.leneu.cloud/omok/`이다. 기존 게임 목록과 Forest Jump 경로는 유지한다. `PUBLIC_ORIGIN=https://game.leneu.cloud`, `PUBLIC_PATH=/omok`으로 HTTP 정적 파일·WebSocket·공유 주소를 같은 경로 아래 제공한다.

공개 release workflow에서 별도 SHA 고정 이미지를 빌드한다. 비공개 ops 배포가 웹·게임 이미지를 함께 선택한다. k3s는 단일 Recreate Deployment와 `jaywiki-omok-data` PVC를 사용하며 기존 인스턴스 종료 후 방 데이터를 넘긴다. PVC는 첫 배포 실패 롤백에서도 삭제하지 않는다. 방 파일의 배포 전 사본은 서버 운영 백업 경로에 보관한다. 이는 단일 miniPC 장애에 대한 외부 백업을 대체하지 않는다.
