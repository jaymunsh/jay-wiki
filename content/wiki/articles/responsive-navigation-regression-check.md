
- 문서 딥링크와 390·768·1280px 화면 폭에서 읽기 계약이 유지되는지 어떻게 확인했나?
- 기능이 열리는지만 보지 않고 딥링크 유지, 늦게 도착한 이전 요청의 덮어쓰기 방지, 화면 폭별 가로 넘침 없음을 회귀 기준으로 고정했다.
- 2026-07-11 production build에서 같은 문서 요청 30회가 모두 HTTP 200이었고, Chrome CDP 기준 390px에서 document와 body 폭이 390px, Mermaid는 314px 프레임 안에서 716px 콘텐츠를 내부 스크롤하는 것을 확인했다.

운영 위키는 문서가 길고 Mermaid, 표, 탭과 타임스탬프가 함께 있어, 아래 기준을 실제 화면에서 확인했다.

## 딥링크·경합·화면 폭을 회귀 기준으로 고정했다

| 항목 | 기대 결과 |
|---|---|
| 딥링크 | 문서 URL로 직접 연 글이 새로고침 뒤에도 유지 |
| 연속 선택 | 늦게 도착한 이전 요청이 현재 문서를 덮지 않음 |
| 390px | document와 body가 viewport 폭을 넘지 않음 |
| Mermaid | 넓은 diagram은 페이지가 아니라 내부 프레임에서 가로 스크롤 |
| 탭과 목록 | 활성 탭, 한글 제목, 타임스탬프가 잘리지 않음 |
| 768·1280px | desktop과 tablet에서 page scrollWidth와 clientWidth가 일치 |

## 390·768·1280px 전부 가로 넘침이 없었다

2026-07-11 production build로 같은 문서 요청 30회와 CSS 요청을 반복해 모두 HTTP 200을 확인했다.
Chrome CDP 기준 390px에서 document와 body 폭은 모두 390px이었고, Mermaid는 314px 프레임 안에서
716px 콘텐츠를 내부 스크롤했다. 768px와 1280px에서도 page scrollWidth와 clientWidth가 일치했다.
